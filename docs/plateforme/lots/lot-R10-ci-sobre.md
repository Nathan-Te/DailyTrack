## 2. Ce qui change dans la CI (`.github/workflows/ci.yml`)
- **PR (mode `pr`)** : `scope` (≈ 8 s) lit les fichiers modifiés (`scripts/ci-zones.mjs`) ; `unit (n/m)` = typecheck, portail, construction (part `verif`) + **les tests unitaires dont le graphe d'imports atteint un fichier modifié** (comme `vitest related`, plus les chemins cités : documents, workflows, données), en **parts de durée égale** (`scripts/unit-durees.json`, 4 au plus ; avant : 143 / 308 / 356 s) ; `e2e-pr (n/m)` = **les specs liés aux fichiers modifiés + la fumée du jeu touché, Chromium, 4 parts au plus**, budget de **900 s de specs** (le reste est *reporté* à la CI complète de `main` et nommé dans le résumé ; jamais un spec modifié ni la fumée) ; `zones`, `api-image` (si le serveur est touché), puis les verdicts `test` et `e2e` (**mêmes noms**).
- **Docs seuls** (`docs/**`, `*.md`) : ni typecheck, ni construction, ni e2e, ni `api-image` ; seuls les tests qui **lisent** ce document tournent (`docsLusParLesTests`, test `ciZones.test.ts` : `codes-erreur.md`, `effacement.md`, `budgets.md`, `traductions.md`, `orchestration.md`…). **Pas de `paths-ignore` sur `ci.yml`** : un statut requis qui ne se rapporte pas bloque la fusion ; `test` et `e2e` se rapportent donc, verts, en quelques secondes. `apercu.yml` ignore les PR de documentation (`paths-ignore`).
- **Plus de `[ci complet]`** (retiré du workflow, de `CLAUDE.md`, d'`apps/jump/CLAUDE.md`). **Le sous-ensemble multi-navigateurs du lot R3 est retiré** (`multi-navigateurs.json` ×2, son test, `e2e-parts.mjs multi`) : une PR ne lance que Chromium.
- **CI complète** (`push` sur `main`, « Run workflow », nuit à 03 h 17 UTC) : inchangée dans ses jeux de tests (trois navigateurs, quarantaine bloquante, matrice `e2e-parts`), unitaires en 3 parts **de durée égale**. **Informative pour les lots en cours** : un rouge sur `main` n'arrête personne. `production.yml` exige toujours le run `push` de `main` vert (`scripts/ci-complete.mjs`, non touché). `concurrency` + `cancel-in-progress` : `ci.yml` (hors `main`), `apercu.yml`, `recette.yml` (PR) l'avaient ou l'ont ; `stabilite.yml` aussi.
- **Lot de mise en production** (`docs/orchestration.md` § 12, qui complète le lot R6) : lancer la CI complète sur `main`, **corriger les tests rouges quelle que soit leur zone (exception écrite à la règle des zones)**, relancer jusqu'au vert, faire le garde-fou des jours, puis Nathan clique.

## 3. La table spec → zones (`e2e/zones.json`, `apps/web/test/ciZones.test.ts`, 30 tests)
29 zones (motifs de chemins, avec `sauf`), **81 specs** (52 de Track, 29 de Jump) déclarés avec 1 à 4 zones ; fumée Track : `replay`, `perf`, `hud-compact`, `cameras` (≈ 52 s) ; fumée Jump : `smoke`, `replay`, `poids`, `jour`, `dangers` (≈ 57 s). Zones partagées (`ui`, `profile-pkg`, `core-clock`, `portail`, `api-coeur`) lancent les specs des deux jeux. Le test refuse : un spec sans zone, une entrée pour un spec disparu, une zone sans spec, un motif qui ne désigne aucun fichier, une fumée absente ou longue (> 120 s). Un fichier de jeu qu'aucune zone ne nomme ne lance que la fumée. Un spec modifié se lance ; un utilitaire de test lance ses importeurs (la fumée s'il y en a plus de 12) ; les outils (`captures-*`, `mesure-*`) ne se lancent jamais.

## 5. La discipline des agents (`CLAUDE.md` racine, « Discipline de l'agent » ; `docs/orchestration.md` § 11)
`npm run verifier` (typecheck, tests unitaires et specs **choisis comme la CI les choisit**, une ligne par étape, 30 lignes de la fin du journal seulement en cas d'échec ; `-- --zones=…`, `-- --liste`, `-- --sans-e2e`) · **pousser aux étapes** · **une seule mise à jour avec `main`**, juste avant de s'arrêter · `npm run attendre-ci` (une commande bloquante et silencieuse, verdict par job, tests rouges + 20 lignes d'erreur au plus ; vérifiée sur un run rouge de Playwright et un de Vitest) · un échec en CI se reproduit d'abord en local · 5 captures regardées au plus · README de lot ≤ 150 lignes · `CLAUDE.md` courts. Aussi : `apps/web/CLAUDE.md` et `apps/jump/CLAUDE.md` (tout spec déclare sa zone, préférer l'unitaire, pas d'attente longue).

## 8. Étape manuelle pour Nathan : le statut requis de `main`
**Rien à changer** si la règle de protection exige déjà `test` et `e2e` (Réglages › Branches › règle de `main` › « Require status checks to pass ») : la CI courte porte les mêmes deux noms. À vérifier une fois qu'**aucun autre** statut n'y est coché (`unit`, `e2e-parts`, `e2e-pr` n'existent pas toujours : un statut requis absent bloquerait une PR). Pour relancer la mesure dans une semaine : `GITHUB_TOKEN=… npm run mesure-ci -- --depuis 2026-10-27 --evenement pull_request` (puis `--evenement push` et `--workflow tous`).
