## Fantôme du premier et profil DailyJump (lot P2)
README : `docs/plateforme/lots/lot-P2-fantome-profil.md`. Code : `apps/api/src/jump.ts` ; tests `apps/api/test/jumpProfile.test.ts` (SQLite **et** libSQL).
- **`GET /api/jump/day/<date>/ghost/first`** : la rediffusion du **premier du classement** de ce jour (la règle du P1 : temps, puis premier envoyé, puis identifiant), avec son pseudo, son temps et ses morts **rejoués**, `levelId`, `simVersion`, `generatorVersion` (celles qui l'ont rejouée : le jeu ignore une autre version) et `mine` (en-tête `X-Player-Id` facultatif : « c'est toi »). **Jamais l'identifiant du premier.** 404 `no_ghost` si personne n'est classé ; futur / avant le premier niveau / date illisible comme `board`. Lecture **comptée en mémoire** (`readHit`, aucune écriture). **Jour passé** (après la grâce) : figé, donc **gardé en mémoire par instance** (`firstOfClosed`, 64 jours au plus ; oublié à un changement de pseudo — `onRename` — ou de code — `rotateStatements`) ; le jour en cours est relu à chaque fois (1 instruction, 2 lignes lues).
- **Un profil par jeu** : **`GET /api/jump/me`** (identifiant en `X-Player-Id`, jamais dans l'adresse) rend le profil **DailyJump** : `{ name, renameRequired, today, simVersion, generatorVersion, days[] (date, levelId, ticks, deaths, medal), stats { days, medals, streak } }` — pour chaque jour classé, le meilleur temps rejoué, les morts **de cet essai** et la médaille (celle du niveau gardé dans `jump_levels` pour ce jour, si c'est bien celui de l'essai ; sinon `null`). 404 `unknown_player` (jamais classé dans aucun jeu ; un joueur de DailyTrack seul a un profil vide), **410 `code_revoked`**, 400 sans en-tête. Lectures en mémoire (60 par joueur, 120 par adresse et fenêtre). **Le `GET /api/me` de DailyTrack est intouché** : DailyJump ne fournit pas le crochet `profile` du registre (qui ferait entrer ses données dans `/api/me`) ; règle : un nouveau jeu sert son profil sous `/api/<jeu>/me`, jamais dans `/api/me` (test « `/api/me` de DailyTrack inchangé » : un joueur des deux jeux reçoit exactement la même réponse qu'avec DailyTrack seul).
- **Démonstration** : `npm run jump:seed -w @cdj/api` écrit aussi `first` (le fantôme du premier, lu par `ghost/first`) dans chaque jour de `apps/jump/public/demo/` (test `jumpHistory.test.ts` : le premier du classement, sa rediffusion se rejoue à son temps).
- **`smoke`** vérifie aussi `ghost/first` (le premier du classement, sa rediffusion, les versions) et `/api/jump/me` (le jour classé du joueur d'essai).
- **Coût mesuré** (`npm run measure:jump-api -w @cdj/api`, sqld local) : `ghost/first` 1 instruction, 2 lignes lues, 0 écrite (jour passé en mémoire : 0) ; `/api/jump/me` 3 instructions, 4 lignes lues (1 jour) / 62 (30 jours), 0 écrite. **Joueur type avec le P2** (fantôme ×6 : 2 chargements + 4 arrivées ; profil ×4 : 2 chargements + 2 envois acceptés ; 30 jours d'historique) : 19 requêtes, 65 instructions, 1 084 lignes lues, 17 écrites (P1 seul : 9, 47, 824, 17).
