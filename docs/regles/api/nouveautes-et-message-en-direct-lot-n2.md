## Nouveautés et message en direct (lot N2)
README : `docs/plateforme/lots/lot-N2-nouveautes-et-message-en-direct.md` ; règles pures : `packages/core/src/nouveautes.ts` (`@cdj/core/nouveautes` : forme d'une ligne, validation, lecture de « ## Pour les joueurs » d'une PR) ; code : `src/diffusion.ts` ; tests : `test/diffusion.test.ts` (SQLite **et** libSQL).
- **Tables** (`PLATFORM_SCHEMA`, migration **réversible** : deux tables nouvelles, rien d'existant touché ; retour arrière : `DROP TABLE nouveautes` et `DROP TABLE annonces`) : **`nouveautes`** (`titre_fr`, `titre_en`, `date_affichee` AAAA-MM-JJ, `lignes` JSON `[{ zone, fr, en, pr? }]`, `statut` `brouillon` | `publiee`, `cree_le`, `modifie_le`, `publie_le`) et **`annonces`** (`texte_fr`, `texte_en`, `ou` `portail,track,jump`, `ton` `information` | `important`, `debut`, `fin`, `retire_le`). **Aucune donnée de joueur** : ce que l'éditeur écrit pour tout le monde ; **gardées** par la remise à zéro du lancement (`TABLES_GARDEES`) et sans crochet `erase`. Le journal des actions (`journal_admin`, **même transaction** que chaque action : `publier une nouveauté`, `modifier…`, `dépublier…`, `supprimer…`, `enregistrer un brouillon`, `publier un message en direct`, `mettre à jour le message en direct`, `retirer le message en direct`) reste celui du lot N1.
- **Routes publiques** (aucun identifiant, rien d'écrit, limites en mémoire de 120 lectures par adresse et fenêtre) : **`GET /api/annonce`** → `{ annonce: { id, fr, en, ou[], ton, fin } | null, maintenant }`, **`Cache-Control: public, max-age=0, s-maxage=30`** (le cache de Firebase Hosting, partagé par toutes les pages ouvertes) ; **`GET /api/portail/nouveautes?avant=`** → `{ nouveautes[{ id, date, titre{fr,en}, lignes[{ zone, fr, en }], publieLe }], suivante }`, 20 par page, la plus récente d'abord (date affichée puis identifiant), `avant` = `AAAA-MM-JJ.<id>` (`400 invalid_cursor` sinon), **`public, max-age=60`** ; **`GET /api/portail/jour`** porte aussi `nouveaute` (la dernière publiée : la ligne de l'accueil, `publieLe` pour « lu sur cet appareil ») et `annonce` — **la seule requête du chargement du portail** (règle du lot I3). Le message actif = `fin > maintenant` et pas retiré : **il s'éteint seul à l'heure pile** (le client compare aussi `fin` à l'heure du serveur : le cache ne le prolonge pas pour l'œil).
- **Administration** (session, `X-Cdj-Admin: 1`, `confirmer: true`, comme le lot N1) : `GET|POST /api/admin/nouveautes` (enregistre ; `publier: true` refuse ce qui n'est pas publiable : **`400 invalid_news` + `problemes`** — dont `{ code: "anglais", n }` : une ligne sans anglais bloque la publication —, un brouillon n'a pas à être complet), `POST …/<id>/depublier|supprimer` (`404 unknown_news`), `GET|POST /api/admin/message` (« Mettre à jour » : **un seul message actif** — l'ancien est retiré dans la même transaction, le nouveau a un autre identifiant : les pages qui avaient fermé l'ancien revoient le nouveau ; `400 invalid_message` + `problemes` : 160 caractères au plus par langue, **ni lien ni HTML**, au moins un endroit, ton, fin dans le futur et à 7 jours au plus), `POST /api/admin/message/retirer` (« Retirer maintenant »). **Un texte reste un texte** : le serveur le nettoie (une ligne, sans caractère de contrôle) mais ne l'interprète jamais ; les clients le posent en `textContent`.
- **Coût** (`docs/plateforme/couts.md` § 9, `npm run measure:annonce -w @cdj/api`, `ANNONCE` et `annonceParHeure` de `scripts/platformBudget.ts`) : une requête qui arrive à Cloud Run = 1 instruction, 1 ligne lue (index `annonces_by_fin`), 0 écrite ; **le cache de Hosting borne ce qui y arrive** (≤ 120 par heure et par point de présence, quel que soit le nombre de pages) ; **le poids est celui de Hosting** (1 requête par page et par minute : 372 Mo par heure à 10 000 pages ouvertes, plus que le transfert gratuit de 360 Mo par jour : décision de Nathan notée dans `couts.md`). Aucune requête ne lit une table entière (test « coût »).
- **`recette:seed`** : deux nouveautés publiées (`NOUVEAUTES_DE_RECETTE`, dates d'avant tout vrai contenu, aucun doublon à la relance), **aucun message actif** (`semerNouveautes`). `smoke --lecture-seule` vérifie les deux lectures publiques et leurs en-têtes.
- **Règles** : une nouvelle lecture publique de contenu de l'éditeur porte son cache (jamais `private` : elle ne dépend pas du joueur) et sa limite de lecture ; une nouvelle action d'administration s'écrit dans la **même transaction que son journal** ; un nouveau code d'erreur suit `codes-erreur.md`.
