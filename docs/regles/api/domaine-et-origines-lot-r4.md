## Domaine et origines (lot R4)
README : `docs/plateforme/lots/lot-R4-domaine.md` ; guide : `docs/plateforme/domaine.md` ; carte des adresses et flux de mise en production : `CLAUDE.md` racine, « Adresses et mise en production ».
- **Le serveur sous la même adresse que les jeux** : Firebase Hosting (`firebase.json`) renvoie `/api/**` vers le service Cloud Run de chaque site (production → `cdj-api`, recette et aperçus → `cdj-api-recette`, `europe-west1`, région prise en charge par les renvois de Hosting). Les jeux appellent `/api/` sur leur propre origine : **aucune requête CORS, aucun pré-vol**. Les routes, les réponses et les **en-têtes de cache du lot P4 ne changent pas** ; le CDN de Hosting garde les lectures `public` (jamais les `private` + `Vary: X-Player-Id`). Délai maximal d'une requête par Hosting : 60 s (le serveur coupe à 30 s).
- **Origines permises** (`ALLOWED_ORIGINS`, calculées par `scripts/domaine.mjs origines <cible>` dans `deploy-api.yml`, testées dans `apps/portail/test/domaine.test.ts`) : production `https://playdujour.com` ; recette `https://recette.playdujour.com` (+ l'origine du canal d'aperçu de la PR pour sa révision étiquetée, que l'aperçu appelle par son adresse directe) ; plus les variables `ALLOWED_ORIGINS` / `RECETTE_ALLOWED_ORIGINS`. **Lot R5 : l'ancienne origine `https://nathan-te.github.io` n'est plus permise** (plus de redirection ni de migration). La production refuse toute origine de recette ou d'aperçu (`*.web.app`). `config.ts` ne change pas : il vérifie toujours la forme des origines.
- **Adresse du client derrière Firebase** : Hosting ajoute un relais devant Cloud Run ; `TRUST_PROXY` est une variable du dépôt (`TRUST_PROXY`, `RECETTE_TRUST_PROXY`, défaut 1), mesurée sur la recette (`scripts/sonde-proxy.mjs`, guide étape 7) : **2**. L'appel direct à `run.app` : fermé autant que possible au lot R5 (rubrique suivante).
- **Production par le bouton** : `deploy-api.yml` (cible `production`) n'est plus appelé que par `production.yml`, sur un commit choisi (`ref`) avec les jours figés par le code en production (`jours_figes`, dans l'image) ; l'image est notée dans l'étiquette `prod-…` (retour arrière : `retour-arriere.yml`). « Run workflow » de `deploy-api.yml` ne propose plus que la recette.
