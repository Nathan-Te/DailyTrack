## Retours (lot C1)
README : `docs/plateforme/lots/lot-C1-retours-avatars-groupes.md` ; code : `src/retours.ts` (routes, règles du texte et du contexte, `semerReponse`), `scripts/retoursDemo.ts` (la recette) ; tests : `test/retours.test.ts`, `retoursDemo.test.ts` (SQLite **et** libSQL `file:`). « Un bug ? Une idée ? » : le joueur écrit, l'éditeur répond dans le panneau, le joueur lit la réponse dans « Mes messages » — **sans e-mail**.
- **Modèle** (`PLATFORM_SCHEMA`, migration **réversible** : deux tables nouvelles ; retour arrière `DROP TABLE retours` et `DROP TABLE retours_messages`) : `retours` (un fil : `player_id` — `NULL` pour un envoi sans profil, aucune réponse possible —, `ref` publique, `type` bug | suggestion | autre, `jeu`, `statut` nouveau | lu | en_cours | traite | refuse, `contexte` JSON, `cree_le`, `maj_le`, `non_lu_joueur`, `non_lu_admin`, `nb_messages`) et `retours_messages` (`joueur` | `admin`, du texte seul). Index : `retours_by_player (player_id, cree_le)` (limite du jour, liste, non lus), `retours_by_statut`, `retours_by_maj`, `retours_non_lus_admin` (partiel : le nombre de non lus du menu). Les deux sont dans `TABLES_VIDEES`, `GRANDES_TABLES`, `players.eraseStatements` (effacement : fils et messages), `players.rotate` (« Changer mon code » : `player_id` et `ref`) et les deux pages de mentions.
- **Routes joueur** (`X-Player-Id`, jamais dans l'adresse) : `GET /api/retours/contexte` (version en production et jour ; avec identifiant aussi la **référence publique** : `private, max-age=300` + `Vary`), `POST /api/retours { type, texte, contexte }` (identifiant facultatif : sans lui l'envoi est anonyme, `reponsePossible: false`), `GET /api/retours` (les 50 fils les plus récents + `nonLus`), `GET /api/retours/<id>` (fil, contexte), `POST /api/retours/<id>/messages { texte }`, `POST /api/retours/<id>/lu`. **Une lecture ne modifie rien** : « lu » est une demande du client après l'affichage. Un fil qui n'est pas à ce joueur : `404 unknown_feedback` (un seul visage).
- **Limites** : **5 nouveaux fils par joueur et par jour de Paris** (vérifiés **à l'écriture** : `INSERT … SELECT … WHERE COUNT < 5`, `429 feedback_limit`), 10 envois par adresse et fenêtre (`hitAddress`, `rtip`) et **3 sans profil** (`rtanip`), 100 messages au plus par fil (`409 feedback_full`), un joueur limité en base (`rtw`). **Texte seul** : normalisé, sans caractère de contrôle, 1 000 caractères (points de code) ; il n'est **jamais interprété** (les clients le posent en `textContent`). **Contexte** : liste fermée de champs (`nettoyerContexte` : jeu, page sans paramètres, jour, navigateur et système en familles, écran `LxH`, langue) ; la **version** est posée par le serveur (`RELEASE_TAG`). Un fil traité ou refusé repart « nouveau » si le joueur répond.
- **`messagesNonLus`** : `GET /api/portail/jour` (avec identifiant) et `GET /api/portail/profil` le portent — **une lecture indexée** (`COUNT … player_id = ? AND non_lu_joueur = 1`), aucune requête de plus côté client (règle du lot I3). `JoueurDuJour.messagesNonLus` ; le test `routesChaudes.test.ts` tient.
- **Administration** (session, `X-Cdj-Admin`, `confirmer: true`, **chaque action au journal dans la même transaction**, **jamais le texte d'une réponse ni un identifiant** : sa longueur seulement) : `GET /api/admin/retours?type=&jeu=&statut=&page=` (50 par page + `nonLus`), `GET …/compte`, `GET …/<id>` (fil, contexte, pseudo et référence ; le panneau lie la fiche N1), `POST …/<id>/repondre { texte }` (impossible pour un visiteur sans profil), `…/statut { statut }`, `…/lu` (nouveau → lu). `404 unknown_feedback`, `400 invalid_action`.
- **Durée de garde** : un fil est effacé **12 mois après son dernier message** (`RETOURS_GARDE_JOURS`, l'entretien horaire de `journaux.ts`). Mentions : la rubrique « Tes retours » des deux pages (constantes `RETOUR_TEXTE_MAX`, `RETOURS_PAR_JOUR`, `RETOURS_GARDE_JOURS`).
- **`recette:seed`** : 3 retours (« Démo » et deux joueurs du classement), celui de « Démo » avec la réponse de l'éditeur à lire (`seedRetoursDemo`, par le vrai `createApi`, `semerReponse` pour la réponse) ; il constate d'abord (une lecture indexée) et n'écrit rien s'ils sont là.
- **Coût** : `couts.md` § 12. **Codes** : `invalid_feedback` 400, `unknown_feedback` 404, `feedback_limit` 429, `feedback_full` 409 (`codes-erreur.md`, `CATALOGUE_RETOURS`).
