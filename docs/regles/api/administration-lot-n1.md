## Administration (lot N1)
README : `docs/plateforme/lots/lot-N1-admin-connexion-tableau-joueurs.md` ; étapes de Nathan : `docs/plateforme/admin.md` ; page : `apps/portail/CLAUDE.md`, « Le panneau d'administration (lot N1) ». **L'administration de la plateforme = `/admin/` avec une connexion Google ; le jeton `ADMIN_TOKEN` ne sert plus qu'aux outils de Track (`/track/admin/`), qui acceptent aussi la session, le temps de la transition.**
- **Fichiers** : `adminGoogle.ts` (vérification du jeton d'identité), `adminSession.ts` (cookie et table `admin_sessions`), `admin.ts` (routes, tableau de bord, joueurs, les cinq actions), `journaux.ts` (`journal_admin`, `journal_erreurs`, entretien). Chaque jeu déclare au registre un crochet **`admin`** (`AdminDuJeu`, `games.ts`) : jeux où il compte l'activité, ses résultats par joueur, `retirer`, `masquer`, le lien de sa rediffusion — le panneau ne connaît aucun jeu.
- **Routes** (`/api/admin/…`, avant celles de Track) : `config` (public : `actif`, `clientId`, `factice`), `session` (POST connexion, GET, DELETE), `tableau`, `joueurs?q=&filtre=&page=`, `joueurs/<ref>` et `…/renommer|masquer|retirer|supprimer` (POST, `confirmer: true` exigé), `journal`. Les routes de Track (`overview`, `planning`, `medailles`, `effacer`) ne changent pas. **Panneau non configuré** (secrets absents) : tout, sauf `config`, répond 404.
- **Connexion** : `POST /api/admin/session { credential }` → jeton d'identité Google vérifié **sans dépendance** (Web Crypto) : RS256 sur les clés publiques de Google (`certs`, gardées selon leur `Cache-Control`, bornées 1 min–1 jour ; une clé inconnue provoque **au plus une relecture par minute** ; des clés périmées ne servent jamais), puis `iss`, `aud` = `ADMIN_GOOGLE_CLIENT_ID`, `exp` (±60 s), `email_verified`, et l'adresse dans la liste du secret `ADMIN_EMAILS` (comparée par empreinte). **Un refus n'a qu'un visage** (401 `unauthorized`, sans cookie) : la raison technique (`signature`, `aud`, `hors_liste`…) n'est que dans le journal du serveur, **jamais l'adresse**. 10 tentatives par adresse et fenêtre de débit.
- **Session** : cookie **`__session`** (le seul nom que Firebase Hosting transmet à Cloud Run), `HttpOnly; Secure; SameSite=Strict`, **1 heure**, `<charge>.<HMAC-SHA-256>` signé avec `ADMIN_SESSION_KEY` ; la charge = `{ identifiant de session, empreinte de l'administrateur, fin }`, **jamais l'adresse** (l'empreinte est un HMAC de l'adresse : sans la clé on ne la retrouve pas). **Révocable côté serveur** : ligne de `admin_sessions`, `revoked_at` à la déconnexion, relue à chaque requête. Toute écriture (`POST`/`DELETE`) exige **`X-Cdj-Admin: 1`** et une **`Origin` d'`ALLOWED_ORIGINS`** (sans liste : celle de la requête) — 403 `forbidden` ; toutes les réponses sont `no-store`. Les outils de Track (`requireAdmin`) acceptent la session (écritures : mêmes en-têtes) **ou** le jeton ; une requête qui porte le cookie sans les en-têtes retombe sur l'examen du jeton.
- **Secrets et comptes** : `cdj-admin-emails` et `cdj-admin-session-key` (recette : `cdj-recette-…`), montés par `deploy-api.yml` en `ADMIN_EMAILS` / `ADMIN_SESSION_KEY` **seulement s'ils existent** ; le droit de lecture (`secretAccessor`) va au **compte d'exécution de l'API**, jamais au compte de déploiement. `ADMIN_GOOGLE_CLIENT_ID` (public) vient de la variable du dépôt du même nom ; `RELEASE_TAG` (étiquette `prod-…`) de `production.yml`. **L'adresse de l'éditeur n'est ni dans le dépôt, ni dans un journal, une réponse ou un rapport.**
- **Vérificateur factice** (`ADMIN_FAKE_VERIFIER=1`, jeton `factice:<adresse>`) : tests locaux et CI seulement ; **`readConfig` lève une `ConfigError` (le serveur s'arrête) en production, en recette et sur Cloud Run**. Les aperçus de PR n'ont pas de panneau utilisable (leur adresse n'est pas chez Google) et n'ont jamais le factice.
- **Tables** (`PLATFORM_SCHEMA`) : `admin_sessions` (gardée ; supprimée un jour après sa fin), `journal_admin` (**vidée** par la remise à zéro : elle nomme des pseudos ; gardée 365 jours), `journal_erreurs` (gardée ; **14 jours**), `resultats_retires` (**vidée**, effacée avec le joueur et suivant « Changer mon code »). Colonnes : `players.hidden` / `players.ref`, `results.hidden`, `jump_results.hidden`, `salon_runs.hidden`. Migrations **additives et réversibles** (`db.ts`, retour arrière en commentaire ; `adminMigration.test.ts`).
- **Journal** : une ligne par action, **dans la même transaction que l'action** (heure, empreinte, action, cible `pseudo · référence`, avant / après) ; **une suppression ne garde que le pseudo** (jamais le contenu effacé). **`journal_erreurs`** : un code de la liste unique, la route (`routeDe` : sans date, numéro ni identifiant) et l'heure — **ni joueur, ni adresse, ni corps** ; notées : les statuts ≥ 500 et les refus de rediffusion (`invalid_replay`, `sim_version`, `track_mismatch`, `not_finished`, `replay_copy`, `version`, `not_daily`, `invalid_level`) sur une route d'envoi ; **écriture bornée à 60 par minute et par instance**. L'entretien (`journaux.entretien`) efface ce qui a passé sa durée, **au plus une fois par heure et par instance, jamais pendant une lecture** (`smoke --lecture-seule` ne doit rien écrire).
- **Joueurs** : l'**identifiant secret ne sort jamais** : un joueur se nomme par sa **référence** (`players.ref` = 12 premiers hexadécimaux du SHA-256 de l'identifiant ; calculée à la création et à « Changer mon code », réparée au passage pour les joueurs d'avant). Recherche : début de pseudo (index de `name_key`, sans accents ni casse) ou de référence ; 50 par page ; filtre `masques`. Fiche : création, dernière partie, jours joués, résultats par jour et par jeu (temps, médaille, rang ; les places gardées des jours fermés sont réutilisées).
- **Les cinq actions** (toutes confirmées, journalisées, appliquées aux classements à la **fenêtre de calcul suivante** : l'instance qui agit oublie sa mémoire — `portail.oublier`, `onErased` des jeux —, les autres à l'expiration de la leur, 45 s au plus pour le classement du jour) : (1) **renommer** (`checkForm`, `assertFree`, `onRename` des jeux) ; (2) **masquer / démasquer** : `players.hidden` et `hidden` **recopié sur chaque résultat** du joueur (Track, Jump, Salon) — **tous les classements écartent `hidden = 1`** : place, nombre de classés, haut du classement, fantôme du premier, classement du jour du portail (`results_by_visible`, `jump_results_by_visible` : sans lire la table) ; ses nouveaux résultats héritent de la marque ; **lui ne voit aucune différence** (ses lignes `own`, son profil, son état « fini » et sa place sont lus sans le filtre ; sa place compte les visibles devant lui) ; les places finales gardées des jours concernés sont oubliées ; (3) **retirer un résultat** : la ligne sort de `results` / `jump_results` et va dans `resultats_retires` avec un motif (3 à 200 caractères) — **la rediffusion est gardée 30 jours puis vidée** (le motif reste) ; la même rediffusion ne revient pas (`409 replay_copy`) ; (4) **supprimer le profil** : même effacement que `POST /api/admin/effacer` (crochets `erase`) + le journal ; il faut **retaper le pseudo** ; (5) **voir une rediffusion** : le lien du lecteur du jeu s'il existe (`lienRediffusion` : Jump `?watch=first` pour le premier du jour ; Track n'a pas de lecteur d'une rediffusion d'un autre).
- **Tableau de bord** (`GET /api/admin/tableau`, **calculé au plus une fois par minute et par instance**, vidé par une action ; les jours fermés des 14 jours sont gardés en mémoire, un recalcul ne relit qu'aujourd'hui et hier). **Définition de « joueur du jour »** : un joueur **distinct** qui a **au moins un résultat classé (rejoué par le serveur) ce jour-là, dans Track ou dans Jump** (jour de Paris) ; un joueur qui a fini les deux jeux compte **une fois** ; masqués et joueurs fictifs de la recette comptés ; ceux qui n'ont pas fini (ni Salon, ni vies de Jump seules) ne le sont pas. « Nouveaux profils » : `players.created_at` dans le jour de Paris. « Track finis » : résultats classés du jour ; « Jump finis » : idem, avec les morts (somme des vies envoyées aujourd'hui ; pour un jour fini, le total figé de `jump_deaths`). Courbe : 14 jours, barres pleines. État : API et base (temps de réponse d'un `SELECT 1`), version (`RELEASE_TAG` et commit), jours prêts par jeu (registre figé de Track, planning à venir ; fichiers figés de Jump), erreurs serveur et rediffusions refusées sur 24 h, le nombre de « PR depuis la dernière mise en production » n'est **pas** calculé par le serveur (`prDepuisMiseEnProduction` reste `null`) : le panneau le lit sur GitHub depuis le navigateur de l'éditeur (lot N2).
- **Coûts** (`couts.md` § 8 ; `npm run measure:admin -w @cdj/api`) : aucune requête du panneau ne lit une table entière (test « coût » de `admin.test.ts`, plans `EXPLAIN QUERY PLAN`) ; écarter les masqués ne coûte rien (index qui portent `hidden`). **Tests** : `adminGoogle`, `adminSession`, `adminConfig`, `admin`, `adminMigration` (SQLite **et** libSQL) ; e2e `apps/web/e2e/admin-panneau.spec.ts` (**ports 4190 et 8810 réservés**).
- **Règles** : une nouvelle action d'administration s'écrit dans la **même transaction que son journal** ; un nouveau classement ou une nouvelle lecture de classement **écarte `hidden = 1`** ; un nouveau code d'erreur suit `codes-erreur.md` ; toute donnée du panneau gardée met à jour les **deux** pages de mentions légales.
