## Avatars (lot C1, partie B)
README : `docs/plateforme/lots/lot-C1-retours-avatars-groupes.md` ; code : `src/avatars.ts` (routes, signalements, administration), `src/imagesAvatar.ts` (**le contrôle d'une image, sans dépendance**), `scripts/avatarsDemo.ts` (la recette) ; tests : `test/avatars.test.ts`, `avatarsDemo.test.ts` (SQLite **et** libSQL `file:`). **Une image venue d'un joueur n'est jamais affichée sans les contrôles du serveur et reste toujours signalable** (règle racine, lot C1).
- **Contrôle** (`controlerImage`, octet par octet, aucune bibliothèque) : **WebP nu** (conteneur RIFF avec un seul segment `VP8 ` ou `VP8L`) **ou JPEG** (marqueurs lus un à un jusqu'au balayage) ; **refusés** : tout autre format (PNG, GIF, SVG…), WebP étendu `VP8X` (porte des métadonnées et de l'animation), `EXIF`, `XMP `, `ICCP`, `ANIM`, `ALPH`, JPEG avec `APP1`…`APP15` ou commentaire, image non carrée, côté hors de 16 à 256 pixels, plus de 40 Ko (`IMAGE_OCTETS_MAX`) — **lot U4 : 256 × 256 et 40 Ko (avant : 128 et 20 Ko) ; une image déjà envoyée en 128 × 128 reste valide, le côté minimum ne change pas**. `400 invalid_image` porte la `raison` (`taille`, `format`, `metadonnees`, `dimensions`). **Le navigateur assainit avant l'envoi** (`assainirImage`, `apps/portail/src/avatarLogique.ts` : Chromium écrit un profil ICC dans son WebP, vérifié) ; le serveur ne nettoie rien, il refuse.
- **Modèle** (migration **réversible** : trois tables et une colonne ; retour arrière `DROP TABLE avatars`, `avatar_signalements`, `avatar_interdits`, `ALTER TABLE players DROP COLUMN avatar`) : `avatars` (`kind` `joueur` | `groupe`, `owner` = l'identifiant interne, l'image en base64 — `SqlDb` n'a que des textes —, `hash` = 16 hexadécimaux de son SHA-256, `statut` `visible` | `masque` | `retire`, `revu`, `jour`), `avatar_signalements` (un par signalant et par image ; `traite` quand l'administration a décidé), `avatar_interdits`. **`players.avatar` garde l'empreinte de l'image visible** : un classement l'obtient avec le pseudo, sans lire `avatars`. Index : `avatars_by_hash`, partiels `avatars_a_revoir` et `avatars_masques` (la galerie d'administration ne parcourt rien). Liées à un joueur : vidées par la remise à zéro, effacées avec lui (`eraseStatements`), suivent « Changer mon code ».
- **Routes** : `POST /api/avatar { image }` (un changement par jour de Paris, `429 avatar_limit` ; `403 avatar_banned` ; 20 par adresse), `DELETE /api/avatar`, `POST /api/avatar/signaler { ref }` (un par signalant et par image ; **à 3 signalants différents en attente l'image est masquée aussitôt** et les initiales reviennent), **`GET /api/avatars/<empreinte>`** (les octets : `Cache-Control: public, max-age=31536000, s-maxage=3600, immutable`, `nosniff` ; l'adresse change avec l'image, donc un cache d'un an ne trompe jamais ; **une heure chez Hosting** : le retrait « sans délai » d'une image déjà connue met au plus une heure à sortir des caches ; `404 unknown_avatar` si masquée, retirée ou inconnue). Le champ `avatar` (l'empreinte) accompagne les lignes des classements du portail et des amis, la feuille d'un joueur, `GET /api/amis`, `GET /api/portail/jour` et `…/profil`. **Aucune lecture d'image pendant une partie** : seuls les écrans hors partie en affichent.
- **Administration** (session, `X-Cdj-Admin`, `confirmer: true`, journal dans la même transaction) : `GET /api/admin/images` (les masquées et les signalées d'abord, puis les nouvelles à regarder, 60 par liste), `GET …/images/<kind>/<réf>` (les octets, `private, no-store`), `POST …/garder` (elle reste, ses signalements ne comptent plus), `…/retirer` (les octets sont effacés, les initiales reviennent, un changement par jour reste compté), `…/interdire` et `…/autoriser`. Aucune image n'est dans le journal : le pseudo et l'action seulement.
- **Coût et recette** : `couts.md` § 12. `recette:seed` : 4 joueurs avec une image (« Démo » et trois du classement ; `seedAvatarsDemo`, par le vrai `createApi`, constate d'abord).
- **Codes** : `invalid_image` 400, `avatar_limit` 429, `avatar_banned` 403, `unknown_avatar` 404, `invalid_report` 400 (`codes-erreur.md`, `CATALOGUE_AMIS`).
