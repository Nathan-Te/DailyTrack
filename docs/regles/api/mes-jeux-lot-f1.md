## Mes jeux (lot F1)
README : `docs/plateforme/lots/lot-F1-mes-jeux-favoris.md` ; règles pures : `packages/core/src/favoris.ts` (`@cdj/core/favoris`) ; code : `src/portail.ts` ; tests : `test/portailFavoris.test.ts` (SQLite **et** libSQL), `packages/core/test/favoris.test.ts`.
- **Stockage** : table **`favoris_jeux`** (`PLATFORM_SCHEMA`, clé `(player_id, du)`) — **une ligne par changement** : à partir du jour de Paris `du`, `jeux` (JSON, le dossier de chaque jeu sur le site : `track`, `jump`…) est la liste du joueur. Migration **réversible** (table nouvelle, rien d'existant touché ; retour arrière `DROP TABLE favoris_jeux`). Liée à un joueur : **vidée par la remise à zéro** (`TABLES_VIDEES`), **effacée avec lui** (`players.eraseStatements`), **suit « Changer mon code »** (`players.rotate`), décrite dans les deux pages de mentions (`data-tables="favoris_jeux"`) et dans `docs/plateforme/effacement.md` par le crochet de la plateforme. Pas de colonne sur `players` : l'historique est nécessaire à la règle ci-dessous.
- **Lecture** : `GET /api/portail/jour` avec `X-Player-Id` porte `joueur.favoris` (la liste choisie, la plus récente ; `null` : rien choisi) et `joueur.jeuxDuJour` (les jeux qui comptent pour lui **aujourd'hui**, les jeux visibles seulement) — **la même requête**, une instruction de plus sur la clé de la table (une ligne par changement). Chaque jeu de `jeux[]` porte `nouveau: true` pendant 7 jours après son ouverture (`estNouveau`, d'après `live_from` : `Jeux.liveFrom`) ; Track et Jump (périodes `[[0, null]]`) ne le sont jamais.
- **Écriture** : **`PUT /api/portail/favoris`** (`X-Player-Id`, corps `{ favoris: ["track", …] }` : la liste entière, au plus 12 noms, sans doublon). Ordre : débit en base (adresse `pfv` `FAVORIS_PER_CLIENT` = 40, joueur `pfvp` `FAVORIS_PER_PLAYER` = 20 par fenêtre de 10 min) → corps (taille) → liste (`400 invalid_json` — code existant, son sens étendu dans `codes-erreur.md` : pas un tableau de noms, trop long, ou un jeu inconnu du registre) → joueur connu (`404 unknown_player` : un visiteur garde sa liste dans son navigateur ; `410 code_revoked`). **Seuls les jeux `on` s'épinglent** (un aperçu de PR voit aussi les autres) : un jeu éteint demandé est écarté, un jeu éteint **déjà épinglé reste dans la liste** (`listeApresChoix` : il disparaît de l'accueil sans message et revient avec le jeu). Réponse (`no-store`) : `{ favoris, jeuxDuJour, effetLe, serie, aProlonger, journeesParfaites, aujourdhuiParfaite }` — de quoi redessiner sans relire le jour. **Cache invalidé pour ce joueur** : sa réponse du jour est `private, no-cache` et se recalcule à chaque requête ; le classement du jour gardé en mémoire ne dépend pas de ses favoris : rien à vider.
- **La règle de la journée sur mes jeux** : la journée parfaite, « n fini sur m », la série (`serieDe`) et la ligne de partage portent sur **mes jeux**, ou sur **tous les jeux qui comptent** sans favori (`mesJeuxDuJour` : ses favoris parmi les jeux qui comptent ce jour-là, sinon tous — des favoris tous éteints ou pas encore comptés valent « sans favori »). **Un changement compte à partir du lendemain**, comme `live_from` (lot P) : le choix écrit la ligne `du = demain` (`jourDEffet`), l'ensemble d'une journée est donc **celui du début du jour** — personne ne retire un jeu à 23 h 59 pour obtenir une journée parfaite. **Chaque jour est jugé avec la liste qui était la sienne** (`favorisLe` sur l'historique) : une série à cheval sur un changement ne se casse pas rétroactivement. **Exception : la première visite** — un joueur dont le profil est créé **aujourd'hui** (`players.created_at` dans le jour de Paris) n'a pas de début de journée à protéger : son choix compte tout de suite (`du = aujourd'hui`). Plusieurs changements dans la journée n'écrivent qu'une ligne (celle de demain) ; un choix qui rétablit la liste d'avant la **supprime** (basculer une étoile puis la remettre ne laisse rien, `favoris` redevient `null`).
- **Ce qui ne change pas** : le **classement du jour** (`/api/portail/classement`) suit la liste des jeux du classement général réglée par Nathan, jamais les favoris ; les classements des jeux, le profil commun (`/profil`, ses séries sont celles de `serieDe`, donc sur mes jeux), l'administration. Le joueur de démonstration de la recette a **Track en favori, pas Jump** (`DEMO_FAVORIS`, `portailDemo.ts` : choisi aujourd'hui, compté dès aujourd'hui ; ses 5 jours de série et ses 2 journées parfaites d'avant ne bougent pas).
- **Coût** : lecture du jour +1 instruction sur la clé `(player_id, du)` (0 à quelques lignes), aucune écriture ; `PUT` : 2 instructions de débit, 2 lectures (historique, `created_at`), 1 écriture ; plan vérifié (`favoris_jeux` est dans `GRANDES_TABLES` de `plans.ts`, aucun `SCAN`).
