# Le niveau du jour des jeux du kit (lot D4)

> Règle du lot D4, écrite ici parce qu'elle ne sert qu'à ce sujet ; le renvoi est dans [`apps/api/CLAUDE.md`](../../../apps/api/CLAUDE.md). README du lot : `docs/plateforme/lots/lot-D4-niveau-du-kit-hors-du-fil.md` (mesures comprises).

**Un jeu du kit ne calcule jamais son niveau dans le fil principal.** Même mécanisme que le lot D3 (Jump, Track), étendu à tout jeu monté par `definirJeuNeuf`, sans en nommer aucun.

- **Le calcul.** `definirJeuNeuf` donne à sa `GameDefinition` `niveauDuJour(options, jour)` : `niveauDuJour` **et `seuils`** du contrat, sans plateforme (un `Proxy` qui lève si le contrat y touche : Rush ne la lit que dans `rejouer`). `niveauxFil.ts` (`DemandeKit` `{ jeu: "kit", code, day, frozen }`, `calculerNiveauKit`, `servirNiveaux`) l'appelle par le code du jeu ; `niveauxFilTravail.ts` passe le registre. **Un second fil du même script** (`server.ts`, `DELAI_NIVEAU_KIT_MS` 300 s, file de 32) : le robot d'un jeu ne fait jamais attendre Jump ni Track. Sans `niveaux-fil.mjs` (tests, outils, développement) : sur place, comme avant. **Les seuils sont calculés avec le niveau** : le robot peut tourner dans `niveauDuJour` (Pinball, Gravity) comme, paresseusement, dans `seuils` (Rush : 1 s qu'on ne voyait pas dans `niveauDuJour`) ; le fil principal ne rappelle jamais `seuils` pour un niveau venu du fil. **Toute autre méthode du contrat** (`infoJour`, `theme`, `contenuPublic`, `empreinteAuteur`…) **tourne dans le fil principal : elle reste brève.**
- **L'état voyage avec la demande** (piège de D3) : le fil ne reçoit que **le fichier figé du jour** (option `frozen`, lot K4f), jamais l'image entière. Un contrat qui lirait un état de module hors de ses arguments calculerait un autre niveau dans le fil.
- **Un niveau calculé se garde.** `ContratJeu.garderEnBase` : sans table de niveaux, le module garde la ligne de `calculer` dans **`meta`** (`niveau:<jeu>:<jour>` : la version du code `platform.revision` — révision Cloud Run ou commit —, la règle, la ligne) ; pas de table nouvelle (aucune donnée de joueur : ni remise à zéro, ni mentions). **Une autre version du code ne relit jamais ce que l'ancienne a gardé** (un robot ou un générateur modifié ne change pas `versions()`) : elle recalcule. **Gardé seulement si petit (`NIVEAU_GARDE_OCTETS_MAX`, 16 Ko) et si le JSON ne perd rien** (`memeValeur` : ni `undefined`, ni tableau typé, ni `-0`, ni `Map`) : sinon la ligne est vide et le niveau se recalcule dans le fil (Rush : 300 à 417 Ko de tableaux typés). Une valeur abîmée est recalculée, jamais crue ; une écriture refusée ne perd pas le niveau.
- **L'accueil n'attend jamais un niveau en cours de calcul** (`ContratJeu.jourSansNiveau`, présent seulement hors du fil principal) : le calcul part, l'accueil rend le jeu avec son numéro et **le thème du calendrier du jeu** (`ContratMinimal.themeDuJour(jour)`, à écrire dès qu'`theme` ne dépend que du jour), `seuils: null` et `provisoire: true` ; sa réponse publique n'est alors gardée que `PORTAIL_PROVISOIRE_MAX_S` (5 s) au lieu de 60 s. Un niveau qu'il suffit de relire en base est attendu (quelques ms). Un calcul qui échoue n'est pas relancé par l'accueil avant 60 s ; une route du jeu (`day/<date>`, envoi) attend, elle, le niveau et réessaie.
- **Préparés à l'avance** : `preparerAuDemarrage` (`api.ts`, `GameInstance.prepareAuDemarrage`) lance à la première requête d'une instance, sans l'attendre, aujourd'hui puis demain de chaque jeu du kit **non éteint** ; `preparerLeLendemain` (D3) prépare le jour suivant dans la demi-heure d'avant minuit. Un échec est retenté au plus toutes les 2 min.
- **Un robot coûteux est permis** (ordre de grandeur : `docs/regles/racine/creer-un-jeu.md`). Limite connue : Cloud Run ne donne du processeur qu'**pendant une requête** (`--cpu-throttling` par défaut) : un calcul de fond avance surtout quand une route du jeu l'attend.
- Tests : `apps/api/test/niveauxKit.test.ts` (un jeu fictif aux seuils de 3 s dans un vrai fil : accueil, `/api/jeux`, classement < 500 ms, boucle < 100 ms ; garde en base et empreinte ; autre version du code ; JSON sans perte de chaque jeu du registre) ; mesure : `npm run measure:niveaux-kit -w @cdj/api`.
