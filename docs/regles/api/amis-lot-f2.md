## Amis (lot F2)
README : `docs/plateforme/lots/lot-F2-amis.md` (le contrat des routes) ; code : `src/amis.ts` (routes, listes, invitations), `src/classementAmis.ts` (le filtre `filtre=amis` et la feuille d'un joueur), `classementDuJour.ts` (`rangEntreAmis`, `ligneDeTri`) ; tests `test/amis.test.ts`, `amisCout.test.ts`, `amisDemo.test.ts` (SQLite **et** libSQL `file:`) ; coûts : `couts.md` § 11, `npm run measure:amis`.
- **Modèle** : `amities (joueur, ami, origine, cree_le)`, clé `(joueur, ami)` + index `amities_by_ami` ; `invitations_amis (joueur PK, empreinte UNIQUE, cree_le)` (un lien actif par joueur). Les deux sont dans `PLATFORM_SCHEMA` (migration **réversible** : `DROP TABLE` des deux), dans `TABLES_VIDEES` (remise à zéro du lancement) et dans `players.eraseStatements` (effacement : les deux sens + le lien) ; « Changer mon code » : `rotate` met à jour `joueur`, `ami` et `invitations_amis` dans la même transaction (la liste ne change pas, la `ref` si). Une ligne = « `joueur` voit les temps de `ami` ». **Ajout par pseudo ou depuis un classement : sens unique** (l'autre n'est pas prévenu) ; **invitation : deux lignes**. 100 au plus **par joueur, masqués compris** (le plafond est vérifié **à l'écriture** : `INSERT … SELECT … WHERE COUNT < 100 ON CONFLICT DO NOTHING RETURNING`) ; `total` ne compte que les visibles.
- **Référence publique = `players.ref`** (12 hexadécimaux de SHA-256(identifiant secret) : à sens unique, déjà publique depuis le lot 55). **L'identifiant secret ne sort jamais** (ni réponse, ni journal), il n'est lu que dans `X-Player-Id` ; une amitié est rangée par identifiant interne. **Un joueur masqué a le visage d'un inconnu** partout (`unknown_friend`, `invalid_invitation`, liste, classement filtré, suggestions, compteur).
- **Jeton d'invitation** : 18 octets de Web Crypto, 24 caractères base64url, **rendu une seule fois** (`POST /api/amis/invitation`, qui crée ou renouvelle) ; le serveur ne garde que **SHA-256** (`invitations_amis.empreinte`). Un lien inconnu, renouvelé, mal formé ou d'un joueur masqué : `404 invalid_invitation` (un seul visage). Accepter sans profil serveur : pseudo obligatoire (`name_required`, `name_taken`…), **rien n'est écrit avant que les deux listes aient été vérifiées** (`friends_full` / `their_friends_full` ne créent ni amitié ni profil) ; les profils créés ainsi sont limités à 5 par adresse et fenêtre (`AMIS_PROFILS_PAR_ADRESSE`).
- **Le filtre `filtre=amis`** (portail et ses trois vues, Track `leaderboard`, Jump `board`, Tower `board`) : toute autre valeur `400 invalid_filter` ; `X-Player-Id` obligatoire ; réponse `private, no-cache` + `Vary: X-Player-Id` (« Tous » inchangé : cache public intact). Toi et tes amis **sans la limite de 50** : `rang`/`rank` = rang entre amis, `rangGeneral` = rang « Tous » de la vue (à 45 s près pour les amis : c'est le classement gardé), `ref` sur chaque ligne, `moi: true`, `classes`, `amis`, `absents: [{ ref, pseudo }]`, `filtre: "amis"`. **Aucune requête par ami** : les rangs viennent du classement du jour que `portail.ts` garde par fenêtre (`VuePartagee`, crochets `portail.classes(day)`), seuls la liste des amis (une jointure indexée) et les **états exacts du joueur qui regarde** (ce qu'il vient de finir se voit tout de suite, comme dans « Tous ») sont lus ; Jump lit en plus les morts des seuls amis classés. Un classement de jeu filtré passe **après la garde de l'interrupteur** (`api.ts` → `amis.classementJeu`) ; **un nouveau jeu ajoute sa ligne à `MOTIFS_JEUX`** (`amis.ts`) et, s'il ne se classe pas au temps ni à la hauteur de Tower, sa mise en forme à `classementAmis.ts`. Les lignes de jeu portent `rank` (son nom) **et** `rang` (le contrat) ; `ref` est sur toute ligne de « Tous » (`top`/`me` : portail, Track, Jump, Tower).
- **`GET /api/portail/jour`** avec joueur : `joueur.rangEntreAmis: { rang, sur } | null` (une seule requête de plus, **seulement** si le joueur a fini un jeu ; `null` sans ami ou si aucun ami n'a rien fini). **`GET /api/amis/fiche/<ref>?date=`** : ses temps du jour par jeu (valeur, médaille, rang), son rang au cumul, `ami` / `reciproque` — lus dans le classement gardé, **rien d'autre** sur lui.
- **Index et plans** : tout passe par la clé de `amities`, `amities_by_ami`, `invitations_amis_by_empreinte` et `players_by_ref` / `players_by_name_key` ; les deux tables sont dans `GRANDES_TABLES` (un `SCAN` fait échouer le test). Suggestions : début de pseudo (≥ 3 lettres, ≤ 5 résultats, 300 candidats lus au plus) des joueurs avec un résultat classé non masqué dans les 30 derniers jours, ni soi ni un ami.
- **Débit** : ajout / retrait (`amwip`/`amw`), lien (`amnip`/`amn` : 10 par joueur), acceptation (`amaip`/`ama`, `amkip` : profils créés), lectures (`amlip`, `amfip`, `amsip`, `amvip`) et classements filtrés (`amcip`) — par adresse **avec** l'adresse de connexion (`hitAddress` / `readHitAddress`) et par joueur. **Journaux** : jamais de pseudo, d'identifiant, de jeton ni d'adresse.
- **Recette** : `scripts/amisDemo.ts` (appelé par `recette:seed`, **jamais** importé par `src/`) donne à « Démo » 5 amis par le vrai `createApi` (4 du classement du jour dont 3 réciproques, 1 pilote de l'historique qui n'a pas joué aujourd'hui) ; il constate (une lecture) et ne recrée que ce que l'effacement de « Démo » ou d'un joueur du classement a retiré. **Coût** : `couts.md` § 11 (0 / 10 / 100 amis) ; garde-fou `amisCout.test.ts`.
- **Mentions légales** (les deux pages) : la rubrique « Tes amis » (`amities invitations_amis`, `AMIS_MAX`) et la clé `cdj:invitation` (sessionStorage) ; toute nouvelle donnée des amis les met à jour (règle de fidélité du `CLAUDE.md` racine).
