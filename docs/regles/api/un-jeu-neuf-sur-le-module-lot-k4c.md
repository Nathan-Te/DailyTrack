## Un jeu neuf sur le module (lot K4c)
README : `docs/plateforme/lots/lot-K4c-jeu-neuf-generateur-et-temoin.md`. Code : `src/jeux/defauts.ts`, `adaptateur.ts` (`adaptateurResultatsJeu`) ; tests : `test/jeuNeuf.test.ts` (un jeu jouet, **deux fiches de test** : un score ↓ et un temps ↑, SQLite **et** libSQL) et `test/jeuNeufAide.ts`.
- **La table commune `resultats_jeu`** (`PLATFORM_SCHEMA`, migration **réversible** : `DROP TABLE resultats_jeu`) : une ligne par `(jeu, day, player_id)`, `cle1` à `cle3` = les colonnes de classement de la fiche **rangées en croissant** (`cle1 = -score` pour un score décroissant : `signe: -1`), `mesures` (JSON), les colonnes de la plateforme (`medal`, `replay`, `inputs_hash`, `hidden`, `apercu`…). **Un seul index** `(jeu, day, hidden, cle1, cle2, cle3, submitted_at, player_id)` sert tous les sens ; une fiche a une à trois colonnes de classement (les clés inutilisées restent à 0, `remplissage`). **Vidée** par la remise à zéro, décrite dans les deux pages de mentions, effacée / suivie par le module (`erase`, `rotateStatements`) ; **seule table nouvelle du lot**. Le niveau du jour d'un jeu neuf **n'est pas gardé en base** (`AdaptateurTable.niveaux` absent : déterministe, recalculé et gardé en mémoire de l'instance).
- **Le contrat minimal** (`ContratMinimal`) : `versions`, `niveauDuJour(jour)` (pure), `decoder`, `rejouer`, `score` (les colonnes de la fiche), `seuils` (Diamant, or, argent, bronze), `entrees` (le texte canonique dont le module prend l'empreinte). **Aucun point d'extension n'est obligatoire.** Facultatifs : `theme`, `empreinteAuteur`, `contenuPublic`, `mesures`, `ticksParSeconde`, `fantome`, `joursFiges`.
- **Les formateurs par défaut** (`contratDeFiche(fiche, nom, minimal)`), tirés de la fiche : ligne de classement `{ rank, name, <colonnes>, medal, ref }`, réponse d'un envoi `{ accepted, date, score, medal, improved, best, rank, participants, board }`, jour du profil `{ date, <colonnes>, medal }`, `day/<date>` `{ versions, medals, theme, contenu? }`, jour du portail (numéro depuis `premierJour`, thème, seuils ; `unite` si le jeu n'est pas au temps), médaille par les seuils dans le sens de la première colonne (`medailleParSeuils`), `jourDe` / `memeContenu` / règle du niveau / journaux. `definirJeuNeuf({ fiche, nom }, contrat)` rend la `GameDefinition` du registre (routes `/api/<code>/`, grâce de 10 min, 50 lignes, compteurs de débit `<code>ip|p|rd|meip|me`).
- **L'enveloppe de rediffusion** est dans `@cdj/core/enveloppe` (`packages/core/CLAUDE.md`) ; `refusDEnveloppe` la traduit en code de la liste unique (`invalid_replay`, `version`).
- **Amis, « Mon groupe », suggestions et groupes d'un jeu neuf (lot K4d)** — **aucune ligne à écrire** : `amis.ts` ne garde que `FORMATS_HERITES` (les adresses et formes de ligne de Track, Jump et Tower, que les bancs fixent) ; tout autre jeu qui déclare `GameInstance.lignesAmies` (le module le fait pour tout jeu qu'il monte) est lu à `/api/<code>/day/<date>/board?filtre=amis|groupe` : les colonnes de la fiche des seuls joueurs de la liste, **une requête** (`sql.joueurs(n)`, **`INDEXED BY resultats_jeu_by_player` imposé** par `AdaptateurTable.indexJoueur` : sans lui SQLite préfère l'index du classement et lit toute la journée), mises en forme par la ligne de « Tous » (`ligneClassement`). Les suggestions lisent l'activité de chaque jeu dans `admin.activite` (table et `portee` sur une table partagée : `jeu = 'cibles'`). Le classement des groupes, lui, lit déjà `estHauteur` : un jeu à un score a sa vue (le plus grand d'abord ; **limite** : un score qui se classe du plus petit au plus grand, hors temps, n'a pas son sens dans les groupes). **Le portail rend l'unité du jeu** (`PortailDuJeu.unite` : `mm` par défaut, `points` pour un jeu neuf ; le client lit le format de la fiche : `entier`) ; la feuille d'un joueur rend `unite: "entier"`. **Les trois bancs de réponses ne bougent pas** ; `test/jeuNeufAmis.test.ts` le prouve sur le jeu jouet (SQLite **et** libSQL).

## La partie du n° 1 du jour et le classement vide (lot « manques de Blocks »)
- **`premier: true`** dans le contrat d'un jeu : `GET /api/<jeu>/day/<date>/first` → `{ date, name, replay, simVersion, generatorVersion, mine }` (la requête `premier` de `sqlDe`, dans l'ordre du classement). Jour **ouvert** : `X-Player-Id` obligatoire et classé ce jour-là (`403 not_ranked` sinon — on le débloque en finissant, comme le fantôme) ; jour **fermé** : public ; `404 no_ghost` si personne n'est classé. Jamais l'identifiant du premier. Test : `apps/api/test/blocks.test.ts`.
- **Le portail ne garde pas un classement vide d'un jour ouvert** (`gardeeDe`, `Gardee.vide`) : sans cela la première lecture, faite avant que quiconque ait joué, figeait toutes les vues 45 s. Un classement qui a des classés reste gardé toute sa fenêtre (`CLASSEMENT_FENETRE_MS`). Test : `apps/api/test/portailVide.test.ts`.
