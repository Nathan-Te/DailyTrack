## Des envois sans faux « serveur indisponible » (lot D2)
README : `docs/plateforme/lots/lot-D2-envois-sans-faux-indisponible.md` ; enquête : `docs/plateforme/analyse-refus.md`.
- **Un renvoi déjà accepté répond avant le rejeu (C5)** : même joueur, même jour (et même état d'aperçu), **même rediffusion (texte identique)** que la partie déjà écrite → `200` avec **la réponse d'un envoi qui n'améliore rien** (`improved: false`) plus **`deja: true`**, construite sur la ligne écrite (temps, rang, classement d'aujourd'hui) : **ni rejeu, ni `spendReplays`, ni écriture**. C'est la file du jeu qui renvoie exactement ce texte après un délai dépassé. Une rediffusion équivalente aux entrées près passe par le rejeu comme avant. **Dans le module** (`jeux/module.ts` : `dejaAccepte`, `reponseDeja` ; requête `sql.deja` ; le contrat fournit `mesureDeLigne`, sans lui le jeu garde l'ancien comportement ; Jump l'appelle dans son `valider`, juste après le texte et avant le décodage ; Tower dans le chemin standard, juste après le jour ouvert) **et dans `cdj.ts`** (`reponseDejaAcceptee`, juste après `assertActive`). Le code du joueur est vérifié avant (`code_revoked` reste refusé). Les **trois bancs** ne changent que ce cas : `deja: true` ajouté à la réponse « même partie renvoyée » de chaque jeu (et, pour Tower, `posees`/`tombees` à 0 dans `resultat` : ces deux nombres ne sont pas gardés ; le jeu lit sa propre partie pour les afficher).
- **Les refus par cause** (`journaux.ts`, `causeDe`) : `perime` (`version`, `sim_version`, `track_mismatch` : un onglet d'avant une mise en production), `invalide` (`invalid_replay`, `not_finished`, `replay_copy`, `invalid_level` : **la ligne à surveiller pour un vrai écart de déterminisme**), `limites` (`rate_limited`, `busy`), `jour` (`day_closed`, `not_daily`). `journal_erreurs` note aussi, sur une route d'envoi, `rate_limited` et `day_closed`. `GET /api/admin/tableau` rend `etat.erreurs24h` (le total « rediffusions » **ne compte plus les onglets périmés ni les limites** : `perimes` et `limites` à part) et **`etat.refus`** : `{ h24, j7 }`, chacun `{ total, parJeu[] }` avec, par jeu (le préfixe de sa route), le nombre par cause et le détail par code. Une instruction de plus par calcul du tableau (au plus une par minute et par instance), sur l'index `journal_erreurs_by_time`.
- **Mémoire de l'instance : 1 Gio** (`deploy-api.yml`, recette et production) ; le processeur, le nombre d'instances et la concurrence ne changent pas.
