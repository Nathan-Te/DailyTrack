## Tower sur la plateforme (lot TP)
README : `docs/plateforme/lots/lot-TP-tower-sur-la-plateforme.md` ; jeu : `docs/tower/consignes.md`. Tower est au registre (`registry.ts`), `TABLES_VIDEES` (`tower_results`) et `TABLES_GARDEES` (`tower_levels`), les deux pages des mentions, `erase` (`partiesDailyTower`). Il reste `off`.
- **Le score en hauteur dans les crochets** (`games.ts`) : `ScorePortail = { unite: "mm", valeur, vies }` est un champ **facultatif à côté des champs existants** (`EtatPortail.fini.score`, `ClasseDuJour.score`, `ResultatAdmin.score`), `JourPortail.unite?: "mm"` (les seuils sont alors en mm) et `PortailDuJeu.classement?: "temps" | "hauteur"` (défaut `temps`). Un jeu au temps ne pose jamais ces champs : **ses réponses ne changent pas d'un octet** (testé : `towerPortail.test.ts`). Pour un jeu à la hauteur, `tempsMs` n'est que la durée de la partie (le dernier départage). Forme choisie parce qu'elle ne touche ni les contrats ni les tests de Track et de Jump et qu'un client ignorant `score` retombe sur `tempsMs`.
- **Le portail** (`portail.ts`) : `classerLaJournee` ne reçoit que les jeux au temps (**le cumul ignore Tower**) ; un jeu à la hauteur a sa **vue** (`GET /api/portail/classement?vue=tower` : `unite: "mm"`, chaque ligne et `moi` portent `score`, ordre du jeu : hauteur, vies, ticks, envoi), garde sa place dans `jeux[]` (avec `unite`), compte dans la série et la journée parfaite (`live_from`), et son état `fini` porte `score`. `GET /api/admin/joueurs/<ref>` rend `score` pour ses résultats ; le tableau de bord ajoute `chiffres.tower` si le jeu est au registre. L'état et le profil d'un joueur incluent ses parties d'aperçu (il se voit ; les classements les écartent : `hidden = 1`).
- **L'image du serveur** : `build-node.mjs` lit `apps/tower/public/jours/*.json` (**preuve comprise : elle reste dans l'image**, le serveur la rejoue) dans `__TOWER_JOURS__` et construit une **seconde entrée** `dist/tower-fil.mjs` (`towerFilTravail.ts`) ; le `Dockerfile` copie `packages/tower-sim`, `apps/tower/public/jours` et le fil. `server.ts` lit `tower-fil.mjs` à côté de lui : s'il y est, les rejeux passent par `executeurFil` (un seul fil, file de 4), sinon par le fil principal (repli) ; **une ligne de journal au démarrage le dit** (« Tower : les rejeux passent par le fil de calcul », sans donnée personnelle) et chaque partie journalise son exécuteur (`executeur: "fil"`). Test sur le paquet construit : `test/towerImage.test.ts` (construit, lance `server.mjs`, joue une partie, lit le journal).
- **Les jours** : `apps/tower/public/jours/AAAA-MM-JJ.json`. « Mettre en production » les prépare (job `figer`, `scripts/mise-en-production.mjs preparer-jeux` — lot K4b : la fenêtre, les scripts et le garde-fou viennent de `jours.fabrication.preparer` de la fiche —, fonctions pures `planPreparation`, `resumePreparation`, `joursAPoser`) : protégés = inchangés, sans résultat = préparés/refaits/gardés selon (`g`, `sim`), fenêtre veille de la bascule → J+14. `lireResultats` lit aussi la vue de chaque jeu à `unite` (un jour joué seulement à Tower est protégé). Les empreintes (`apps/api/scripts/tower-empreintes.ts`, clé `tower` de `jours-passes.json`) comparent ce que sert la production et la construction ; **un jeu absent du code en production (la première fois) n'a rien à conserver** (`comparerEmpreintes`).
- **Recette et vérifications** : `SERVER_PATHS` (+ `packages/tower-sim/**`, `apps/tower/public/jours/**`) ; `smoke` complet joue une partie scriptée (`tower-aide.ts`, **jamais une preuve**) comme un **aperçu de PR** (hors production : rangée à part) et vérifie qu'un serveur de production est **fermé** pour Tower ; `smoke --lecture-seule` accepte « fermé » ou ouvert et vérifie que le jour ne montre jamais de `preuve` ; `recette:seed` joue 8 joueurs fictifs sur le jour courant **seulement si Tower est `on` sur la recette**.
- **Coût** : `TOWER_PLAYER` (`platformBudget.ts`, 10 requêtes, ≈ 720 lignes lues) et `measure:platform --tower N` ; mesuré sur la base de référence (`measure:lignes`, `routesChaudes.ts` : classement, profil, envoi de Tower) ; **le `sqld` local n'a pas pu servir** (pas de Docker dans l'environnement du lot) : à remesurer par `npm run measure:tower -w @cdj/api`.
