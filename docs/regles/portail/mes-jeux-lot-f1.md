## Mes jeux (lot F1)
README : `docs/plateforme/lots/lot-F1-mes-jeux-favoris.md` ; charte : `docs/plateforme/identite.md` § 9 (révision 15), maquette `docs/plateforme/maquettes/favoris-et-amis.html` (planche A) ; serveur : `apps/api/CLAUDE.md`, « Mes jeux (lot F1) » ; liste côté client : `packages/profile/CLAUDE.md`.
- **L'accueil** : une **étoile de 44 px par cartouche** (`boutonFavori` de `@cdj/ui`, `aria-pressed`, nom lu « Ajouter Track à mes jeux » / « Retirer Track de mes jeux », clés `portail.favoris.ajouter` / `retirer`, fr + en — **dans le catalogue du portail, pas le commun** : le français commun est dans le premier chargement de Jump, dont le budget n'a pas la place ; `data-cle="favori-<jeu>"`, le focus la suit quand la cartouche change de place). **« Mes jeux »** : les jeux épinglés en cartouches pleines, dans l'ordre de la plateforme (jamais celui des clics : l'ordre manuel est hors périmètre) ; **« Les autres jeux »** dessous, en **cartouches compactes** (`cartouche({ compacte: true })` : une variante du composant, pas un dessin par jeu — nom, numéro, « Jouer », étoile, sur la coque et la police du jeu). **Sans favori** (`repartir`, `src/mesJeux.ts`, pur) : l'accueil d'avant, tous les jeux en cartouches pleines (« Les jeux du jour »), plus la ligne « Touche l'étoile pour garder tes jeux en haut. » dès qu'il y a deux jeux. **Seuls les jeux que le serveur liste (`on`) sont des cartouches** : un favori dont le jeu repasse à `off` disparaît sans message et revient avec lui (le serveur garde la liste). L'étoile reste après « Jouer » dans l'ordre du clavier : l'action principale à la manette (`PAGES_MANETTE.accueil`, `.dj-cartouche .dj-bouton`) est toujours « Jouer ».
- **« Nouveau »** : la pastille (`.dj-badge-nouveau`, terre cuite) sur un jeu ouvert depuis moins de 7 jours (`nouveau` de `GET /api/portail/jour`), **tant qu'il n'est pas épinglé** ; un jeu ouvert arrive dans « Les autres jeux » : seul le joueur l'épingle.
- **La journée sur mes jeux** : « n fini sur m » (`avancement(jeux, jeuxDuJour)`, `jeuxDeLaJournee`) et la ligne de partage (`construireOptions`) ne portent que sur **`joueur.jeuxDuJour`** (rendu par le serveur) ; sans favori ou sans réponse, tous les jeux qui comptent. **Un changement compte à partir de demain** : la ligne « Ton choix compte pour ta journée à partir de demain. » (`#favoris-demain`, `choixPourDemain`) le dit tant que les jeux épinglés ne sont pas ceux de la journée. Le classement du jour (`/classement/`, la tuile) **ne change pas**.
- **Écrire** (`basculerFavori`) : un joueur que le serveur connaît — la liste change tout de suite à l'écran, puis `PUT /api/portail/favoris` (la liste entière ; une écriture à la fois ; la réponse redessine, **sans relire le jour**) ; un échec remet la liste d'avant et dit « Ton choix n'a pas pu être enregistré » (`#message-favoris`). Un **visiteur** (sans profil connu du serveur) : la liste reste dans `cdj:favoris` (écrite par `ecrireFavorisLocaux` de `@cdj/profile` sur le stockage de `src/stockage.ts`, qui reste le seul accès du portail ; `try/catch`), reprise dans son profil à sa création (`reprendreFavoris`, après le rendu). Toujours **une seule requête au chargement**.
- Fichiers : `src/mesJeux.ts` (pur : `repartir`, `choixPourDemain`), `src/portail.ts` (rendu, `basculerFavori`, `reprendreFavoris`), `src/jour.ts` (types, `jeuxDeLaJournee`), `src/portail.css` (`.portail-etagere--compacte`, `.dj-badge-nouveau`). Textes : `portail.mesJeux.titre`, `portail.autresJeux.titre`, `portail.favoris.*`, `portail.nouveau` (catalogue du portail, fr + en). Vitrine `/ui/` : l'étoile dans ses états et les cartouches compactes. Tests : `test/mesJeux.test.ts` ; e2e un seul (épingler › l'ordre change › recharger) dans `apps/web/e2e/portail-jour.spec.ts`.
