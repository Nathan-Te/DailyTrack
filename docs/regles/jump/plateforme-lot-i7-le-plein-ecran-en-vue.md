## Plateforme (lot I7) — le plein écran en vue
README : `docs/plateforme/lots/lot-I7-plein-ecran.md`. **Règle (Nathan) : le plein écran est important sur mobile (la barre du navigateur mange la hauteur en paysage) : il est toujours en vue, jamais seulement dans la pause.** Le rendu, la simulation et les zones tactiles ne changent pas ; **Jump n'a pas de choix de caméra** (une seule, orthographique, qui suit le personnage) : aucun bouton caméra.
- **Une seule logique, celle du socle** (`@cdj/ui` : `pleinEcran.ts`, `boutonPleinEcran`, `astuceIphone` ; `packages/ui/CLAUDE.md`) : `pauseMenu.ts` n'a plus `fullscreenAvailable` ni `toggleFullscreen`. **En partie** : `#fullscreenbtn`, 44 px, en haut à gauche **juste après la pause** (`#hud-gauche`, plaque du HUD, dans `main.ts` à côté de `#pausebtn`) ; la bande du centre et la zone du personnage ne bougent pas. **Sur l'accueil** : dans la barre des jeux, à côté de la date (`barreDuJour({ pleinEcran: true })`, `home.ts`). **Dans la pause** : `#menu-fullscreen`, le même bouton en texte. Caché si l'API n'existe pas (iPhone) ou si le site est une application ; **sur iPhone**, l'accueil montre une fois, sous le titre, la ligne « Partager › Sur l'écran d'accueil » (`#home .dj-astuce` ; `HomeOptions.store` : le stockage où se souvenir qu'elle est fermée). Entrer en plein écran **essaie de verrouiller le paysage** (refus ignoré). **Petit portrait** (≤ 500 px de large, `hud.css`) : `#fullscreenbtn` n'est pas en partie (la bande du centre prend la place) ; il reste sur l'accueil et dans la pause.
