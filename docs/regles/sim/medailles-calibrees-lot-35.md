## Médailles calibrées (lot 35)
- **`medalsFor(tempsDuPilote, jour)`** (`medals.ts` depuis le lot 36, réexportée par `generator.ts`) : **toujours passer le jour** (sans lui : les seuils d'avant). Avant **`BASCULE_LOT_35` = 28/10/2026** : auteur = temps du pilote, or ×1,08, argent ×1,20, bronze ×1,40 (`MEDAL_FACTORS`, lot 4). À partir de la bascule : **auteur = 0,84 × pilote**, or ×1,045, argent ×1,07, bronze ×1,13 **de l'auteur** (`MEDAL_FACTORS_35`). **Lot G1 (demande de Nathan du 28/10 : le Diamant était imprenable) : les circuits du générateur v19 (`GENERATOR_MEDAILLES_G1`) et suivants ont auteur = 0,92 × pilote** (mêmes écarts : or ×1,045, argent ×1,07, bronze ×1,13 de l'auteur : `MEDAL_FACTORS_G1` ; rouler comme le pilote rapporte le bronze). **Plus de date** : `medalsFor(pilote, jour, générateur = generatorVersionOf(jour))` lit la version du jour dans le registre, comme le circuit — un jour servi garde ses seuils, le lendemain d'une mise en production prend les nouveaux ; la v19 a les mêmes circuits que la v18 (seuls les identifiants `-g19` et les médailles changent). `BASCULE_LOT_35` (28/10/2026) reste pour les versions d'avant la v19. Le Salon (graines au-delà des jours) suit les nouveaux seuils. `authorMs` des circuits reste le temps brut du pilote (golden, table `circuits`, identifiants inchangés) ; ce qui s'affiche comme « auteur » est `medals.author`.
- **Origine** : export de production du 22/10/2026 (38 meilleurs temps, 9 jours ; avec les anciens seuils 97 % avaient l'auteur). Facteurs choisis par simulation (`medalPoolStats`) : auteur 5 %, or 32 %, argent 61 %, bronze 87 % des joueurs sur les jours passés (cibles 5–10 / 25–35 / 50–60 / 85–90 %). **Pas de correction par thème** (1 à 3 jours par thème : l'écart d'un jour à l'autre domine). La répartition varie beaucoup d'un jour à l'autre (pilote inégal selon les circuits). Détail : `docs/lots/lot-35-medailles.md`. **Recalibrer** = une nouvelle série de facteurs **pour une nouvelle `GENERATOR_VERSION`** (lot G1 : `MEDAL_FACTORS_G1`, `GENERATOR_MEDAILLES_G1` = 19), **jamais une date** : c'est la mise en production qui décide du premier jour concerné (les jours joués gardent leurs médailles par le registre).
- **Statistiques** (`medalStats.ts`, pur, testé par `test/medalStats.test.ts`) : `percentileOf` (rang le plus proche), `medalDayStats` (percentiles, rapports au pilote, parts cumulées, comptes), `ratiosOf` (temps ÷ pilote, triés : ce que l'export garde), `medalPoolStats` (journées réunies, et **simulation** d'autres seuils exprimés en multiples du pilote), `thresholdsOf`. Servent la route `GET /api/admin/medailles` (cdj.ts) et le calibrage.
