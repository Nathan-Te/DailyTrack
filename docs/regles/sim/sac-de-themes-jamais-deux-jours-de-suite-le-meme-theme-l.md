## Sac de thèmes : jamais deux jours de suite le même thème (lot V1)
README : `docs/plateforme/lots/lot-V1-themes-sans-repetition.md`. **Générateur 20** (`GENERATOR_VERSION`, `GENERATOR_SAC_THEMES` de `dailyId.ts`) ; `SIM_VERSION` inchangée (14) ; les circuits ne changent que par leur thème (et `MAX_ATTEMPTS_SAC`, plus bas).
- **La règle, commune aux deux jeux, écrite une fois** : `packages/core/src/sacThemes.ts` (`themeDuSac`, `ordreDuCycle` ; aucune logique de jeu, des indices de thèmes et des numéros de jour). Les jours se découpent en **cycles de n jours** (n = 8 thèmes) **alignés sur le numéro de jour** (`⌊jour ÷ n⌋`, aucune date écrite) ; dans chaque cycle chaque thème sort **une fois**, dans un ordre tiré de la graine (`mixSeed(cycle, sel)`) ; **à la jonction de deux cycles** le dernier thème du cycle d'avant ne revient pas avant le 3ᵉ jour et l'avant-dernier pas le 1ᵉʳ (seules les deux premières places sont réordonnées : jamais deux jours de suite, jamais A B A) ; deux apparitions d'un thème sont séparées de **2n − 1 jours au plus**. Le calcul d'un jour est **direct** (trois cycles, mis en cache), jamais « rejouer les jours depuis l'ouverture ».
- **`themeForDay(jour, version = generatorVersionOf(jour))`** (themes.ts) : version < 20 → l'**ancienne règle** (`themeAncien`, un tirage indépendant par date, qui pouvait répéter la veille ; ne change jamais : c'est le thème de tout jour déjà servi) ; sinon le sac. **Un jour est « ancien » quand le registre (`jours-track.json`, `generatorVersionOf`) lui donne une version d'avant le sac** : le **premier jour du sac** (celui dont la veille est ancienne) lit donc le thème de la veille dans le registre et évite le thème de la veille et de l'avant-veille ; le suivant évite celui de l'avant-veille (`resolu`, `sacThemes.ts` : seuls ces deux jours-là, au plus, sont remplacés par un autre thème tiré de la date). Aucune date écrite : la bascule se lit dans le registre que « Mettre en production » écrit.
- **Un test ou une mesure d'une ancienne version impose sa version** (`dailyCircuit(jour, 0, null, 18)`, `themeForDay(jour, 18)`, `themeOccurrence(jour, thème, 18)`) : sans cela le thème du jour serait celui du sac. `themeOccurrence` (rotation des vedettes, lot 49) compte les apparitions avec l'ancienne règle pour une version d'avant le sac, avec le thème réellement servi (`themeForDay(d)`) pour la v20.
- **Budget de tentatives** : `MAX_ATTEMPTS_SAC` = **120** pour la v20 (40 pour les versions d'avant : un jour de secours ou une tentative retenue d'une ancienne version ne bouge pas). Mesuré sur 365 jours : un seul jour (Banquise, 02/12/2026) épuisait 40 tentatives ; il aboutit à la 51ᵉ.
- **Un nouveau thème s'ajoute au sac ; la règle ne change pas** : `THEME_NAMES` + `THEMES` (voir « Thèmes (lot 8) ») changent n, donc les cycles de tous les jours **qui suivent le sac** : monter `GENERATOR_VERSION` (comme tout changement de thème). Au moins cinq thèmes (`ordreDuCycle` lève sinon).
- **Mesure** : `npm run mesure:themes` (`scripts/mesure-themes.ts` ; `-- --niveaux` : la validité des 365 niveaux des deux jeux). Tests : `packages/core/test/sacThemes.test.ts` (la règle, n = 5 et 8), `registreJours.test.ts` (rotation des vedettes en v20), `golden-daily.test.ts` (un vecteur par thème de la dernière version).
