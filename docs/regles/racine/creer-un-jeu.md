## Créer un jeu (lot K4g) — `npm run nouveau-jeu`, en 5 étapes
Le kit est terminé : un jeu neuf s'obtient en une commande, sans retouche à la main (`docs/plateforme/kit-de-jeu.md`, « Le kit est terminé » ; rapport : `docs/plateforme/lots/lot-K4g-generateur-et-bout-en-bout.md`).
1. **Nathan écrit le seed**, dans la conversation de la plateforme : le jeu, les piliers, une partie, le classement (score ou temps). Le gabarit vide est `docs/<id>/seed.md` après l'étape 2.
2. **Un lot court de la plateforme** lance `npm run nouveau-jeu -- --id <id> [--nom "<Nom>"] --classement score|temps` (`--a-blanc` : liste ce qu'il créerait, sans rien écrire) et **verse le seed dans `docs/<id>/seed.md`**. Il copie « Cibles », renomme, écrit la fiche (`off`, `temoin: false`, teinte d'étiquette libre **à choisir par Nathan**), les lignes mécaniques des fichiers partagés (Dockerfile, tsconfig, verrou, catalogues, ligne de `budgets.md`), `docs/<id>/{seed,consignes,passation}.md`, puis lance `npm run fiches`, le golden du jeu et `npm run traductions`. **L'`id` : minuscules et chiffres, sans tiret** (c'est aussi un nom dans le code).
3. **Nathan ouvre la conversation du jeu** avec `docs/<id>/passation.md` (générée depuis les `CLAUDE.md` : l'état de la plateforme, les règles, la charte, les zones du jeu, la méthode ; `npm run nouveau-jeu -- --id <id> --passation` la remet à jour) et le seed.
4. **Les lots du jeu**, dans ses zones seulement : simulation, rendu, sensations ; **maquettes d'abord** pour l'étiquette et le HUD. Le jeu de départ est un squelette à remplacer ; `packages/<id>-sim/src/variante.ts` range tout ce qui dépend du sens du classement.
5. **Nathan publie** depuis `/admin/` › Jeux : `off` → `preview` → `on` (mentions légales décrites avant `on`). La liste des jeux du classement cumulé reste un réglage à part.
- **« Cibles » est le modèle du générateur** : toute amélioration du modèle passe par lui (`docs/cibles/consignes.md`), jamais par le script. **Le job « Kit de bout en bout »** (`scripts/kit-bout-en-bout.mjs`, `ci.yml`) génère `essai` (score) et `essaitemps` (temps) dans une copie du dépôt à chaque changement du kit, du module serveur, de `core`, des fiches, de « Cibles » ou du générateur, et chaque nuit : typage, fiches, unitaires (SQLite et libSQL), construction, budgets, e2e Chromium, **aucun fichier hors des zones du jeu**. **Aucun jeu généré n'est versé au dépôt** ; un lot qui change le générateur ou le modèle voit ce job rouge s'il casse l'un des deux.
