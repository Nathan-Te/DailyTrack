> Déplacé **mot pour mot** de `docs/tower/consignes.md` (lot T1, économie de jetons) : rien n'est réécrit, les règles sont en vigueur. Le renvoi est dans [`apps/tower/CLAUDE.md`](../../../apps/tower/CLAUDE.md).

## Les jours figés (lot T2, `jours.ts`, `tools/figer.ts`)
- **Un fichier par jour** (comme Jump) : `apps/tower/public/jours/AAAA-MM-JJ.json` = `{ format: 1, jeu: "tower", date, g, tirage, sim, contenu: { pieces, plateformeDemi8, paliers, ventSens, theme }, medailles, preuve? }` — le contenu du jour tel qu'il a été servi, avec les versions qui l'ont produit ; `medailles` est `null` pour un jour seulement figé (`figer:tower`), et **`{ auteur, or, argent, bronze }` en millimètres, avec la `preuve` de l'auteur (la rediffusion du bot), pour un jour préparé** (`preparer:tower`, lot T3 : voir « Le bot de l'auteur »). **Lot T3b : dès `g = 3` le fichier nomme son `tirage`** (0 à `TIRAGES_MAX` − 1, le tirage que la préparation a retenu ; les fichiers `g = 1` et `2` n'ont pas ce champ, leur texte ne change pas) : le jeu lit le contenu **à ce tirage** (`lireJour`), et sans fichier il prend le tirage 0.
- **`npm run figer:tower -w @cdj/tower-sim -- --du AAAA-MM-JJ --au AAAA-MM-JJ`** écrit ces fichiers (`--dossier=` pour essayer ailleurs). Il ne lance aucun workflow et ne lit aucune base ; **un fichier déjà écrit n'est jamais réécrit** (un jour figé ne change plus) ; un fichier qui ne se relit plus, ou qui n'est plus ce que sa version `g` génère, est signalé et l'outil s'arrête en erreur.
- **Le jeu** lit le jour figé s'il existe (`jour.ts` : seulement pour une date de la liste écrite à la construction, d'après `public/jours/`), sinon génère avec la version courante. Un fichier qui ne se relit pas (`lireJourFige` : format, jeu, date, versions, forme de chaque champ) est ignoré. Lot T6 : un jour figé sous la simulation 3 ou 4 est lu (sa preuve se rejoue par la version du fichier, qui doit être celle de la preuve) ; une autre version est refusée. **Les jours déjà préparés de `apps/tower/public/jours/` (versés par une mise en production, en simulation 3) ne sont pas touchés par le lot** : ceux sans résultat seront re-préparés à la prochaine mise en production, parce que leur version diffère.
- **Garde-fou** (`test/jours.test.ts`) : chaque fichier figé présent se relit et se régénère à l'identique avec sa version `g` (empreinte, puis texte canonique) ; lot T3 : **et sa preuve, rejouée, donne exactement le Diamant écrit** (`verifierJourPrepare`) — dans `apps/tower/public/jours/` et `test/fixtures/jours/`. **Aucun jour n'est figé au lot T2** : ce sont des jours servis, c'est la mise en production qui les fige.
- **Lot R16 — un jour servi ne change jamais, même sans fichier préparé.** Tower fige ses jours comme Jump : **un fichier par jour servi, sans exception**. Sans fichier, un jour prend `dailyTower(jour, TOWER_GENERATOR_VERSION)` : il changerait à la prochaine version du générateur. « Mettre en production » (job `figer`) fige donc, **avec le code alors en production** (`figer:tower` dans son dépôt), tout jour **protégé** (d'avant le lancement, déjà figé ou avec un résultat) qui n'a pas de fichier, le pose dans la construction, le serveur, le site et le dépôt, et **s'arrête s'il en manque un** ; la comparaison des empreintes couvre Tower (`jours-passes.json`, clé `tower`). **Changer le générateur = monter `TOWER_GENERATOR_VERSION` et garder l'ancienne version dans `GENERATEURS`** tant qu'un fichier la nomme (test : `apps/api/test/towerJoursFiges.test.ts`, générateur factice). Un lot de jeu n'écrit jamais ces fichiers. **Réserve** : les médailles d'un jour figé sans préparation sont l'estimation géométrique du code (`COEFFICIENT_GEOMETRIQUE_PCT`), pas figées avec le fichier ; en changer arrête la mise en production (le garde-fou voit la différence).
- **Le branchement à « Mettre en production » est un lot de la plateforme (T4)** : quels jours figer, avec le code alors en production, le registre des versions à la manière de `jours-track.json` (règle R11), la copie dans l'image du serveur ; rien n'est publié en production (Tower est `off`).
