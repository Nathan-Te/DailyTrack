## iPhone : le plein écran par l'écran d'accueil (lot 53)
README : `docs/lots/lot-53-iphone-plein-ecran.md`. **Rendu, simulation et commandes (lot 52) inchangés.**
- **Pourquoi** : sur iPhone (Safari, Chrome : le même WebKit) une page ne passe pas en plein écran (l'API Fullscreen n'est ouverte qu'aux vidéos) ; `pleinEcranPossible()` est faux, le bouton était retiré **volontairement**. Le seul vrai plein écran est l'ajout du site à l'écran d'accueil (`display: standalone` du manifeste, iOS traite `fullscreen` comme `standalone`). **La détection est celle de la fonction** (`pleinEcranParEcranAccueil`, `@cdj/ui` : pas d'API Fullscreen **et** écran tactile, hors mode application), jamais le nom de l'appareil.
- **Le bouton « Plein écran » reste là** (barre de l'accueil, pause, plaque de la course : `pleinEcranBoutonVisible`) et **ouvre une aide** (`aidePleinEcran`, `aideIphone.ts` de `@cdj/ui`, **chargée à la demande**) : « Pour jouer en plein écran : touche [icône Partager] puis « Sur l'écran d'accueil ». Ton profil se retrouve avec ton code de transfert. », « Copier mon code » (s'il y a un profil) et un lien vers le code (`profilHref`). Ce n'est pas un interrupteur (pas d'`aria-pressed`, `aria-haspopup="dialog"`). **En course l'aide met la partie en pause avant de s'ouvrir** (`avantAide: () => setPaused(true)`). `main.ts` dit à l'aide où est le profil : `reglerAideIphone({ lienCode, code })`, le code se calcule à la demande (`retrouverJeu.ts`). La rangée de boutons du haut compte ce bouton sur iPhone (`syncCameraButton`).
- **Mode application** (`modeApplication()` : `display-mode: standalone` ou `navigator.standalone`) : aucun bouton plein écran, aucune pastille, **le stockage est celui de l'application, séparé de Safari** : au premier lancement sans profil, **« Retrouver mon profil »** (`retrouverJeu.ts`, `import()` seulement en mode application ; `retrouverMonProfil` de `@cdj/ui/src/retrouver`, `verifierRetrouver` de `@cdj/profile` : le profil est lu sur le serveur (`GET /api/portail/profil`, l'identifiant en `X-Player-Id`), **montré** — pseudo et jours finis — puis adopté après confirmation ; la page recharge) ; « Commencer sans profil » ne revient pas (`cdj:retrouver:vu`). **Rien dans une adresse ne transmet le profil** (lot 32 : l'identifiant ne passe jamais dans une adresse) : le seul chemin est le code `CDJ2` copié dans Safari (profil du portail, ou « Copier mon code » de l'aide) et collé dans l'application (`navigator.clipboard.readText`, qu'iOS propose au geste du joueur, ou le champ).
- **Marges de sécurité obligatoires** (`hud.css` : `--sure-haut`, `--sure-droite`, `--sure-bas`, `--sure-gauche`, lues de `env(safe-area-inset-*)`) : tout élément posé contre un bord est à `max(<sa marge>, var(--sure-…))` — pause, boutons du haut, bande, objectif et rang, aide, bandeaux, vitesse, effets, classement, finale du Salon ; les écrans posés sur la scène ont le padding du cadre (`@cdj/ui`), les commandes tactiles la sonde de `touchUi.ts`. **Un nouvel élément contre un bord les respecte** et passe par `e2e/iphone.spec.ts` (portrait 390 × 844 et paysage 844 × 390, marges d'un iPhone 13 : aucun bouton dans les marges). L'invitation « tourne ton téléphone » (`#rotate`) marche en mode application comme dans Safari (iOS ne verrouille pas le paysage).
- Budget : `retrouverJeu.ts`, l'aide et l'écran « Retrouver mon profil » sont **à la demande** ; le premier chargement n'ajoute que la détection et le bouton (voir `docs/plateforme/budgets.md`).
- Tests : `e2e/iphone.spec.ts` (profil `devices["iPhone 13"]` et `"iPhone 13 landscape"` ; WebKit dans le petit ensemble `@navigateurs`) ; `packages/ui/test/pleinEcran.test.ts`, `packages/profile/test/retrouver.test.ts`.
