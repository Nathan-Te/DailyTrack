## Profil commun (lot P0 de la plateforme)
- L'identité, le code `CDJ2`, le client du profil (`/api/me`, `/api/name`, `/api/player`, `/api/me/code`), le service de synchronisation, le pseudo et « Changer mon code » sont dans **`@cdj/profile`** (`packages/profile/CLAUDE.md`). `identity.ts`, `transfer.ts` (garde les anciens codes `CDJ1` et le cache des records), `api.ts` (`LeaderboardApi` hérite de `ProfileClient`), `profileSync.ts` (garde la fusion des records `mergeProfile`) et `online.ts` (délègue `rename` / `changeCode`) en sont des **façades** : mêmes noms, même comportement. Un changement d'identité se fait dans le module, pour tous les jeux.

- **L'identifiant du joueur ne va jamais dans une adresse ; toujours `X-Player-Id` (lot 32).** Ni `?player=`, ni dans une ancre, ni dans une clé de cache, ni dans le corps d'un envoi : une adresse finit dans les journaux de requêtes de l'hébergeur (Cloud Run : 30 jours). Une seule définition, `asPlayer(playerId)` (`api.ts`), passée comme en-tête de `call` (`@cdj/profile`) par `LeaderboardApi` (classement, fantômes, envoi) et `HttpSalonApi` (`now`, `board`, `submit`) ; `ProfileClient` (`/api/me`, `/api/name`, `/api/me/code`) l'utilisait déjà. **Un nouvel appel qui désigne le joueur reprend `asPlayer`.** Hors de la même origine (`?api=http://…`, essais) l'en-tête déclenche un pré-vol CORS (le serveur autorise déjà `X-Player-Id`, réponse gardée 24 h) ; en production (`VITE_API_URL=/`) il n'y en a pas. Tests : `test/api.test.ts`, `test/salon.test.ts`, `test/watch.test.ts` (adresses et en-têtes des clients), e2e `adresses-joueur.spec.ts` (relève **toutes** les adresses d'une course du jour, de l'ouverture du Salon et de « revoir le meilleur tour » ; échoue si l'identifiant ou `player=` apparaît dans l'une ; serveur 8799 lancé dans le spec, réservé). Détail : `docs/lots/lot-32-en-tete-joueur.md`.

- **Révision d'identité de la plateforme (lot P4)** : **DailyTrack lit au démarrage** le compteur de révision d'identité de `@cdj/profile` (`followIdentityRevision`, `transfer.ts`, appelé en tête de `main.ts`, avant toute lecture des records) : un code chargé **dans un autre jeu** (DailyJump) depuis sa dernière visite → `applyIdentity` avec l'identité du navigateur (cache des records, places et temps confirmés de l'ancienne identité vidés ; le record du jour non confirmé reste) ; sinon **rien ne change** (première visite, rotation, création). Un code chargé ici l'avance (`noteCodeLoaded`, `profileUi.ts`) et le note comme vu. Clé vue : `cdj:identite:vue`. Tests : `test/revisionIdentite.test.ts`, e2e `identite-plateforme.spec.ts` (les deux jeux servis par la même origine, `e2e/deux-jeux.mjs`, port 4175 ; serveur 8792 réservé). README : `docs/plateforme/lots/lot-P4-consolidation.md`.
