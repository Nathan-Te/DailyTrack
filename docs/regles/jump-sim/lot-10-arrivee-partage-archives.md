## Lot 10 — arrivée, partage, archives
- **Règle, une fois le jeu lancé : figer avant de changer de version.** **Depuis le lot R6, c'est « Mettre en production » qui fige** (`freeze:days` jusqu'à la veille du jour de bascule, avec le code en production, `docs/plateforme/mise-en-production.md`) : un lot n'a plus à le faire, et le garde-fou arrête la mise en production si un jour protégé changeait. **Lot R11 (décision de Nathan) : seuls les jours d'avant le lancement, déjà figés ou avec au moins un résultat en production sont figés** ; un jour sans aucun résultat n'est pas figé, la mise en production le régénère avec le code déployé (`jours-figes-filtrer`), comme pour Track. (Avant le lot R6, tout lot qui changeait `JUMP_SIM_VERSION` ou `JUMP_GENERATOR_VERSION` lançait `freeze:days -- demain` et commitait `public/levels/` ; un fichier figé par un lot avec un code autre que celui en production **arrête la mise en production** — « jour(s) figé(s) différent(s) » : le retirer du lot.) Les jours joués ou en cours ne changent jamais. Un niveau figé sous une autre `JUMP_SIM_VERSION` ne se rejoue plus (refusé) : la règle pour ses archives est une décision de Nathan (`docs/jump/lots/lot-10-arrivee.md`). Lot 15 : le code joue la v3 **et** la v4 (version inscrite dans le niveau) : les jours figés en v3 se rejouent tels quels ; le gel avant le lot 15 s'est fait en v3 (jusqu'au 22/10/2026).
