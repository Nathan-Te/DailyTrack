## Sac de thèmes : jamais deux jours de suite le même thème (lot V1)
README : `docs/plateforme/lots/lot-V1-themes-sans-repetition.md`. **`JUMP_GENERATOR_VERSION` 23** (`JUMP_GENERATOR_SAC`, themes.ts) ; **`JUMP_SIM_VERSION` reste 12** (aucune physique, aucun morceau : un niveau g22 se rejoue tel quel) ; golden v3 à v11 identiques au bit, nouvelles références `daily-golden-v12.json` / `replay-golden-v12.json` (g23).
- **La règle est celle de DailyTrack, écrite une fois** (`@cdj/core`, `packages/core/src/sacThemes.ts` : cycles de n = **5** jours alignés sur le numéro de jour, chaque thème une fois par cycle dans un ordre tiré de la graine, jonction de cycles sans répétition ni A B A, 2n − 1 jours au plus entre deux apparitions). `jumpThemeForDay(jour)` = le sac ; **`jumpThemeAncien(jour)`** = l'ancienne règle (jour pair libre, jour impair entre ses voisins : jamais deux de suite mais A B A possible ; `fixtures/themes-lot9.json`), qui reste celle de **tout niveau figé d'un générateur d'avant g23** (`jumpThemeOfGenerator(jour, generatorVersion)`, lu par `thawLevel` dans le fichier) et des références d'avant la version 12 de la simulation (`jumpThemeOfSim(jour, simVersion)`, utilisé par `dailyLevel`, `dailyLevelId`, `fallbackLevel`).
- **Le générateur lit le thème de la veille figée.** Un jour est « ancien » quand un fichier figé de `apps/jump/public/levels/` le nomme avec `generatorVersion` < 23. La simulation est pure : **chaque lieu qui calcule un thème déclare ces jours au démarrage** — `declareOldFrozenDays(dates)` / `declareFrozenGenerators({ date: generatorVersion })` (themes.ts, la déclaration remplace la précédente) : le jeu (`apps/jump/src/frozen.ts`, liste écrite à la construction par `vite.config.ts`, `__JUMP_FROZEN_OLD_DAYS__` : seulement les jours d'avant le sac, la liste ne grossit plus), le serveur (`apps/api/src/jump.ts`, `createJump`), la mesure (`scripts/mesure-themes.ts`). Le **premier jour du sac** (dont la veille est ancienne) évite le thème de la veille et de l'avant-veille ; le suivant celui de l'avant-veille ; seuls ces deux jours, au plus, sont remplacés par un autre thème tiré de la date. **Un lieu qui oublie la déclaration** voit le sac sans mémoire des jours figés : un test de bout en bout (`test/sacThemes.test.ts`) relit chaque fichier du dépôt.
- **Un nouveau thème s'ajoute au sac ; la règle ne change pas** : `JUMP_THEME_NAMES` change n (au moins 5), donc les cycles des jours qui suivent le sac : `JUMP_GENERATOR_VERSION` +1.
- **Tests à dates fixes** : un test qui génère avec une version d'avant (`dailyLevel(jour, null, 9)`) choisit ses jours par `jumpThemeOfSim(jour, 9)`, jamais par `jumpThemeForDay`. Tests : `test/sacThemes.test.ts` (365 jours, cycles, jonction avec un jour figé à chaque position, écart maximal, niveaux figés du dépôt), `test/themes.test.ts` (l'ancienne règle = le lot 9). Mesure : `npm run mesure:themes` (`-- --niveaux` : 365 niveaux, jamais le secours, aucune règle de `dailyProblems` enfreinte).
