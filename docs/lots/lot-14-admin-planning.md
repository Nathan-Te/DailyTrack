## Livré
- **Variantes** (`packages/sim`) : `dailyCircuit(jour, variante = 0, thème?)`. **La variante 0 est exactement le circuit d'avant** : même texte, même identifiant (`jour-AAAA-MM-JJ-g5`, sans suffixe) → golden, rediffusions de référence, jeu de données de démo, records locaux et versions (`SIM_VERSION`/`GENERATOR_VERSION` = 5) **inchangés**. Une variante n ≥ 1 change la graine (décalage de n × 1000 tentatives : jamais de recoupement) et ajoute `-v<n>` à l'identifiant ; un thème imposé ajoute son nom : `jour-AAAA-MM-JJ-g5-v2-nuit` (31 caractères au plus, la limite est 32). `dailyTrackId(jour, thème, variante)`, `isVariant`, `MAX_VARIANT` = 99. Chaque variante est validée par le pilote dans la fenêtre 30–40 s comme n'importe quel circuit.
  *Écart avec le seed* : le seed écrit `-v<n>` pour toute variante ; la variante 0 n'a pas de suffixe, sinon tous les identifiants (donc toutes les rediffusions de référence et les archives) auraient changé.
- **Planning côté API** (`apps/api`) : table `planning` (jour → variante, thème imposé ou `NULL`, date du choix). `getCircuit(jour)` lit le planning et **rejoue toujours le circuit en vigueur** : une ligne du cache ou une mémoire d'une autre variante (ou d'une autre version du générateur) est ignorée et régénérée. Routes publiques : `GET /api/day/AAAA-MM-JJ` (renvoie aussi `variant`, `theme`, `trackId`) et `GET /api/planning` (jours remplacés **jusqu'à aujourd'hui**, pour les miniatures des archives ; l'avenir n'est pas révélé).
- **Accès admin** : `ADMIN_TOKEN` (variable d'environnement ; secret Wrangler sur Workers ; **jamais dans le dépôt**), **au moins 16 caractères** sinon l'admin est désactivé (les routes répondent 404). En-tête `Authorization: Bearer <jeton>`, comparaison **à temps constant** (empreintes SHA-256 comparées octet par octet). **Limite de débit** : 10 mauvais jetons par fenêtre de 10 min et par adresse (hachée), puis 429 avec `Retry-After` — même le bon jeton est refusé jusqu'à la fenêtre suivante. Routes : `GET /api/admin/overview` (planning, aujourd'hui + 14 jours passés avec joueurs et meilleur temps, temps du jour), `PUT /api/admin/planning/AAAA-MM-JJ` (`{ variant, theme }`), `DELETE /api/admin/planning/AAAA-MM-JJ` (retour à l'original).
- **« Un jour commencé est figé »** : `PUT` / `DELETE` sur aujourd'hui ou le passé → 409 `day_started` (UTC ; la grâce de 10 min après minuit ne change rien : hier est déjà passé). Au plus 60 jours à l'avance. Le circuit est **généré et validé à l'enregistrement** : une variante qui ne se finit pas est refusée (503) au lieu de laisser un jour sans circuit.
- **Jeu** (`apps/web`) : au lancement il demande la variante du jour (`GET /api/day/…`, **2,5 s** au plus) et vérifie que l'identifiant du serveur est bien celui qu'il calcule. **Sans API, ou en cas d'échec, ou si l'identifiant diffère** : circuit d'origine (variante 0), course jouable, **« hors ligne, non classé »** dans l'en-tête, pas de classement. `?variant=N` (et `&theme=`) : une variante pour l'essayer, jamais classée. En `?api=demo`, le planning vient du navigateur (`cdj:demo-plan`). Les miniatures des archives tiennent compte des jours remplacés (le planning public est demandé à l'ouverture des archives). `__cdj.trackId` et `__cdj.plan` (tests).
- **Panneau `/admin/` refait**, en français, utilisable sur téléphone : **Aujourd'hui** (miniature, thème, médailles, joueurs, meilleur temps, histogramme), **Planning** (14 cartes : miniature, thème, temps de l'auteur, largeurs, revêtements, blocs à effet, virages serrés ; Jouer, Regarder le pilote, Remplacer), **Remplacer** (5 variantes générées dans le navigateur avec le même code que le serveur, thème modifiable, « Autres variantes », **Choisir** puis **Confirmer**, **Revenir à l'original**), **Historique** (14 jours passés en lecture seule : joueurs, meilleur temps, variante utilisée), **Outils** (l'ancien constructeur d'adresses, avec en plus l'option `variant`). Le jeton se saisit une fois (gardé dans ce navigateur, `cdj:admin-token`, jamais effacé avec les données du jeu). Génération et miniatures passent par le fil de travail et le service du lot 13.
- **Mode démo** `/admin/?api=demo` : sans serveur, « aujourd'hui » = celui de la démo, bandeau explicite, remplacements gardés dans ce navigateur seulement.

## ADMIN_TOKEN pour l'API locale
```
npm run build:node -w @cdj/api
ADMIN_TOKEN=un-jeton-de-16-caracteres-ou-plus DB_PATH=:memory: npm start -w @cdj/api     # http://localhost:8787
```
puis ouvrir `/admin/?api=http://localhost:8787` (en `npm run dev`, `http://localhost:5173/admin/?api=http://localhost:8787`), saisir le jeton. Génère un vrai jeton avec `openssl rand -hex 24`. Sur Workers : `wrangler secret put ADMIN_TOKEN`.

## Décisions pour Nathan
- **14 jours de planning** affichés, 5 variantes par page (autant de pages que tu veux jusqu'à 99).
- **Si l'API tombe le jour même** : le jeu retombe sur le circuit d'origine, **non classé**. Si le jour avait été remplacé, les joueurs hors ligne jouent donc un autre circuit que le classement : c'est voulu (mieux qu'un temps qui ne s'accorde pas avec le serveur). L'alternative serait de garder la dernière variante connue en cache local.
- **Générer à l'enregistrement** coûte ≈ 0,2 à 1 s de calcul côté serveur (l'offre gratuite de Workers n'y suffit pas, comme pour le rejeu : voir lot 5).
