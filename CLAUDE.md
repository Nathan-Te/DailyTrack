# Circuit du Jour

Jeu web quotidien : un circuit court par jour, identique pour tous, classement validé par rediffusion. Source de vérité : `docs/seed.md` (ne pas modifier, c'est Nathan qui le fait). Réponses et docs en français.

## Structure
- `packages/sim` — simulation pure (physique, blocs, chrono, générateur, bot). **Aucune dépendance** au DOM, à Three.js ou à Node.
- `apps/web` — le jeu (Vite + Three.js) ; affiche ce que calcule `sim`.
- `apps/api` — classement (lot 5) ; importe le même `sim` pour rejouer les courses.
- `docs/lots/` — un README d'une page par lot.
- `docs/orchestration.md` — synthèse des lots, règles à ne pas casser, méthode et suite (pour l'agent orchestrateur).

## Commandes
- `npm install` · `npm run dev` · `npm test` (Vitest) · `npm run typecheck` · `npm run build` · `npm run measure:generator` (durées, validation par thème, vitesse du pilote, coût d'un rejeu)

## Circuits (lot 2)
- Un circuit = un texte de blocs (`parseTrack`, voir `packages/sim/src/track.ts`) : cellules de 32 m, repère canonique (p = gauche, q = avance) tourné par quarts de tour ; hauteurs enchaînées automatiquement.
- `trackWorld(track)` donne `sample` (hauteur/pente/plaque) et `collide` (rebords) à `stepCar` ; `createRace`/`stepRace` ajoutent portes, chrono et reprises. Les commandes enregistrables sont `{ steer, throttle, brake, respawn }`.
- Tests navigateur : `?debug` expose `window.__cdj`. Scénarios : `?scenario=essai|pilotage|surfaces|largeurs|vitesse|glace|relief|cuves|plat`.
- **Cuves (lot 18)** : `V` cuve droite, `ML` / `MR` mur latéral, `/c` sur un virage (`L2/c` : son mur extérieur) ; voir « Cuves (lot 18) ». **Les boucles restent exclues** (comme les tunnels fermés et les murs au plafond).

## Rediffusions (lot 3)
- Une rediffusion = `Replay` (séries de commandes) ; `encodeReplay`/`decodeReplay` ↔ texte base64url ; `replayRace` rejoue et renvoie le résultat recalculé. **Ne jamais faire confiance à un temps annoncé.**
- **`SIM_VERSION`** (constants.ts) : à incrémenter dès que la physique, un bloc ou un circuit change le résultat d'une course ; puis régénérer la rediffusion de référence : `UPDATE_GOLDEN=1 npx vitest run packages/sim/test/golden.test.ts`.
- `apps/web/src/session.ts` : `RunSession` avance course + enregistrement + fantôme ; `verify.html` : rejeu sans rendu pour les tests de navigateur (`npm run test:e2e`, Playwright ; `CHROMIUM_PATH` pour un Chromium déjà installé, `E2E_ALL_BROWSERS=1` pour Firefox et WebKit).

## Circuit du jour (lot 4)
- `dailyCircuit(jour)` (`generator.ts`) : graine = jour UTC (`parseDay`/`formatDay`, calendrier sans `Date`) ; `composeSpec` construit le texte, `bestPilotRun` (`autopilot.ts`) valide et donne le temps de l'auteur, d'où `medalsFor`. Id du circuit : `jour-AAAA-MM-JJ-g<GENERATOR_VERSION>` (variante 0) ; voir « Admin et planning ».
- **`GENERATOR_VERSION`** (constants.ts) : à incrémenter dès que le circuit d'une date change (règles, pilote, fenêtre de durée) ; puis régénérer `fixtures/daily-golden.json` (`UPDATE_GOLDEN=1 npx vitest run packages/sim/test/golden-daily.test.ts`).
- Web : `?seed=AAAA-MM-JJ` (ou `?day=`), `?theme=<nom>`, `?api=demo`, `?scenario=essai|pilotage|surfaces|largeurs|plat`, `?debug&tune` (réglages), touche **C** (caméra). Palettes dans `apps/web/src/trackMesh.ts` (`PALETTE_DEFS`).
- **`npm run measure:generator`** (`apps/api/scripts/measure-generator.ts`) : durées d'auteur, largeurs, virages serrés, temps de génération et de rejeu sur 60 dates, taux de validation par thème (12 dates × 6 tentatives, thème forcé). **Toute règle de générateur se valide par ce script (durées, taux de validation par thème), pas seulement par les tests.** `FAST=1` pour un passage rapide ; résultats de référence dans `docs/lots/lot-12-circuits-amples.md`.

## Classement (lot 5)
- `apps/api` : `createApi({ db, now })` (`src/api.ts`) ne dépend que de `Request`/`Response` et de `SqlDb` ; adaptateurs : Node + SQLite (`server.ts`, Docker) et Cloudflare Workers + D1 (`worker.ts`). **Le serveur ne fait jamais confiance à un temps annoncé** : il rejoue la rediffusion (`replayRace`) et enregistre son propre résultat.
- Le client est dans `apps/web/src/{api,identity,online}.ts` ; adresse de l'API : `?api=` ou `VITE_API_URL`. Sans elle, aucun classement.
- Tests : `apps/api/test` (SQLite en mémoire, horloge injectée) ; e2e `leaderboard.spec.ts` (Playwright lance le vrai serveur : `npm run test:e2e` construit aussi `apps/api`). Outils `?debug` : `timescale=N`, `__cdj.autoplay(code)`.
- Le Worker ne tient pas dans les 10 ms de calcul de l'offre gratuite de Cloudflare (voir docs/lots/lot-5-classement.md).

## Arrivée, partage, archives, mobile (lot 6)

- Mise en page : un seul `index.html` avec media queries (`max-width: 900px` / `max-height: 520px`). Test `e2e/mobile.spec.ts` : aucun chevauchement sur 3 formats de téléphone. Poids : budget dans `e2e/perf.spec.ts` ; Three.js reste dans son propre chunk (`vite.config.ts`).
- Outil de test : `?debug&today=AAAA-MM-JJ`.

## Conduite (lot 7)
- `packages/sim/src/car.ts` : modèle **bicyclette** (deux essieux, force latérale saturée par `tireCurve`) + **4 ressorts** posés sur `world` (hauteur, tangage, roulis en pentes ; charge → adhérence ; butée) + **balistique** en l'air (voir « Air » ci-dessous). 2 sous-pas fixes par pas. Rebords : deux disques, impulsion avec rebond et frottement. Dérapage au frein (`car.drift`). Détail et mesures : `docs/lots/lot-7-conduite.md`.
- **`CarParams`** (`DEFAULT_CAR_PARAMS`) passé à `stepCar(car, input, world, params)` et `createRace(track, params)` ; le serveur et les rediffusions utilisent toujours les défauts. **`SurfaceParams`** `{ grip, traction, rolling }` lu sous chaque roue par `surfaceAt(échantillon)` (`world.ts`, table `SURFACES`, « route » seulement).
- Reprise = état de la voiture au passage du dernier point de contrôle (`race.checkpoints`). Virage large `L2`/`R2` (2 × 2 cellules, `blockCells`).
- Pilote (`autopilot.ts`) : trajectoire lissée (`racingLine`), vitesses par courbure, freinage anticipé ; `PILOT_GRIPS`.
- **Contact par la normale (lot 18)** : dans un bloc de cuve la voiture quitte le modèle à ressorts : `stepCar` appelle `world.shell(x, z, y, hit)` et, s'il répond, `substepShell` (car.ts) — voir « Cuves (lot 18) ».
- Web : panneau `?debug&tune` (`apps/web/src/tune.ts`) — une course avec réglages modifiés n'est **jamais** enregistrée ni classée ; caméras proche/loin (touche **C**, bouton Vue de la manette) ; `?scenario=pilotage`.
- **Réglages par défaut = ceux de Nathan (retouche 7b, `docs/lots/lot-7b-reglages.md`)** : pointe 48 m/s, grip 44 / 47, seuil de glisse 0,14, dérapage doux (angle 0,32, serrage 33), gravité 24,6, rebords durs (rebond 0,6, frottement 0,3). `SIM_VERSION` et `GENERATOR_VERSION` valaient 3 au 7b ; le lot 8 les passe à 4, le lot 12 à 5, le lot 15 à **6**.
- Générateur : **deux lignes droites derrière chaque plaque** (`PAD_RUNOUT`, generator.ts) — à 48 m/s, une plaque suivie d'un virage serré ne se prend pas (frein 40 contre poussée 30 pendant 0,9 s). Le circuit d'essai suit la même règle. Pilote : marge aux rebords de 3,6 m (`WALL_MARGIN`).
- **Vitesse au-delà de la pointe (lot 15)** : la pointe du plat reste **48 m/s** mais n'est **plus un plafond dur** : au-delà, **traînée en cube** `overspeedDrag × ((u ÷ pointe)³ − 1)` (2,5 ; remplace l'ancienne décélération constante de 14 m/s²), appliquée aussi sous plaque et turbo. La gravité (`slopeGravity` **40**, pente 0,125 par bloc de descente) et les poussées vont plus haut : **plaque 66 m/s** (`boostMaxSpeed`), **super turbo 88 m/s** (`turboMaxSpeed`, ≈ 317 km/h) ; la voiture retombe progressivement (88 → 61 m/s en 5 s). Un virage reste limité par l'adhérence (R3 ≈ 60 m/s, L2 ≈ 43, serré ≈ 26). **Garde-fou anti-traversée** : aucun changement de pas (0,375 m par sous-pas à 88 m/s pour un disque de 1 m) ; `vitesse.test.ts` fait heurter des rebords à 88 m/s (angles de 5° à 60°, de face dans un virage, braquage à fond, transition de largeur) et exige que la voiture reste sur la route à chaque pas. **Toute nouvelle poussée ou nouveau relief qui augmente la vitesse maximale doit rejoindre ce test.** Panneau `?debug&tune` : `overspeedDrag`, `boostMaxSpeed`, `turboMaxSpeed`, `slopeGravity`.
- **Chute et reprise automatique (lot 17)** : sous `track.voidY` la voiture tombe sans commande `FALL_TICKS` pas (0,5 s) puis reprend au dernier point de contrôle, chrono qui continue (voir « Relief, sauts et chute »).
- **Cuves rapides (retouche 18b, `docs/lots/lot-18b-cuves-rapides.md`)** : sur une paroi (`substepShell`), la pesanteur n'est pas symétrique — la montée coûte `shellClimb` (0,4) de la pesanteur tant qu'elle n'est pas franche, la descente pousse `shellDescent` (2,6) fois, avec un surplus éteint vers `shellGainTop` (56 m/s) — et la paroi est une **voie rapide** (pointe `shellTop` 1,15 × 48 m/s, poussée `shellPush` 14 m/s² sous cette pointe). **Garde-fou anti-zigzag** : au-delà de `shellGainTop` de vitesse totale une traînée (3 /s) ramène la voiture, et la descente n'ajoute plus rien (un zigzag dans 14 blocs de cuve reste sous 62 m/s à plat, test `cuves-rapides.test.ts`). Les cinq clés sont dans `CarParams` et `?debug&tune`. Pilote : il « pompe » les cuves droites (`STRAIGHT_UP` / `STRAIGHT_DOWN`, bouts libres) et prend la paroi des virages en cuve ; la relaxation longue de la trajectoire ne vaut qu'à `CUVE_NEAR` blocs d'une cuve. Générateur : cuve droite de 6 blocs + 4 droites (`CUVE_RUN`, `CUVE_RUNOUT`), virage en cuve large ou ample (plus de serré). `SIM_VERSION` et `GENERATOR_VERSION` : **10**.
- Tests de comportement chiffrés : `packages/sim/test/conduite.test.ts` (seuils recopiés dans le README du lot, mis à jour au 7b), `vitesse.test.ts` (lot 15, seuils dans `docs/lots/lot-15-vitesse.md`).

## Air et atterrissages (lot 19)
- **Réception** (`land`, `car.ts`) : au premier contact après un vol (≥ `LANDING_MIN_AIR` sous-pas), la vitesse **normale** au sol est absorbée (`landAbsorb` 0,95 : aucun rebond) et la vitesse **tangentielle** garde `1 − landLoss × (écart d'alignement − landTolerance)` (plancher 0,4), l'écart étant |tangage − pente du sol| + |roulis − pente latérale| (pentes, jamais d'angles). Mêmes règles dans une cuve (`landOnShell`) ; la voiture se pose à plat sur la paroi.
- **Rotation héritée** : en l'air la caisse garde tangage, roulis et lacet (`airDamping` 0,4 /s) ; plus de retour à l'horizontale (`airLevel` supprimé). Un vol de moins de `HOP_SUBSTEPS` (6 sous-pas : bosse, frôlement de paroi) garde l'ancien amortissement fort. Pentes bornées à ±1,6 (`AIR_TILT_MAX`). En quittant une paroi (`leaveShell`) seule la **vitesse de rotation** de la courbure est héritée (bornée à 1,5 pente/s), jamais l'inclinaison : une caisse couchée par une paroi verticale lirait ses roues sous la route comme un mur (`STEP_UP`).
- **Frein en l'air = figer** : l'amortissement de la rotation passe à `airDamping + airFreeze × frein` (`airFreeze` 14 /s : < 5 % de la vitesse angulaire en 0,3 s) ; il ne ralentit pas la voiture (rien du moteur ni des freins n'agit en l'air). Accélérateur et direction sont sans effet en l'air.
- **Pilote** : `needsFreeze(car)` (autopilot.ts) = en vol (≥ 6 sous-pas) et la caisse tourne (> 0,12 /s) ; le pilote freine alors. Les tests de saut et de tremplin l'utilisent aussi (un joueur correct fait pareil). Après l'arrivée, une voiture qui repart en arrière freine aussi (`FINISH_REVERSE_BRAKE`, race.ts).
- **Clés de `CarParams`** (toutes dans `?debug&tune`) : `airDamping`, `airFreeze`, `landAbsorb`, `landTolerance` (0,3), `landLoss` (0,7). `landBounce` et `airLevel` n'existent plus. `SIM_VERSION` : **11** ; `GENERATOR_VERSION` : **12** depuis le lot 20 (figures).
- **Web** (présentation seule) : indicateur « ❄ FIGÉ » (`#freeze`) tant que le frein agit en vol, caméra qui suit la **direction du déplacement** en vol (`airMix`), son de réception selon sa qualité (`landingQuality` / `landingSound`, audioLogic.ts), secousse plus forte pour une mauvaise réception. `__cdj.air` expose `{ frozen, lastLanding, cameraMix }`.
- Scénario `?scenario=air` (`createAirTrack`, circuits.ts) : dos d'âne à haute vitesse, tremplin `J`, long saut au super turbo, saut vers un virage relevé, chute de trois niveaux, mur latéral quitté en l'air. Tests : `packages/sim/test/air.test.ts` (seuils recopiés dans `docs/lots/lot-19-air.md`), `e2e/air.spec.ts`.

## Commandes tactiles (lot 10)
- `apps/web/src/touch.ts` (logique pure, testée : `TouchPad` = doigts → axes, `dragSteer`, `zoneAt`, réglages `cdj:touch`, seuil de choc) ; `touchUi.ts` (DOM : zones, aides, boutons, réglages, invitation portrait, plein écran) ; `input.ts` (`Controls` fusionne clavier, manette et doigts). Mode actif si `pointer: coarse`, ou `?touch=1` (la souris simule le doigt) ; `?touch=0` le coupe.
- Disposition paysage : moitié gauche = direction (glissement relatif au point de pose, ou boutons ← →), moitié droite = frein ; accélérateur **automatique** par défaut (ou bouton gaz) ; boutons pause / reprise / départ / réglages / plein écran ; **P** = pause (aussi au clavier).
- **Deux pédales par défaut (retouche 18b)** : `autoThrottle` vaut `false` (gaz manuel à droite + frein) ; l'accélérateur automatique reste une option des réglages. Les réglages enregistrés (`cdj:touch`) portent une **version** (`TOUCH_SETTINGS_VERSION`, 2) : un enregistrement sans version (ancien défaut) retrouve une fois le nouveau défaut pour `autoThrottle`, le reste est conservé ; un choix fait depuis est respecté. Les e2e qui conduisent en automatique l'enregistrent d'entrée (`phone(browser, p, { stored })`, `fresh: true` pour le vrai défaut).
- **Règle : le tactile produit les mêmes commandes entières que les autres entrées** (axes flottants → `makeInput`) ; rien dans `sim`, rediffusions identiques. Vibration (point de contrôle, choc) = présentation seule, lecture de la vitesse sans effet sur la simulation.
- **Zones (retouche 10b, `docs/lots/lot-10b-zones-tactiles.md`)** : une seule définition dans `touch.ts` — `zoneSpans` (zones **actives**, sans trou, toute la hauteur : ← 0–25 %, → 25–50 %, frein 50–100 % ou frein 50–75 % | gaz 75–100 %), `zoneAt` en découle, `buttonRects` place le **visuel** (compact, centré dans sa zone, écarté des zones sûres `env(safe-area-inset-*)` et de 24 px des bords). Le toucher se décide par la zone, jamais par le bouton dessiné. Un doigt glisse d'un bouton à l'autre d'une même famille (← →, frein / gaz) ; identifiant de pointeur, `pointerup` / `pointercancel` seulement (pas `lostpointercapture`). **Piège : un petit bouton attire les appuis voisins** (le navigateur corrige le toucher vers lui) : la barre d'actions reste compacte et loin des frontières entre zones. Réglage « taille des boutons » (`buttonSize`), `?steer=boutons|glisser`, `?zones=1` (zones et un point par doigt, rouge hors couche de jeu), options dans `/admin/`.
- Tests : `apps/web/test/touch.test.ts` ; e2e `tactile.spec.ts` (vrais événements tactiles via `Input.dispatchTouchEvent`, gabarits Android et iPhone) ; outils `?debug` : `spec=<blocs>`, `__cdj.input`, `__cdj.manual(true)` + `__cdj.advance(n)` (pas à pas, sans rendu). Aides de mise en page : `e2e/layout.ts`.

## Surfaces et blocs à effet (lot 8)
- **Revêtement = attribut d'un bloc** (`Block.surface`, notation `S/t` terre, `S/g` glace, `S/h` herbe ; `/b` = virage relevé : `L2/b`, `R/tb`) ; `parseToken` (`track.ts`) lit la notation. `SURFACES` (`world.ts`) : `{ grip, traction, rolling, slick }` — route `1/1/0`, terre `0,7/0,85/1,5`, herbe `0,5/0,55/7`, glace `0,3/0,4/0` (`slick` 1 : lot 16) ; `surfaceAt(échantillon)` les lit sous chaque roue (adhérence latérale ← grip ; motricité et freinage ← traction ; roulement en m/s²). **Où en ajouter un** : `SurfaceKind` + `SURFACE_LETTERS` (track.ts), une ligne de `SURFACES`, ses couleurs dans `trackMesh.ts` (`SURFACE_COLORS`, `SURFACE_MARKS`), `SURFACE_HUD` (main.ts). **Nouvelle surface ou nouveau bloc = `SIM_VERSION` +1** (et `GENERATOR_VERSION` si le pilote ou le générateur s'en sert).
- **Blocs à effet** : `P` plaque, `T` super turbo (`turboTicks` 180, `turboAccel` 42, `turboMaxSpeed` 68 : trois clés de `CarParams`), `C` moteur coupé (`car.cut` : l'accélérateur n'agit plus ; `stepRace` le rend au pas exact qui franchit le point de contrôle suivant). Les états `boost`, `turbo`, `cut` vivent dans `CarState` (donc rejoués à l'identique) ; après l'arrivée les effets sont coupés (`withoutEffects`).
- **Virages relevés** : `bankAt` (track.ts) donne hauteur et gradient du relevé (pente 0,3 serré / 0,22 large, rampe de 8 m) ; `world.sample` les ajoute à la hauteur et au gradient ; `collide` compare au sol réel ; la voiture reçoit la pente latérale (`ay -= gravity × pente`). Rendu : `trackMesh.ts` (`arcPoint` suit le relevé).
- **Pilote** : `racingLine` module vitesse de passage (grip × revêtement + g × pente) et freinage (traction × revêtement + roulement) ; il reste à 1,5 m de l'axe en virage relevé. Générateur : `PAD_RUNOUT` (2 droites derrière une plaque) et `TURBO_RUNOUT` (5 derrière un super turbo).
- Tests : `packages/sim/test/surfaces.test.ts` (seuils recopiés dans `docs/lots/lot-8-surfaces-themes.md`), `e2e/surfaces.spec.ts`. Outils : `?scenario=surfaces`, `?theme=<stade|rallye|banquise|nuit|campagne>`.

## Glace (lot 16)
- La glace réagit au pied (`car.ts`, `SurfaceParams.slick` = 1 ; valeurs = clés `ice*` de `CarParams`, dans `?debug&tune`) : **accélérateur appuyé** = adhérence latérale très faible (`SURFACES.ice.grip` 0,3), sous-virage, motricité 0,4 (patinage) ; **roue libre** (ni gaz ni frein) = adhérence rendue (`iceCoastGrip` 0,38), décélération × `iceCoast` 0,3, et `iceRealign` 0,8 /s éteint la vitesse latérale (le vecteur vitesse se réaligne sur le cap, sans freiner) : gauche-droite en roue libre rattrape la trajectoire ; **frein** = adhérence × `iceBrakeGrip` 0,5, freinage 16 m/s², glisse. Pointe sur glace = pointe du plat × `iceTop` 1,2 (la traînée au-delà de la pointe suit). Aucun roulement sur glace.
- Pilote : vitesse de passage sur glace = roue libre (`racingLine(…, iceCoastGrip)`), il lâche l'accélérateur en braquant (> 0,12) et le rend en ligne droite. Générateur : aucune règle ajoutée ; *Banquise* mesurée comme les autres thèmes. `?scenario=glace` (`GLACE_TRACK_SPEC`), tests `packages/sim/test/glace.test.ts` (seuils dans `docs/lots/lot-16-glace.md`), e2e `glace.spec.ts`. `SIM_VERSION` et `GENERATOR_VERSION` valent **7**. **Un test qui compare des revêtements fixe le pied** (gaz appuyé).

## Thèmes (lot 8)
- `themes.ts` : `THEMES` (stade, rallye, banquise, nuit, campagne). **Choix** : `themeForDay(jour)` = `THEME_NAMES[Rng(mixSeed(jour, 0x70a1)).int(5)]` — graine = jour UTC, identique pour tous ; la palette en découle (`paletteForDay`). **Un thème règle** : palette, zones de revêtement (nombre et poids), largeurs de route (poids et nombre de changements, lot 12), chance de virage relevé, chance de super turbo, moteur coupé (suivi d'un point de contrôle deux blocs plus loin), passage signature (`signatureParts`, generator.ts). `dailyCircuit(jour, variante = 0, thèmeImposé?)` : un thème imposé donne un autre circuit (id `jour-AAAA-MM-JJ-g<N>-<nom>`), marqué `forcedTheme` ; **par l'adresse (`?theme=`, `?variant=`) c'est un essai, jamais classé** ; par le planning de l'admin il est classé.
- **Ajouter un thème** : un nom dans `THEME_NAMES`, une entrée de `THEMES` (et une palette `PALETTES` + `PALETTE_DEFS` dans trackMesh.ts + `PALETTE_LABELS` si nouvelle), éventuellement une signature. **Changer un thème (ou en ajouter un) = `GENERATOR_VERSION` +1**, puis régénérer `fixtures/daily-golden.json`.

## Largeurs de route et courbes amples (lot 12)
- **Largeur = attribut de bloc** (`Block.w0` entrée, `Block.w1` sortie, en m) : `e` étroite 14 m, `n` normale 20 m, `l` large 26 m (`ROAD_WIDTHS`, track.ts), dans une cellule de 32 m. Notation : `S/n` (constante), `S/e>l` (**bloc de transition**), combinable (`S/n>et`, `L3/lb`). **Chaînée comme les hauteurs** : un bloc sans largeur garde la sortie du précédent (14 m au départ, comme avant) ; une largeur écrite doit la prolonger exactement (`parseTrack` refuse « marche de largeur ») ; seul le premier bloc choisit la sienne. Un virage garde sa largeur (pas de transition dans un virage).
- **Transition** : une droite de 32 m dont la demi-largeur suit un lissage cubique (`blockHalfWidth`, `blockHalfWidthSlope` : pente nulle aux deux bouts, 0,28 au plus) ; `world.sample` l'utilise, `collide` incline la normale du rebord (`√(1 + pente²)`), le générateur ne fait qu'**un cran à la fois** (14 ↔ 20 ↔ 26). Les **plaques** (P, T) font la moitié de la largeur de la route (`blockPadHalfWidth`, 3,5 m de demi-largeur sur 14 m : inchangé) ; `Gate.halfWidth` donne la largeur de la porte (course : tolérance + 2 m) ; le rendu (`trackMesh.ts`) suit : rebords, sillons, damier, portes, tremplin, moteur coupé.
- **Virage ample `L3` / `R3`** (3 × 3 cellules, rayon d'axe 80 m, `curveSize`) : huit cellules réservées (le coin intérieur n'est jamais touché par la route), sortie à 3 colonnes et 2 rangées. Un **virage serré** (rayon 16 m) tient jusqu'à 26 m de large (rayon intérieur 3 m) mais **le générateur n'en met pas sur la route large**.

## Relief, sauts et chute (lot 17)
- **Niveaux** : `LEVEL` = 4 m. `U` / `D` = 1 niveau sur une cellule (pente 0,125) ; **`U2` `U3` `D2` `D3`** = 2 ou 3 niveaux (pente 0,25 / 0,375, `RISE_LETTERS`, `track.ts`). `Block.rise` = dénivelé résolu du bloc (les hauteurs s'enchaînent avec `exitDelta(kind, rise)`) ; `Block.open` = sans rebords. Un dos d'âne (`U2 D2`) fait décoller ; une montée raide ne se met jamais sur l'herbe, la terre ou la glace (la voiture cale : `surfaceable`, generator.ts).
- **Sauts** : **`K`** rampe (plate jusqu'à `KICK_START` = 16 m, puis +1 niveau, pente 0,25), **`G`** vide (aucun sol, aucun rebord ; `GU` / `GD` / `GD2` : l'autre bord est 1 niveau plus haut / plus bas / 2 niveaux plus bas), puis une réception (`D`, `S`…). `packages/sim/src/jump.ts` : `trackJumps(track)` → `{ kick, gapCells, gap, rise, landing, runout, minSpeed, maxSpeed }` = **fenêtre de vitesse au bord de la rampe** (balistique pure, marge ×1,05 mesurée ; plancher ≈ 33 m/s pour un vide d'une cellule vers un bord plus bas, 40 au même niveau, 52–58 pour deux cellules, 55 vers un bord plus haut ; plafond = la réception ne suffit plus). **Tester par la simulation** (`test/sauts.test.ts`), pas seulement par la formule. `J` (tremplin, lot 2) reste dans le circuit d'essai et `pilotage`, mais le générateur ne le pose plus.
- **Sans rebords** (`S/o`, modificateur `o`) : `collide` ne retient plus la voiture par le côté ; elle tombe. Le générateur n'en met que sur des blocs ordinaires à ≥ 6 m au-dessus du point le plus bas (`openSection`), selon le thème (`openChance`).
- **Chute** (`race.ts`) : sous `track.voidY` (route la plus basse − `FALL_DEPTH` = 4 m) `race.fallTicks` passe à 1 ; la voiture tombe **sans commande** pendant `FALL_TICKS` = 60 pas (0,5 s), puis reprend au dernier point de contrôle (`respawn`) ; le chrono ne s'arrête jamais (un pas par pas, +1 à la reprise) ; la touche de reprise pendant la chute reprend aussitôt. Rejouable à l'identique. Web : voile sombre `#fall`, bandeau « Chute ! », sons `fall` / `respawn`, caméra qui ne plonge pas ; **ombre d'atterrissage** (`landing.ts`, `predictLanding` : lecture seule) = ombre posée au point de réception prévu, absente si la voiture ne retombe sur rien.
- **Générateur** (`composeSpec`) : dénivelé ≥ `MIN_RELIEF` = 12 m (le premier relief du circuit en fait au moins 12), reliefs `HILLS_GENTLE` / `HILLS_STEEP` (hauteurs gardées entre ±24 m), **vrai saut** (`jumpCalm` : `short` K GD, `flat` P K G D, `long` T K G G D, `longDown` P K G GD D, `up` T K GU) selon `theme.jumpChance` (100 % Stade, Nuit ; le Rallye l'a aussi par sa signature, un saut court sur la terre) ; priorité des créneaux : signature, saut, virages marquants, portions rapides, reliefs. Pas d'intersection (une cellule = un bloc) ; **pas de pont à deux niveaux** (la grille ne le permet pas simplement). Descentes raides dans la portion rapide `drop`.

- Rendu : piliers et dalle mince au-delà de `PILLAR_MIN` = 12 m au-dessus du sol lointain, faces pleines au bord d'un vide, rampe claire à bande d'alerte, damier vert de réception, bordure plate rouge et blanche sans rebords. Miniatures : le vide se voit (repli 2D compris).

## Cuves (lot 18)
- **Notation** (`track.ts`) : `V` cuve droite (deux parois, demi-tube), `ML` / `MR` mur latéral (une paroi, à gauche / à droite), `/c` sur un virage (`L2/c`, `R3/c`, `L/c` : sa paroi est du côté **extérieur**). Une cuve est **une droite ou un virage avec un attribut** : `Block.cuve` (bits `CUVE_LEFT` | `CUVE_RIGHT`), `cuveIn` / `cuveOut` (côtés que le voisin prolonge : pas de rampe à ce bord). Refusés : pas de repère (`@cp`) ni de transition de largeur, ni `o`, ni `b`, ni sur le départ ou l'arrivée ; elle reste plate (aucun relief), la route peut porter un revêtement mais le générateur n'en met pas. `parseToken` renvoie `cuve` seulement s'il y en a une.
- **Géométrie** (`cuve.ts`, pas de trigonométrie) : en travers de la route, fond plat jusqu'à `f`, **quart de cercle** de rayon `R = CUVE_RATIO (0,65) × demi-largeur` (4,6 / 6,5 / 8,5 m pour 14 / 20 / 26 m), qui devient vertical en `demi-largeur`, puis **paroi verticale** jusqu'à `R + CUVE_LIP (8 m)` ; au-delà, c'est le vide (on passe par-dessus). Amplitude `a` ∈ [0, 1] (`cuveAmplitude`) : 0 = rebord ordinaire de 1,4 m, 1 = cuve ; **rampe de `CUVE_RAMP` = 16 m** depuis l'entrée / la sortie d'une droite, **30 % de l'arc** (`CUVE_RAMP_ARC`) dans un virage (7 / 22 / 37 m), sauf si le bloc voisin prolonge la paroi. Un virage est une **surface de révolution** (l'écart est la distance au centre du virage) : la normale reste dans le plan rayon-vertical. `shellAt` (distance signée, normale, avance de la route) ; `world.shell(x, z, y, out)` n'existe que pour `trackWorld` (le sol plat n'en a pas) ; `world.sample` rend une hauteur approchée (paroi tronquée à ≈ 80°) pour les lecteurs de hauteur ; `collide` ne répond pas dans une cuve (les parois sont dans la surface).
- **Physique** (`car.ts`, `substepShell`) : le contact se fait par la **normale** de la surface. La voiture est repérée dans le plan tangent (`tangentFrame` : avance `f`, gauche `l`, normale `n`) ; `car.yaw` reste l'angle d'un cap « à plat » (la voiture tourne autour de la normale : `yaw − cap de la route`) ; mêmes pneus, moteur et freins qu'à plat (formules recopiées de `substep`) ; la pesanteur se projette sur le plan (`ax −= slopeGravity × f_y`, `ay −= gravity × l_y`) ; la paroi repousse la position le long de la normale et supprime la vitesse qui y entre (sans rebond) ; **en l'air** (distance > `SHELL_TOUCH` 0,08 m) : balistique ; elle suit une paroi qui s'éloigne de moins de `SHELL_SNAP` 0,1 m (fin de rampe). Tangage et roulis restent 0 dans une cuve ; `CarState` gagne `nx, ny, nz` (la normale sous la voiture : (0, 1, 0) hors cuve, lue par le rendu). **Les blocs sans cuve rejouent au bit près** (test : même état qu'un monde sans `shell` ; rediffusion de l'essai inchangée à la version près).
- **« Décrochage »** (cuve **droite** seulement) : au-dessus de `shellStickHi` (34 m/s) la pesanteur le long de la paroi est annulée (la voiture tient sur la verticale), sous `shellStickLo` (24 m/s) elle s'applique en entier (la voiture redescend), entre les deux c'est progressif (`smoothstep`) ; l'adhérence suit la charge presque en proportion sur une paroi, et `shellDown` (1,2 g) est l'appui qui charge les pneus à vitesse. **Dans un virage en cuve la pesanteur reste entière** : c'est la géométrie (cône) qui tient la voiture à sa hauteur d'équilibre (`tan θ = v² / (g × rayon)`). Trois clés de `CarParams` (`?debug&tune`).
- **Pilote** : `AutopilotOptions.wall` (faux par défaut : le fond, comme un virage ordinaire) ; `true` = trajectoire **clouée** à la paroi extérieure du virage en cuve (écart latéral imposé : `pin`, entonnoir de 40 m en lissage cubique, `CUVE_INSET` = 1 / 2 / 2,5 m du pied de la paroi verticale selon la taille, `racingLine` compte `g × pente de la paroi` comme un relevé, aucun freinage sur la rampe de sortie). **`bestPilotRun` essaie les deux** (fond et paroi, 4 niveaux d'adhérence chacun) et garde le plus rapide ; `PilotRun.wall` dit lequel. La relaxation de la trajectoire va plus loin (4000 itérations) seulement pour un circuit qui a un virage en cuve : **les autres circuits gardent leur tracé**.
- **Générateur** : `Theme.cuveChance` — Stade 100 %, Nuit 100 %, Banquise 25 %, Rallye et Campagne 0 %. Rien n'est tiré pour un thème sans cuve (même suite de tirages). Motifs (`CuveKind`, poids 3 / 2 / 3) : `bowl` six blocs `S V V V V S`, `wall` `S ML/MR ×4 S`, `turn` un virage en cuve (`L2/c`, `L3/c`, parfois le serré `L/c` qui compte dans le budget de virages serrés). Priorité des créneaux : signature, saut, **cuve**, virages marquants, portions rapides. `bowl` et `wall` ajoutent six cellules : un créneau de moins ; s'il n'y a pas de créneau calme libre, c'est un virage en cuve. Un thème à 100 % refuse la tentative sans cuve (graine voisine).
- **Rendu** (`trackMesh.ts`, `addCuve`) : fond à la couleur du revêtement, quarts de cercle et parois en **damier rouge et blanc** (bandes de 4 m dans le sens de la marche), chapeau de crête, remblai en retrait de 0,15 m derrière chaque paroi (sinon les deux plans scintillent). Voiture et fantôme : `carPose.ts` (`CarPose` : la normale de la voiture, lissée à 12 /s, tourne le « haut » du monde ; **l'axe de rotation est l'avance de la route**, le cap reste donc le long de la paroi) ; **caméra** : son « haut » est entre la verticale et la normale (60 % du roulis, `CAMERA_ROLL_FOLLOW`) ; ombre masquée sur une paroi. `telemetry.ts` : roues posées dans le plan tangent (`tangentFrame`), `tilt`, `onWall` ; `fx.ts` : traces de pneus au ruban orienté par la normale (`Skids.wheel(…, nx, ny, nz)`) et étincelles des roues arrière sur la paroi (> 18 m/s).
- Outils : `?scenario=cuves` (`CUVES_TRACK_SPEC`, circuits.ts : élan, cuve droite, mur latéral, virage en cuve large à pleine vitesse, demi-tour serré, le même virage abordé trop lentement), raccourci « Cuves et murs » de `/admin/`, ligne « Cuves » du planning (`cuvesText`), miniature cadrée sur la cuve s'il n'y a ni signature ni saut. Tests : `packages/sim/test/cuves.test.ts` (seuils recopiés dans `docs/lots/lot-18-cuves.md`), `apps/web/test/carPose.test.ts`, `e2e/cuves.spec.ts` (navigateur et Node calculent la même voiture sur la paroi, à 1e-9 près).
- `SIM_VERSION` et `GENERATOR_VERSION` valent **9**. **Une nouvelle forme de paroi ou un changement de `shell*` = `SIM_VERSION` +1** (et `GENERATOR_VERSION` : le pilote d'auteur roule sur ces blocs), puis les références habituelles (`UPDATE_GOLDEN=1`, `history:seed`, `measure:generator`).

## Figures (lot 20)
- **Un circuit du jour = 5 à 7 figures** (`packages/sim/src/figures.ts`, `FIGURES`, 40 figures) posées à la suite par `composeFigures` (`generator.ts`) ; `composeSpec` n'en rend que le texte, `DailyCircuit.figures` donne `{ name, variant, left, from, to }` (blocs `[from, to)`). Le texte, les temps et les golden d'une date changent avec le lot ; **`SIM_VERSION` ne bouge pas** (aucun bloc, aucune physique).
- **Une figure** = `{ name, label, category, intent, variants, off, build(ctx) }` + drapeaux `jump` / `cuve` / `cut` / `turbo` / `banked` / `relief` / `braking`, `weight`. `build({ L, R, wall, width, variant })` rend des blocs (`L` = sens du premier virage, échangé par le miroir ; `width` = route à l'entrée, la figure se rétrécit d'elle-même si besoin : `toTight`, `reach`) ou `null` si la variante est impossible. Catégories : `technique`, `saut`, `rapide`, `combo`, `cuve`, `relief`. Une figure commence par une droite d'amorce (retirée si le bloc précédent en est une) et garde derrière elle les droites exigées (2 après une plaque, 5 après un super turbo, 3 après un saut court, 5 après une cuve ou un saut long). `turned` ajoute un virage large derrière un saut ou une cuve : sans lui, on les quitte à plus de 55 m/s et on garde le plein gaz jusqu'au bout.
- **Composition** (`selectFigures`) : la signature du thème (`SIGNATURE_FIGURE`) toujours ; un saut et une cuve selon `jumpChance` / `cuveChance` (une figure qui fait les deux, 55 %) ; du dénivelé (de préférence un virage en pente) ; au moins un **freinage franc** (`braking` : plaque ou turbo, puis virage) ; une portion rapide ; une figure favorite du thème ; au moins deux techniques ; le reste au poids (favorites ×4, `braking` ×2, `weight`) dans un budget de durée (`FIGURE_BUDGET`, `figureSeconds`). Plafonds : 2 sauts, 1 cuve, 1 moteur coupé, virages serrés (`minTightTurns`) ≤ `MAX_TIGHT`. **Huit tirages** : le premier budget tenu (`FIGURE_TOTAL_MAX`) qui lâche le plus le gaz (somme des `off`) l'emporte. Ordre aléatoire, jamais de saut en tête ni en queue ; chaque figure prend la première (variante, miroir) qui tient sur la grille, dans les hauteurs permises et le budget de virages serrés, sinon une remplaçante de la même catégorie ; la signature ne se remplace pas. Liaisons `CONNECTORS` ; `MAX_PLAIN_STRAIGHT` (6 blocs) plafonne la plus longue droite ordinaire. Un circuit estimé hors de `ESTIMATE_MIN`–`ESTIMATE_MAX` (`estimateSeconds` : durée du pilote ≈ 0,95 × estimation) est refusé **sans faire rouler le pilote**.
- **Peu de répétition sans historique** : `isRested(nom, jour)` — trois groupes de figures (empreinte du nom), le jour `d` laisse au repos le groupe `d mod 3` (hors signature) ; deux jours de suite n'ont que le tiers des figures en commun, et rien n'est généré pour les jours passés. **Thèmes** : `theme.figures.favor` / `.ban` (glace là où il y a de la glace, terre là où il y a de la terre, cuves là où il y en a).
- **Ajouter une figure** : une entrée de `FIGURES` (nom en minuscules à tirets, `off` provisoire) → `npx vitest run packages/sim/test/figures.test.ts` (le pilote doit finir **chaque** variante, dans les deux sens, sur les trois largeurs) → `RHYTHM=1 npm run measure:generator` pour régler `off` (secondes hors plein gaz par passage) → favorites ou interdites des thèmes → **`GENERATOR_VERSION` +1**, `UPDATE_GOLDEN=1 npx vitest run packages/sim/test/golden-daily.test.ts`, `npm run history:seed`. **Un thème qui interdit trop de figures ou une règle de plus se mesure** (`construit` / `dans la fenêtre` par thème) : au lot 20, trois virages serrés tirés sans compter faisaient échouer 50 % des tentatives de *Campagne*.
- **Pilote** : mesure seule ajoutée à `PilotRun` (`fullThrottleTicks`, `liftEvents`, `grip`) ; un moteur coupé ne compte pas comme plein gaz.
- Web : `?scenario=figures` (tour de onze figures écrit à la main, `FIGURES_TRACK_SPEC`) et `?scenario=figure&f=<nom>&v=<variante>&m=1` (`createFigureTrack` : cinq droites de lancement, point de contrôle juste avant, miroir avec `m=1` ; nom inconnu = circuit d'essai) ; admin : « Les figures », « Une figure en boucle » (sélecteur, variante, miroir) et la carte d'un jour du planning liste ses figures (`figuresText`). Tests : `packages/sim/test/figures.test.ts`, `apps/web/e2e/figures.spec.ts`. README : `docs/lots/lot-20-figures.md`.

## Règles de la simulation (déterminisme)
- Pas fixe (`TICK_RATE` = 120 Hz), jamais de `dt` variable ; interpolation à l'affichage seulement.
- Pas de moteur physique externe. Pas de `Math.sin/cos/exp/pow/tanh/atan2/…` dans `sim` : implémentations maison ou tables (`sin`/`cos` de `math.ts` ; saturation rationnelle `tireCurve` = t / ⁴√(1 + t⁴) ; angles de glissement, tangage et roulis gardés en **pentes** (rapports), jamais convertis en angles ; amortissements en `x * (1 − k·dt)`).
- Modifier une valeur par défaut de `CarParams` (ou la géométrie de `car.ts`) = incrémenter `SIM_VERSION` + régénérer les références (et `GENERATOR_VERSION` si le temps du pilote change, ce qui est presque toujours le cas).
- Commandes de la voiture = entiers (`makeInput`) ; l'état de référence de `car.test.ts` ne change que si la physique change volontairement.
- Pas de `Math.random` ni `Date` dans `sim` : PRNG à graine explicite.
- Une course = la suite des commandes du joueur ; le même code la rejoue côté serveur.

## Méthode
- Un lot = une session = une branche = une PR. L'agent s'arrête quand les critères du lot sont verts.
- Tout code de `sim` est testé par Vitest en ligne de commande.
