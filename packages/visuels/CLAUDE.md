# `packages/visuels` (`@cdj/visuels`) : les visuels communs des jeux (lot DA1)

Chargé quand on lit un fichier de `packages/visuels`. **Zone partagée** (un lot n'y touche que si son prompt le dit : lot de plateforme). Deux modules : **`blocs`**, la direction artistique des blocs de Tower (aplats bordés d'encre, relief, petits yeux, palettes par thème du jour), que Blocks et d'autres jeux reprennent ; **`plateformes`** (lot DA2), celle de Jump (thèmes, tuiles, décor, personnage, blocs à mécanique), que Gravity et d'autres jeux de plateformes reprennent. Le module ne dépend d'aucun jeu ni de la plateforme (`three` seulement, dans le dessinateur Three.js) et ne nomme aucun jeu dans son code.

## Les couches (un point d'entrée chacune ; l'index est vide)
| Point d'entrée | Contient | Chargement |
|---|---|---|
| `@cdj/visuels/blocs` | **la description**, sans moteur de rendu : palettes (le port), formes (`boitesDeForme`), relief (`decrirePiece` : l'encre, le liseré, la couleur, tous dans la forme), yeux (`expressionDe`, `disposerYeux`, `Clignotement`), couleurs de la charte (`ENCRE`, `PAPIER`, `melanger`) | premier chargement du jeu qui s'en sert (palette du port, mélange) |
| `@cdj/visuels/blocs/themes` | les cinq autres palettes | `import()` |
| `@cdj/visuels/blocs/three` | le dessinateur **Three.js** (celui de Tower) : formes de base, `poserCouches`, `Yeux` | avec la scène du jeu, jamais au premier chargement |
| `@cdj/visuels/blocs/canvas` | le dessinateur **Canvas 2D** (pour un jeu en grille) : `placer`, `dessinerCouches`, `dessinerYeux`, `dessinerPiece` | à la demande |

**Règles** : (1) un fichier de description n'importe ni `three`, ni le navigateur, ni un jeu (`test/description.test.ts`) ; (2) **les deux dessinateurs lisent la même description** : un nouvel élément du dessin s'ajoute d'abord à la description, puis aux deux dessinateurs, et la planche `/ui/` › Blocs doit rester sous 1 % de pixels différents par paire (`apps/web/e2e/portail.spec.ts`, `test/dessinateurs.test.ts`) ; (3) le module ne lit aucun jeton : l'encre et le papier sont des constantes que les tests des jeux comparent aux jetons (`apps/tower/test/visuelsBlocs.test.ts`) ; (4) les couleurs et les distances viennent de Tower **sans changement** : toute modification d'apparence est une décision de Nathan, et Tower le voit (captures de référence) ; (5) tout dépasse-t-il le budget d'un jeu ? mesurer (`node scripts/budgets.mjs`).

## Le module `plateformes` (lot DA2)
| Point d'entrée | Contient | Chargement |
|---|---|---|
| `@cdj/visuels/plateformes` | **la description**, sans moteur de rendu : les cinq thèmes (`THEMES` : palette, tuiles, décor, plans de parallaxe), les couleurs réservées (`HAZARD`, `HAZARD_OUTLINE`, `PLAYER`), l'assemblage des tuiles (`tileShape`, `neighbourMask`, `depthMap`, bruit de case), les règles du décor (`DECOR_*`, `itemBox`), le personnage (`LOOK`, `STEP`, `animateLook`, pieds calés sur la distance, écrasement), les blocs à mécanique (`BELT_STYLE`, `ICE_STYLE`, `BLOCK_STYLE`, `WIND_STYLE`) | premier chargement du jeu (tout est de la donnée, les imports inutilisés partent à la construction) |
| `@cdj/visuels/plateformes/three` | le dessinateur Three.js (`src/plateformesThree/`, à côté de la description, jamais dedans) : le tampon de géométrie pur `Art` et `artGeometry`, les plans de parallaxe (`buildParallax`, `layerOffset`, `visibleLayers`), les tuiles d'une grille (`buildTileArt(grille, style, codes, degagement)`, `insideTiles`) et le personnage (`creerPersonnage` : cube, yeux, pieds ; `poser(look)` à chaque image) | avec la scène du jeu, jamais seul au premier chargement (les imports inutilisés partent à la construction) |

**Règles** : (0) **le dessinateur ne lit pas plus que la description** (`test/plateformesThree.test.ts` : n'importe que `../plateformes`, `three` et `@cdj/core`, aucun nom de jeu) ; **ce que le jeu garde** : le décor posé (`placeDecor`, `buildDecorArt`), les dangers, les blocs à mécanique animés, la caméra, la scène ; le jeu dit ce que sont ses cases par un `CodesTuiles` (`estMatiere`, `estGlace`, `estPic`, `sensTapis`, `vide`) et lui donne la distance de chaque case au danger le plus proche (`degagement`, pour que la garniture n'ait pas de bosse près d'un danger) ; (1) les identifiants et les valeurs sont ceux du jeu d'origine, **sans changement** (un changement d'apparence est une décision de Nathan et se voit dans tous les jeux qui lisent le module) ; (2) le module ne lit ni la simulation ni un jeu : **ce qui dépend d'un niveau** (poser le décor, dire ce qui est de la matière, le choix du thème d'un jour, l'événement d'un pas) **reste dans le jeu**, qui passe au module une grille (`Grille`) et un prédicat (`estMatiere`) ; (3) `test/plateformes.test.ts` : aucun import hors du dossier, aucun nom de jeu, rien du navigateur ; (4) les mesures de contraste (luminance, teinte) et les tests de lisibilité restent dans le jeu, qui lit ses palettes dans le module ; (5) tout dépasse-t-il le budget d'un jeu ? mesurer (`node scripts/budgets.mjs`).

**Réutiliser un design (jeu de plateformes)** : 1. `THEMES[nom]` donne palette, tuiles (`TileStyle`), décor (`DecorKind`) et plans (`ParallaxLayer`) ; le jeu choisit le thème de son jour. 2. Pour dessiner les tuiles : `neighbourMask(grille, col, row, estMatiere)` puis `tileShape(masque)`, `depthMap` et `depthColor`. 3. Le personnage : le jeu remplit un `Motion` (vitesses en tuiles/s) et appelle `animateLook` à chaque image ; `STRIDE_TILES` règle le cycle des pieds. 4. Les dangers gardent `HAZARD` et son contour ; aucun bloc ne prend ni ce rouge ni le jaune du personnage. 5. Ce qui est propre à un jeu (son héros, ses blocs propres) n'entre pas ici. 6. **Dessiner avec Three.js** : `buildTileArt(grille, theme.tiles, codes, degagement)` → un `Mesh` par tronçon (`artGeometry`, `MeshBasicMaterial({ vertexColors: true, side: DoubleSide })`) ; `buildParallax(theme, largeur, identifiantDuNiveau)` → un `Mesh` par plan, posé à `layerOffset` ; `creerPersonnage({ couleur, largeur, hauteur })` → `groupe` à poser au bas-milieu de la boîte. **Preuve que le dessin n'a pas bougé** : `apps/jump/test/dessinFige.test.ts` (empreinte de la géométrie de Jump). La planche `/ui/` › Plateformes montre les cinq thèmes, le personnage et les blocs à mécanique.

## Le relief n'a pas de trou (lot B1)
`interieur` (`relief.ts`) ajoute un carré de `2 × retrait` à tout point que quatre quarts de plan remplis se partagent (quatre cases autour d'un point, ou deux cases appuyées sur une troisième) : sans lui les ponts s'arrêtent tous à `retrait` du point et un point d'encre reste au milieu du bloc. Les coins rentrants (T, L) n'en reçoivent pas. **Aucune forme de Tower n'a un tel point** : `test/description.test.ts` vérifie que leurs rectangles sont inchangés (une boîte, ou autant de boîtes que de ponts + 1), donc leur rendu aussi. Le regard (`regard`, `regardVers`) et la fermeture des yeux (`fermeture`, genre `figee`, clignement) existent déjà dans `expression.ts`.

## Détails qui font le même rendu
Le disque est le polygone de 20 côtés de Three.js (`COTES_DISQUE`) ; les rectangles d'une couche sont **un seul chemin rempli une fois** en Canvas (sinon un filet clair marque l'arête de deux rectangles) ; les yeux se dessinent **couche par couche** (tous les contours, puis les blancs, les pupilles, les sourcils : un œil écarquillé recouvre l'autre).

## Réutiliser un design (comment un jeu reprend les blocs)
1. Donner au dessin des **boîtes** (`Boite8`, huitièmes de case autour du centre de masse) : `boitesDeForme` pour les sept formes à quatre cases, ou les siennes.
2. `decrirePiece(boites, { couleur: palette.pieces[forme], encre: ENCRE, halo? })` → les couches ; `centreDesYeux(boites)` et `disposerYeux(x, y, échelle, expressionDe({ niveau, genre, regard, clignement, t }), t, phase)` → les yeux. Le niveau de panique et le regard sont **calculés par le jeu** (Tower : `panique.ts`) ; le module ne lit que le nombre.
3. Dessiner : en Canvas, `dessinerPiece(ctx, { x, y, pxParMetre, angle }, couches, yeux)` ; avec Three.js, `poserCouches(groupe, couches)` et `new Yeux(groupe, x, y, échelle, phase).appliquer(expression, t)` à chaque image.
4. Palette : `PALETTE_PORT`, puis `import("@cdj/visuels/blocs/themes")` ; le jeu vérifie le contraste avec ses propres fonds (Tower : `test/palettes.test.ts`).
5. **Rien de ce qui est propre à un jeu n'entre ici** (décors, effets de palier, particules, habits : restent dans le jeu). Un nouveau design commun = un nouveau dossier `src/<nom>/` et ses points d'entrée.
