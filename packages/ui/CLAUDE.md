# `packages/ui` (`@cdj/ui`) : le socle commun de l'interface (lot I1, phase 3)

Chargé quand on lit un fichier de `packages/ui`. **Zone partagée par toutes les applications** (portail, Track, Jump : un seul propriétaire à la fois ; un lot n'y touche que si son prompt le dit). README : `docs/plateforme/lots/lot-I1-socle-ui.md`. Vision : `docs/plateforme/seed-phase-3.md` (ne pas modifier).

**La charte `docs/plateforme/identite.md` fait foi** (direction « Cartouches », lot I0) ; seul Nathan la modifie. Un écart nécessaire se **propose** dans le README du lot, il ne s'applique pas. Maquettes de référence (à lire, jamais construites ni servies) : `docs/plateforme/maquettes/cartouches/`.

## Ce que contient le paquet
- `src/jetons.ts` — **la seule source** des jetons (couleurs § 3, polices, échelle typographique, rayons, traits, ombres nettes, espacements, cibles, durées) ; `src/jetons.css` (`--dj-*`, `--track-*`, `--jump-*`) en est **généré** : `MAJ_JETONS=1 npx vitest run packages/ui/test/jetons.test.ts`. `valeurJeton`, `varJeton`.
- **Médailles (lot A1)** : le jeton `--dj-diamant` (`#4FC3DC`, texte `--dj-diamant-texte` `#0B2530`, contraste ≥ 7:1 : `PAIRES` de `src/contraste.ts`) **remplace `--dj-auteur`** (vert `#2E9E5B`), sans alias ; `TypeMedaille` vaut `"diamant" | "or" | "argent" | "bronze"` (classe `.dj-medaille--diamant`, clé `medaille.diamant` : « Diamant » / “Diamond”). Les applications traduisent la clé de **donnée** `author` / `auteur` (API, base, rediffusions) vers ce type : le nom affiché change, la donnée non (`apps/api/CLAUDE.md`).
- `src/socle.css` (base : fond, texte, focus visible, mouvement réduit, `.dj-cible`, `.dj-cache`), `src/composants.css`, `src/styles.css` (les trois) ; `src/polices/<famille>-<graisse>[-italique].css` : **une feuille par face**, l'application n'importe que les siennes. Fichiers `woff2` (sous-ensemble latin) et licences OFL dans `polices/`, copiés des paquets `@fontsource` par `node packages/ui/scripts/polices.mjs` (`polices/sources.json` : version, taille, empreinte).
- `src/composants.ts` — `logo`, `bouton` (marque, secondaire, track, jump), `cartouche` + `etiquetteTrack` / `etiquetteJump` (lot I2 : option `suite`, ce qui suit le texte — le statut du joueur sur le portail), `tuile`, `afficheur`, `barrePortail` (lot I2 : option `profil`, l'avatar devient un lien vers le profil commun), `barreJeu`, `choixLangue`, `avatar` (lot I2 : avec `href`, un lien de 44 px qui s'enfonce, montré dans la vitrine), `medaille` (pastille, case) ; `src/icones.ts` (chevron, flamme, crâne, drapeau, horloge, profil) ; `src/dom.ts` (`el`, `svg` : jamais `innerHTML`).
- `src/cadre.ts` + `src/cadre.css` (**lot I4b**) — `creerCadre` : le cadre d'un écran de jeu **posé sur sa scène** (charte rév. 8 § 9, « on reste dans le jeu » ; né dans Jump au lot I5, commun à Track et Jump) : un élément `.cadre` (`role="dialog"`, caché au départ s'il est créé ; ou l'élément `racine` déjà dans la page) avec le voile à rayures (`--cadre-voile`, encre par défaut), la barre des jeux en plaque crème (donnée par le jeu : `barre()`, relue par `majBarre()` avec `aria()`), puis `.cadre__defile` : l'étiquette (`main`, classes du jeu ; le jeu peut la poser dans sa coque) et le pied `.cadre__pied` (plaque crème, caché tant qu'il n'a rien de visible). `haut: true` (`.cadre--haut`) : un sous-écran, qui efface les autres cadres tant qu'il est ouvert (un seul voile). Rend `{ racine, etiquette, corps, pied, defile, majBarre }`. **`cadre.css` n'est pas dans `styles.css`** (le portail ne la charge pas) : chaque jeu l'importe et règle `--cadre-voile`, `--cadre-largeur`, `--z-cadre`, `--z-cadre-haut` et l'habillage de son étiquette. Montré dans la vitrine `/ui/` (section « Écran posé sur la scène d'un jeu », Track et Jump). **Le cadre crème pleine page est réservé aux écrans Du Jour** (portail, profil, classement du jour, mentions) : un écran de jeu passe par `creerCadre`.
- **Lot I7 : le plein écran** — `src/pleinEcran.ts` est **la seule logique de plein écran de la plateforme** (Track et Jump, leurs pauses, leurs accueils et leurs boutons en partie : plus aucune copie dans un jeu) : `pleinEcranPossible` (faux si `fullscreenEnabled` est faux — l'iPhone — ou si le site est ouvert comme application, `display-mode: standalone` ou `navigator.standalone` ; **lot 53 : sur iPhone le bouton reste, il ouvre l'aide**), `pleinEcranActif`, `basculerPleinEcran` (entre sans barre de navigation, **essaie de verrouiller le paysage** en entrant ; ne lève jamais : un refus est ignoré sans message), `surChangementPleinEcran` (`fullscreenchange`), `modeApplication`, `astuceIphoneAPropos` ; le module lit la page (`document`, `screen`, `matchMedia`, `navigator`) et les tests la remplacent (`vi.stubGlobal`, `test/pleinEcran.test.ts`, sur des navigateurs fictifs). **Pas de préfixe WebKit** (iPad avant iPadOS 16.4 : pas de bouton ; Track l'avait avant le lot I7 — retiré pour tenir le budget, voir `docs/plateforme/budgets.md`). Composants (`composants.ts`) : `boutonPleinEcran({ t, id?, classe, texte? })` (`t` : la traduction de `pleinEcran.entrer` / `.quitter`) — 44 px, icône au trait (`pleinEcran`, `pleinEcranQuitter` : quatre coins / coins rentrants), `aria-pressed` et nom lu selon l'état (« Plein écran » / « Quitter le plein écran » : `pleinEcran.entrer` / `.quitter`), **caché** quand ce n'est pas possible ; en partie c'est la plaque du jeu qui l'habille (`classe`), dans la barre des jeux `dj-plein-ecran--barre` ; `texte: true` en fait un bouton à texte (la pause). `barreJeu({ pleinEcran: true })` le pose à droite, à côté de la date (l'accueil de chaque jeu seulement). `astuceIphone({ textes, stockage })` : sur un iPhone sans plein écran, **une ligne** « Pour jouer en plein écran : Partager › Sur l'écran d'accueil » (`pleinEcran.iphone`) que la croix ferme et **qui ne revient pas** (mémorisé : `cdj:astuce:plein-ecran`, dans le stockage que **l'appelant** donne : ce paquet n'y touche pas ; nommé dans les mentions légales). `majPleinEcran()` : un jeu l'appelle quand sa langue change (les boutons et l'astuce se relisent ; un seul abonnement au document, aucun registre : l'événement `maj` est envoyé aux éléments `.dj-plein-ecran` et `.dj-astuce` de la page). Icône `camera` (la caméra de Track). Tout est montré dans la vitrine `/ui/` (section « Plein écran et astuce de l'iPhone »).
- **Lot 53 : l'iPhone et l'application ajoutée à l'écran d'accueil** — sur iPhone une page n'a pas de plein écran (l'API Fullscreen n'est ouverte qu'aux vidéos) : le plein écran passe par « Sur l'écran d'accueil ». `pleinEcran.ts` : `modeApplication` (`display-mode: standalone` **ou** `navigator.standalone`), `pleinEcranParEcranAccueil` (écran tactile **sans** API et hors application : **la fonction, jamais le nom de l'appareil** ; l'iPad, Android et l'ordinateur gardent leur plein écran), `pleinEcranBoutonVisible` (bascule **ou** aide), `reglerAideIphone({ lienCode, code })` (l'application dit où est son profil). `boutonPleinEcran` reste **visible sur iPhone et ouvre l'aide** (`aidePleinEcran`, `aideIphone.ts` : le geste Partager › Sur l'écran d'accueil, « Copier mon code », le lien du code ; pas d'`aria-pressed`, `aria-haspopup="dialog"` ; option `avantAide` : en partie le jeu se met en pause). `retrouver.ts` : **« Retrouver mon profil »** (`retrouverMonProfil` : « Coller mon code » lit le presse-papiers au geste du joueur, sinon le champ ; le profil trouvé est montré puis adopté après confirmation ; « Commencer sans profil »). **Règles** : ces deux écrans et leur feuille (`modale.css`) et leur catalogue (`catalogue.iphone.ts`, hors du catalogue commun) sont **à la demande** (`import()`, jamais dans `index.ts`) et **n'importent rien du reste du socle** (ni `dom`, ni `i18n`, ni `icones`, ni `pleinEcran` : un module à la demande qui importe un module du premier chargement le fait éclater en fichiers de plus, mesuré +1,2 ko sur Track) ; la langue est celle de `<html lang>` ; ils passent devant tout (`visibility: visible !important`). Dans la vitrine `/ui/` (section « Plein écran… »). **Marges de sécurité** : tout écran posé contre un bord les respecte (`max(<marge>, env(safe-area-inset-*))`).
- **Lot N2 : le message en direct** — `bandeauAnnonce(t, { texte, ton, onFermer, fermableApresMs?, classe? })` (`composants.ts`, feuille `.dj-bandeau` de `composants.css`) : une ligne `role="status"` (jamais de focus pris), ton « information » ou « important » (étiquette ; **la croix n'existe qu'après 10 s**, `BANDEAU_IMPORTANT_MS`), croix de 44 px, **texte posé en `textContent`** ; habillage par `--bandeau-fond`, `--bandeau-texte`, `--bandeau-bord` (les jeux y mettent leurs couleurs) ; clés `annonce.fermer`, `annonce.important` ; dans la vitrine `/ui/`. `src/visibilite.ts` : `visibiliteDeLaPage()` (`visible`, `surVisibilite`), **le seul endroit du socle qui lit `document.visibilityState`** (`@cdj/profile`, qui ne touche jamais au document, la reçoit en paramètre).
- `src/i18n.ts` — `traducteur(langue, ...catalogues)` : clés `zone.objet.detail`, paramètres `{nom}` (nombres au format de la langue), pluriels par `Intl.PluralRules` sur le paramètre `n` (`{ one, other }`). `src/formats.ts` — `formatTemps`, `formatNombre`, `formatRang`, `formatDate`, `formatDateCourte`, `formatNumeroJour`, `formatDecompte` (lot I5 : un compte à rebours « 07:42:09 » ou, sans les heures, « 42:09 » ; arrondi à la seconde au-dessus, jamais négatif ; Track et Jump), `majuscule` (espaces insécables U+00A0 ; aucune police de la charte n'a U+202F).
- `src/catalogue.ts` — le **catalogue commun** (composants, noms des jeux, **chaque code d'erreur du serveur** sous `erreur.<code>` : liste unique `apps/api/src/codesErreur.ts` ; lot I3 : `arrivee.jeuSuivant`, `arrivee.jeuSuivant.aria`, `arrivee.parfaite`, les clés de l'écran d'arrivée de chaque jeu ; **lot I5 : les répliques des thèmes de Jump**, `jump.replique.<thème>`, lues par le portail et par le jeu — une réplique ne vit qu'ici : `catalogues.test.ts` refuse une clé d'application contenant « replique » et toute copie mot pour mot). `src/contraste.ts` — les **paires texte / fond** déclarées et leur rapport WCAG.
- **Lot I6** : `src/dialogue.ts` — `suivreDialogue(écran, { ouvert?, observer?, focusInitial? })` : un écran en surimpression est un dialogue dont le focus entre à l'ouverture (sauf s'il s'ouvre **sous** un autre dialogue qui a le focus) et revient à la fermeture (à l'élément d'un autre écran qui l'a ouvert, sinon à l'écran resté dessous, sinon à la page : la partie reprend le clavier) ; posé d'office par `creerCadre` ; `[role=dialog][tabindex="-1"]` n'a pas de contour (socle.css). `src/mentions.ts` — `cheminMentions(langue, racine)` / `PAGES_MENTIONS` : la page des mentions de la langue (`mentions-legales/`, `legal/`). `src/catalogue.en.ts` — l'anglais du catalogue commun, **un module à part** (`CATALOGUE_COMMUN_EN`) que chaque jeu charge avec son anglais ; `CATALOGUE_COMMUN_FR` pour le premier chargement ; le portail garde `CATALOGUE_COMMUN` (les deux). `choixLangue` : le code court se voit, le nom de la langue se lit (pas d'`aria-label`).
- `outils/vite.ts` (Node, construction) — `pagesDuSocle` : textes du HTML pré-remplis depuis le catalogue (`data-t`, `data-t-<attr>`), couleurs des jetons (`data-jeton-<attr>`), icône d'onglet (`data-icone-du-jour`), préchargement des polices (`data-precharge-polices`).
- La **langue commune** (`cdj:langue`, détection, lecture, écriture) est dans `@cdj/profile` (`lireLangue`, `ecrireLangue`) : ce paquet ne touche ni au stockage ni à `navigator`.

## Consignes
- **Toute couleur, police, rayon, ombre et durée vient des jetons** (`var(--…)`) : aucune valeur en dur dans une feuille, un composant ou une application (test `jetons.test.ts`).
- **Aucune chaîne d'interface en dur** : toujours une clé de catalogue `fr` **et** `en` (parité : `catalogues.test.ts`) ; les noms propres passent aussi par le catalogue, ou portent une marque `i18n-ok: <raison>` (`chainesEnDur.test.ts`, dossiers vérifiés et catalogues des applications : `test/applications.ts` — **les lots I4 et I5 y ont ajouté leurs dossiers et catalogues** ; une même clé peut exister dans Track et dans Jump : les doublons se cherchent par application, catalogue commun compris).
- **Pas d'émoji dans l'interface** (seulement dans les lignes à partager) ; icônes SVG au trait, `currentColor`, `aria-hidden` si décoratives, `aria-label` si seules.
- **Ombres nettes seulement**, pas de dégradé de fond (seuls les motifs : stries, livrée), **pas de translucidité** (ni `opacity`, ni `rgba`, ni flou).
- **Cibles de 44 px**, **focus visible** (contour 3 px encre, ambre sur fond sombre : classe `dj-sombre`), mouvement réduit respecté, vrais éléments (`button`, `a`).
- **Ajouter un composant = l'ajouter à la vitrine `/ui/`** (`apps/portail/src/vitrine.ts`) dans tous ses états ; **ajouter une paire de couleurs = une ligne de `PAIRES`** (`src/contraste.ts`), qui doit passer le test de contraste (4,5:1 ; 3:1 pour 24 px et plus).
- **Lot I6 : une clé de catalogue jamais lue est refusée** (`test/clesUtilisees.test.ts` : nommée en clair dans le code ou le HTML de son application, ou sous un préfixe calculé `` `theme.${…}` `` ; sources par application : `SOURCES_DES_CLES` de `test/applications.ts`) ; **après tout changement de catalogue : `npm run traductions`** (`docs/plateforme/traductions.md`, relu par Nathan ; `test/traductions.test.ts` échoue s'il n'est pas à jour ; un nouveau catalogue d'application rejoint `CATALOGUES` **et** `scripts/traductions.ts`). Un texte lu seulement à la construction (balises de partage) vit dans un catalogue à part (`catalogue.apercu.ts`) pour ne rien peser dans le paquet.
- **Une modification de `packages/ui` relance les tests de toutes les applications** (`scripts/ci-scope.mjs` : les trois catégories).
- Tests : `npx vitest run packages/ui` (jetons, contrastes, formats, traduction, catalogues et codes d'erreur, chaînes en dur, polices) ; e2e du portail et de la vitrine : `apps/web/e2e/portail.spec.ts`.
