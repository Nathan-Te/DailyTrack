# `packages/core` (`@cdj/core`) : consignes

Socle sans logique de jeu (PRNG, calendrier, codage d'octets, sac de thèmes, date du lancement, règles des nouveautés et de l'interrupteur). Zone partagée. La « Règle du socle » (aucune dépendance, aucun `Date`, aucune transcendante, golden des jeux inchangés) est dans `packages/jump-sim/CLAUDE.md`.

## La fiche d'un jeu (lot K1)
- **`src/fiche.ts`** : le type `FicheJeu`, `validerFiche` / `lireFiche` (tous les problèmes d'un coup), `validerEnsemble` (identifiants, codes, ordres, tables uniques) et les **projections** — une par lecteur : `projectionPortail` (ce que le portail dessine, rien de plus : il l'embarque), `projectionServeur`, `projectionCI`, `projectionJeu`. Pur : aucun disque, aucun DOM. Lots K1b et K1c : **les trois jeux ont une fiche, `JEUX_SANS_FICHE` n'existe plus** ; le champ facultatif `dossiers` (`{ app, sim }`) et les noms hérités (`CHEMINS_HERITES`, `TABLES_HERITEES`, `PREFIXES_HERITES`, nommés un par un) permettent à Track (`apps/web`, `packages/sim`, `results`, `cdj:`…) de rester sous la règle « un jeu ne réclame que ses propres chemins ». Lot A3 : `categorie` (`jour` | `arcade`, obligatoire ; un jeu d'arcade exige `classement.cumul: false`) et `categorieDepuis` (facultatif, le premier jour de la catégorie : voir `categorieLe`, `@cdj/core/jeux`). Champs facultatifs ajoutés : `accrocheTheme`, `rejeu.ticksParUnite`, `e2e.regression`, `jours.registre`, `zones.documents`.
- **`src/ficheSorties.ts`** : ce que `npm run fiches` écrit — `config/jeux/projections/{portail,serveur,ci,jeu}.json` (lus par les scripts, le portail, les tests) et un `fiches.generated.ts` dans `core`, `profile`, `ui`, `musique` (ces paquets n'importent rien d'extérieur : pureté, `rootDir`). Les listes y sont **écrites en toutes lettres, identiques à ce que le code contenait** (ordre des fiches : Track, Jump, Tower) : un jeu ne grossit pas d'un octet. Le test `test/fiches.test.ts` recalcule les sorties et échoue si le dépôt n'est pas à jour (comme `jetons.css`).
- **Validation = garde de la règle des zones** : le lot d'un jeu écrit sa fiche ; la validation refuse des zones de CI, des tables (`<id>_…`), un préfixe de stockage, une destination de message ou des lignes de budget qui ne seraient pas ceux de ce jeu. Une règle nouvelle de la fiche s'ajoute ici avec son test.
- **Ajouter un champ** : le type, la validation, la projection qui le porte (la plus petite possible ; la projection du portail n'écrit que ce qui s'écarte de l'usage), les fiches des trois jeux, `npm run fiches`, un test. Ne jamais lire une fiche depuis un jeu : un jeu ne s'importe pas lui-même par la plateforme.

## Appareil bridé à 30 images/s (lot Q1)
`src/bridage.ts` (`@cdj/core/bridage`) : `bridePar30`, `DetecteurBridage` — pur, testé sous Node. Règle, usage et message au joueur : `docs/plateforme/bridage-30-images.md`.

## L'enveloppe de rediffusion commune (lot K4c)
- **`src/enveloppe.ts`** (`@cdj/core/enveloppe`) : `encoderEnveloppe` / `decoderEnveloppe`, `ErreurEnveloppe` (`format_illisible`, `version_inconnue`, `trop_longue`). Une rediffusion d'un **jeu neuf** = `[format 1][sim][générateur][genre : jour | scénario]` + le jour (ou le nom du scénario) + **la charge** (les octets que le jeu comprend seul), en `base64url` sans remplissage. Le texte est borné **avant** d'être lu ; les versions inconnues sont refusées ; jamais d'exception brute. **Les simulations existantes (Track, Jump, Tower) gardent leur format et ne sont pas touchées.**
- **Fiche** : le champ facultatif `donnees.tableCommune: "resultats_jeu"` dit qu'un jeu range ses résultats dans la table commune de la plateforme ; sa liste `tables` peut alors être vide (toute autre table doit toujours commencer par `<id>_`).

## Ce que le lot K4e ajoute à la fiche
- **`temoin?: boolean`** (jeu jamais en production ; aucune table à lui : `tables` vide et `tableCommune`) ; **`budget.aLaDemande?: string[]`** (préfixes de fichiers chargés à la demande, pour la mesure d'un jeu neuf) ; **`clesDeCatalogue(fiche)` / `clesManquantes(fiche, catalogues)`** (les clés de catalogue qu'une fiche exige, `JEUX_SANS_NOM_DE_THEME` : l'exception nommée de Track) ; les projections `serveur`, `ci` et `jeu` portent `temoin: true` ; `npm run fiches` écrit en plus les feuilles `*.generated.css`, `apps/api/src/registre.generated.ts` et `scripts/catalogues-jeux.generated.ts` (`sorties(fiches, existe)` reste pure : le disque est injecté).
- **Lire les fiches dans un test ou un script : `lireFichesBrutes` (`scripts/fiches-brutes.mjs`)**, qui ajoute, en essai seulement, les dossiers de `CDJ_FICHES_SUPPLEMENTAIRES` (le jeu fictif de `scripts/jeu-fictif.mjs`).

## L'identité d'un jeu (lot K5)
- **`identite: { police, motif, illustration, aujourdhui }`** (obligatoire) : la voix, le motif (`MOTIFS` : rayures, lignes, quadrillage, losanges, uni), l'illustration (`apps/<id>/public/illustration.svg`, ou `propre` pour Track et Jump qui gardent leurs cartes à la main) et le panneau « Aujourd'hui ». `A_CHOISIR` (« à choisir ») est la valeur d'un jeu neuf : `identiteComplete`, `etatPermis(fiche, etat)` (pas de `preview` ni de `on` sans identité complète), `projectionServeur.identiteIncomplete` (l'administration refuse). `etiquette.police` doit commencer par `identite.police`. `npm run fiches` écrit `packages/ui/src/identites/<id>.generated.css` pour chaque jeu générique (face de la police, motif en deux tons de la teinte : `tonsDuMotif`) et les règles de la carte du profil dans `apps/portail/src/jeux.generated.css`. Tests : `test/identite.test.ts`.

## Le contexte audio commun (lot S2)
`src/audio.ts` (`@cdj/core/audio`) : **`ouvrirContexteAudio`** est la seule façon d'ouvrir un contexte audio dans un jeu ou dans `@cdj/musique` ; il pose la session `ambient` (le son se mêle à celui du téléphone) puis crée le contexte (`null` sans Web Audio). Pur : l'environnement est un paramètre. Règle et test qui la garde : `CLAUDE.md` racine (« Le son d'un jeu se mêle à celui du téléphone »), `test/sonMelange.test.ts`.
