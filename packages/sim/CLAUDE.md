# DailyTrack — `packages/sim` : consignes de la simulation, du générateur et des circuits

Chargé quand on lit un fichier de `packages/sim`. Physique, blocs, rediffusions, générateur, thèmes, figures, déterminisme. Synthèse de DailyTrack : `docs/orchestration.md` (partir de là ; un README de `docs/lots/` seulement pour un détail). Autres consignes du jeu : `apps/web/CLAUDE.md` (rendu, interface, Salon côté jeu), `apps/api/CLAUDE.md` (classement, serveur, production).

> **Renvois « voir <rubrique> »** : une rubrique citée mais absente de ce fichier se trouve dans un autre `CLAUDE.md` du dépôt ; l'index des rubriques est dans le `CLAUDE.md` racine. Pour l'état d'ensemble, partir de la synthèse ; n'ouvrir un README de lot que pour un détail.

## Circuits (lot 2)
- Un circuit = un texte de blocs (`parseTrack`, voir `packages/sim/src/track.ts`) : cellules de 32 m, repère canonique (p = gauche, q = avance) tourné par quarts de tour ; hauteurs enchaînées automatiquement.
- `trackWorld(track)` donne `sample` (hauteur/pente/plaque) et `collide` (rebords) à `stepCar` ; `createRace`/`stepRace` ajoutent portes, chrono et reprises. Les commandes enregistrables sont `{ steer, throttle, brake, respawn }`.
- Tests navigateur : `?debug` expose `window.__cdj`. Scénarios : `?scenario=essai|pilotage|surfaces|largeurs|vitesse|glace|relief|cuves|air|bas-cotes|herbe|figures|plat`, `?scenario=figure-<nom>` (lot 49 : une figure en boucle ; `figures` ouvre d'abord la page des nouvelles figures).
- **Cuves (lot 18)** : `V` cuve droite, `ML` / `MR` mur latéral, `/c` sur un virage (`L2/c` : son mur extérieur) ; voir « Cuves (lot 18) ». **Les boucles restent exclues** (comme les tunnels fermés et les murs au plafond).

## Rediffusions (lot 3)
- Une rediffusion = `Replay` (séries de commandes) ; `encodeReplay`/`decodeReplay` ↔ texte base64url ; `replayRace` rejoue et renvoie le résultat recalculé. **Ne jamais faire confiance à un temps annoncé.**
- **`SIM_VERSION`** (constants.ts) : à incrémenter dès que la physique, un bloc ou un circuit change le résultat d'une course ; puis régénérer la rediffusion de référence : `UPDATE_GOLDEN=1 npx vitest run packages/sim/test/golden.test.ts`.
- `apps/web/src/session.ts` : `RunSession` avance course + enregistrement + fantôme ; `verify.html` : rejeu sans rendu pour les tests de navigateur (`npm run test:e2e`, Playwright ; `CHROMIUM_PATH` pour un Chromium déjà installé, `E2E_ALL_BROWSERS=1` pour Firefox et WebKit).

## Circuit du jour (lot 4)
- `dailyCircuit(jour)` (`generator.ts`) : graine = numéro de jour de la date (`parseDay`/`formatDay`, calendrier sans `Date` ; « aujourd'hui » = **la date à Paris**, voir « Jour de Paris (lot 31) ») ; `composeSpec` construit le texte, `bestPilotRun` (`autopilot.ts`) valide et donne le temps de l'auteur, d'où `medalsFor`. Id du circuit : `jour-AAAA-MM-JJ-g<G>` (variante 0), **`G` = la version du générateur de ce jour** (`generatorVersionOf(jour)`, lot R11 : celle du **registre des jours** `src/jours-track.json` pour un jour protégé, **la dernière** pour un jour qu'il ne nomme pas — voir « Registre des jours (lot R11) » ci-dessous) ; voir « Admin et planning » et « Freinage après un boost (lot 34) ».
- **`GENERATOR_VERSION`** (constants.ts) : à incrémenter dès que le circuit d'une date change (règles, pilote, fenêtre de durée) ; puis régénérer `fixtures/daily-golden.json` (`UPDATE_GOLDEN=1 npx vitest run packages/sim/test/golden-daily.test.ts`, qui refuse de réécrire un vecteur d'une ancienne version). **Depuis le lot R11, plus aucune date de bascule dans le code** : monter la version suffit ; la version d'un jour déjà servi est celle du registre (voir « Registre des jours (lot R11) »), et c'est la mise en production qui décide du premier jour de la nouvelle version.
- Web : `?mode=salon` (Salon, lot 26), `?seed=AAAA-MM-JJ` (ou `?day=`), `?theme=<nom>`, `?api=demo`, `?scenario=essai|pilotage|surfaces|largeurs|plat`, `?debug&tune` (réglages), touche **C** (caméra : proche, loin, capot ; lot 23). Palettes dans `apps/web/src/trackMesh.ts` (`PALETTE_DEFS`).
- **`npm run measure:generator`** (`apps/api/scripts/measure-generator.ts`) : durées d'auteur, largeurs, virages serrés, temps de génération et de rejeu sur 60 dates, taux de validation par thème (12 dates × 6 tentatives, thème forcé), bas-côtés et moments de choix par thème (lot 21). **Toute règle de générateur se valide par ce script (durées, taux de validation par thème), pas seulement par les tests.** `FAST=1` pour un passage rapide ; résultats de référence dans `docs/lots/lot-12-circuits-amples.md`.

## Conduite (lot 7)
- `packages/sim/src/car.ts` : modèle **bicyclette** (deux essieux, force latérale saturée par `tireCurve`) + **4 ressorts** posés sur `world` (hauteur, tangage, roulis en pentes ; charge → adhérence ; butée) + **balistique** en l'air (voir « Air » ci-dessous). 2 sous-pas fixes par pas. Rebords : deux disques, impulsion avec rebond et frottement. Dérapage au frein (`car.drift`). Détail et mesures : `docs/lots/lot-7-conduite.md`.
- **`CarParams`** (`DEFAULT_CAR_PARAMS`) passé à `stepCar(car, input, world, params)` et `createRace(track, params)` ; le serveur et les rediffusions utilisent toujours les défauts. **`SurfaceParams`** `{ grip, traction, rolling }` lu sous chaque roue par `surfaceAt(échantillon)` (`world.ts`, table `SURFACES`, « route » seulement).
- Reprise = état de la voiture au passage du dernier point de contrôle (`race.checkpoints`). Virage large `L2`/`R2` (2 × 2 cellules, `blockCells`).
- Pilote (`autopilot.ts`) : trajectoire lissée (`racingLine`), vitesses par courbure, freinage anticipé ; `PILOT_GRIPS`.
- **Contact par la normale (lot 18)** : dans un bloc de cuve la voiture quitte le modèle à ressorts : `stepCar` appelle `world.shell(x, z, y, hit)` et, s'il répond, `substepShell` (car.ts) — voir « Cuves (lot 18) ».
- Web : panneau `?debug&tune` (`apps/web/src/tune.ts`) — une course avec réglages modifiés n'est **jamais** enregistrée ni classée ; caméras proche/loin (touche **C**, bouton Vue de la manette) ; `?scenario=pilotage`.
- **Réglages par défaut = ceux de Nathan (retouche 7b, `docs/lots/lot-7b-reglages.md`)** : pointe 48 m/s, grip 44 / 47, seuil de glisse 0,14, dérapage doux (angle 0,32, serrage 33), gravité 24,6, rebords durs (rebond 0,6, frottement 0,3). `SIM_VERSION` et `GENERATOR_VERSION` valaient 3 au 7b ; le lot 8 les passe à 4, le lot 12 à 5, le lot 15 à **6**.
- Générateur : **deux lignes droites derrière chaque plaque** (`PAD_RUNOUT`, generator.ts) — à 48 m/s, une plaque suivie d'un virage serré ne se prend pas (frein 40 contre poussée 30 pendant 0,9 s). Le circuit d'essai suit la même règle. Pilote : marge aux rebords de 3,6 m (`WALL_MARGIN`).
- **Vitesse au-delà de la pointe (lot 15)** : la pointe du plat reste **48 m/s** mais n'est **plus un plafond dur** : au-delà, **traînée en cube** `overspeedDrag × ((u ÷ pointe)³ − 1)` (2,5 ; remplace l'ancienne décélération constante de 14 m/s²), appliquée aussi sous plaque et turbo. La gravité (`slopeGravity` **40**, pente 0,125 par bloc de descente) et les poussées vont plus haut : **plaque 66 m/s** (`boostMaxSpeed`), **super turbo 88 m/s** (`turboMaxSpeed`, ≈ 317 km/h) ; la voiture retombe progressivement (88 → 61 m/s en 5 s). Un virage reste limité par l'adhérence (R3 ≈ 60 m/s, L2 ≈ 43, serré ≈ 26). **Garde-fou anti-traversée** : aucun changement de pas (0,375 m par sous-pas à 88 m/s pour un disque de 1 m) ; `vitesse.test.ts` fait heurter des rebords à 88 m/s (angles de 5° à 60°, de face dans un virage, braquage à fond, transition de largeur) et exige que la voiture reste sur la route à chaque pas. **Toute nouvelle poussée ou nouveau relief qui augmente la vitesse maximale doit rejoindre ce test.** Panneau `?debug&tune` : `overspeedDrag`, `boostMaxSpeed`, `turboMaxSpeed`, `slopeGravity`.
- **Chute et reprise automatique (lot 17)** : sous `track.voidY` la voiture tombe sans commande `FALL_TICKS` pas (0,5 s) puis reprend au dernier point de contrôle, chrono qui continue (voir « Relief, sauts et chute »).
- **Cuves rapides (retouche 18b, `docs/lots/lot-18b-cuves-rapides.md`)** : sur une paroi (`substepShell`), la pesanteur n'est pas symétrique — la montée coûte `shellClimb` (0,4) de la pesanteur tant qu'elle n'est pas franche, la descente pousse `shellDescent` (2,6) fois, avec un surplus éteint vers `shellGainTop` (56 m/s) — et la paroi est une **voie rapide** (pointe `shellTop` 1,15 × 48 m/s, poussée `shellPush` 14 m/s² sous cette pointe). **Garde-fou anti-zigzag** : au-delà de `shellGainTop` de vitesse totale une traînée (3 /s) ramène la voiture, et la descente n'ajoute plus rien (un zigzag dans 14 blocs de cuve reste sous 62 m/s à plat, test `cuves-rapides.test.ts`). Les cinq clés sont dans `CarParams` et `?debug&tune`. Pilote : il « pompe » les cuves droites (`STRAIGHT_UP` / `STRAIGHT_DOWN`, bouts libres) et prend la paroi des virages en cuve ; la relaxation longue de la trajectoire ne vaut qu'à `CUVE_NEAR` blocs d'une cuve. Générateur : cuve droite de 6 blocs + 4 droites (`CUVE_RUN`, `CUVE_RUNOUT`), virage en cuve large ou ample (plus de serré). `SIM_VERSION` et `GENERATOR_VERSION` : **10** à la 18b (**12 et 13** depuis le lot 21).
- Tests de comportement chiffrés : `packages/sim/test/conduite.test.ts` (seuils recopiés dans le README du lot, mis à jour au 7b), `vitesse.test.ts` (lot 15, seuils dans `docs/lots/lot-15-vitesse.md`).

## Air et atterrissages (lot 19)
- **Réception** (`land`, `car.ts`) : au premier contact après un vol (≥ `LANDING_MIN_AIR` sous-pas), la vitesse **normale** au sol est absorbée (`landAbsorb` 0,95 : aucun rebond) et la vitesse **tangentielle** garde `1 − landLoss × (écart d'alignement − landTolerance)` (plancher 0,4), l'écart étant |tangage − pente du sol| + |roulis − pente latérale| (pentes, jamais d'angles). Mêmes règles dans une cuve (`landOnShell`) ; la voiture se pose à plat sur la paroi.
- **Rotation héritée** : en l'air la caisse garde tangage, roulis et lacet (`airDamping` 0,4 /s) ; plus de retour à l'horizontale (`airLevel` supprimé). Un vol de moins de `HOP_SUBSTEPS` (6 sous-pas : bosse, frôlement de paroi) garde l'ancien amortissement fort. Pentes bornées à ±1,6 (`AIR_TILT_MAX`). En quittant une paroi (`leaveShell`) seule la **vitesse de rotation** de la courbure est héritée (bornée à 1,5 pente/s), jamais l'inclinaison : une caisse couchée par une paroi verticale lirait ses roues sous la route comme un mur (`STEP_UP`).
- **Frein en l'air = figer** : l'amortissement de la rotation passe à `airDamping + airFreeze × frein` (`airFreeze` 14 /s : < 5 % de la vitesse angulaire en 0,3 s) ; il ne ralentit pas la voiture (rien du moteur ni des freins n'agit en l'air). Accélérateur et direction sont sans effet en l'air.
- **Pilote** : `needsFreeze(car)` (autopilot.ts) = en vol (≥ 6 sous-pas) et la caisse tourne (> 0,12 /s) ; le pilote freine alors. Les tests de saut et de tremplin l'utilisent aussi (un joueur correct fait pareil). Après l'arrivée, une voiture qui repart en arrière freine aussi (`FINISH_REVERSE_BRAKE`, race.ts).
- **Clés de `CarParams`** (toutes dans `?debug&tune`) : `airDamping`, `airFreeze`, `landAbsorb`, `landTolerance` (0,3), `landLoss` (0,7). `landBounce` et `airLevel` n'existent plus. `SIM_VERSION` : **11** ; `GENERATOR_VERSION` : **12** depuis le lot 20 (figures) ; **12 et 13** depuis le lot 21 (bas-côtés).
- **Web** (présentation seule) : indicateur « ❄ FIGÉ » (`#freeze`) tant que le frein agit en vol, caméra qui suit la **direction du déplacement** en vol (`airMix`), son de réception selon sa qualité (`landingQuality` / `landingSound`, audioLogic.ts), secousse plus forte pour une mauvaise réception. `__cdj.air` expose `{ frozen, lastLanding, cameraMix }`.
- Scénario `?scenario=air` (`createAirTrack`, circuits.ts) : dos d'âne à haute vitesse, tremplin `J`, long saut au super turbo, saut vers un virage relevé, chute de trois niveaux, mur latéral quitté en l'air. Tests : `packages/sim/test/air.test.ts` (seuils recopiés dans `docs/lots/lot-19-air.md`), `e2e/air.spec.ts`.

## Surfaces et blocs à effet (lot 8)
- **Revêtement = attribut d'un bloc** (`Block.surface`, notation `S/t` terre, `S/g` glace, `S/h` herbe, `S/s` sable (lot 22) ; `/b` = virage relevé : `L2/b`, `R/tb`) ; `parseToken` (`track.ts`) lit la notation. `SURFACES` (`world.ts`) : `{ grip, traction, rolling, slick }` — route `1/1/0`, terre `0,7/0,85/1,5`, herbe `0,5/0,55/7`, glace `0,3/0,4/0` (`slick` 1 : lot 16) ; `surfaceAt(échantillon)` les lit sous chaque roue (adhérence latérale ← grip ; motricité et freinage ← traction ; roulement en m/s²). **Où en ajouter un** : `SurfaceKind` + `SURFACE_LETTERS` (track.ts), une ligne de `SURFACES`, ses couleurs dans `trackMesh.ts` (`SURFACE_COLORS`, `SURFACE_MARKS`), `SURFACE_HUD` (main.ts). **Nouvelle surface ou nouveau bloc = `SIM_VERSION` +1** (et `GENERATOR_VERSION` si le pilote ou le générateur s'en sert) — **sauf depuis le lot 48 pour une surface (ou un bloc) qu'aucun circuit existant n'utilise** : voir « Herbe de course (lot 48) ».
- **Blocs à effet** : `P` plaque, `T` super turbo (`turboTicks` 180, `turboAccel` 42, `turboMaxSpeed` 68 : trois clés de `CarParams`), `C` moteur coupé (`car.cut` : l'accélérateur n'agit plus ; `stepRace` le rend au pas exact qui franchit le point de contrôle suivant). Les états `boost`, `turbo`, `cut` vivent dans `CarState` (donc rejoués à l'identique) ; après l'arrivée les effets sont coupés (`withoutEffects`).
- **Virages relevés** : `bankAt` (track.ts) donne hauteur et gradient du relevé (pente 0,3 serré / 0,22 large, rampe = `BANK_RAMP_ARC` 0,5 de l'arc, profil quintique `bankFactor` : pente et courbure nulles à l'entrée et à la sortie — lot 24, plus de tremplin ; `SIM_VERSION` 14 / `GENERATOR_VERSION` 15) ; `world.sample` les ajoute à la hauteur et au gradient ; `collide` compare au sol réel ; la voiture reçoit la pente latérale (`ay -= gravity × pente`). Rendu : `trackMesh.ts` (`arcPoint` suit le relevé).
- **Pilote** : `racingLine` module vitesse de passage (grip × revêtement + g × pente) et freinage (traction × revêtement + roulement) ; il reste à 1,5 m de l'axe en virage relevé. Générateur : `PAD_RUNOUT` (2 droites derrière une plaque) et `TURBO_RUNOUT` (5 derrière un super turbo).
- Tests : `packages/sim/test/surfaces.test.ts` (seuils recopiés dans `docs/lots/lot-8-surfaces-themes.md`), `e2e/surfaces.spec.ts`. Outils : `?scenario=surfaces`, `?theme=<stade|rallye|banquise|nuit|campagne|canyon|col|ville>`.
- **Revêtement selon la position en travers (lot 21)** : `world.sample` rend le revêtement **du point** (`Surface.kind`) : la route du bloc, un **vibreur** (`kerb`, bandes de `KERB_WIDTH` 1,5 m aux deux bords d'un virage sur route : **exactement l'adhérence de la route**, seuls le son, la vibration et la caméra changent) ou un **bas-côté**. `SurfaceKind` (sous les roues) ⊃ `BlockSurface` (attribut `S/t`…). Le **sable** (lot 22) est à la fois revêtement de bloc (`S/s`) et bas-côté (`~s`).
- **Bas-côtés (lot 21)** : **bord = attribut de bloc chaîné comme la largeur** (`Block.shoulder`, `Block.open`) : `~h` herbe, `~t` terre et gravier (`gravel`), `~p` neige poudreuse (`snow`), `~v` vide (sans rebords, comme `o`), `~r` retour aux rebords (`S/n~h`, `L2/~t`) ; `o` reste « ce bloc seul sans rebords ». Un bloc qui ne peut pas en porter garde ses rebords **sans casser la chaîne** (départ, arrivée, cuve, vide, rampe, tremplin ; et pour une bande : montée, virage relevé, descente de trois niveaux). La bande va du bord de la route à `SHOULDER_EDGE` = 15 m de l'axe (8 / 5 / 2 m de large sur 14 / 20 / 26 m) où **un rebord ordinaire** l'arrête (« au-delà : un rebord », décidé) ; là où la bande s'arrête contre un bloc plus étroit, une **face de bout** (segment, nez arrondi : `endFaces`, world.ts) ; la porte d'un point de contrôle couvre la bande. Revêtements (`SURFACES`) : terre et gravier `0,6/0,65/4,5`, herbe `0,5/0,55/7`, neige poudreuse `0,42/0,5/8` ; **ordre de ralentissement : gravier < herbe < neige** (pointes 38 / 27 / 20 m/s), jamais de chute ni de calage à plat (`basCotes.test.ts`).
- **Route bosselée (lot 21)** : modificateur `u` (droites, pentes, blocs à effet) : tôle ondulée en travers, bosses de `RIPPLE_HEIGHT` 0,15 m tous les `RIPPLE_LENGTH` 6 m, effacées sur la première et la dernière période (`rippleAt`, polynômes) ; `world.sample` l'ajoute à la hauteur et à la pente, pas `blockHeight`. Effet mesuré : freinage +16 %, réponse latérale −40 %, pointe presque intacte.

## Herbe de course (lot 48)
README : `docs/lots/lot-48-herbe.md` (l'existant, les paramètres et les tests chiffrés, la mesure sur 20 Campagne avant / après, la bascule).
- **Règle : une surface nouvelle plutôt qu'un ancien paramètre changé.** L'herbe d'avant (`grass` : zones des anciens circuits et bas-côtés `~h`) garde ses valeurs au bit près ; le nouveau comportement a son identifiant (`turf`, notation **`S/z`**, `SURFACE_LETTERS`, `SURFACE_MOD`). **`SIM_VERSION` reste 14** : aucun circuit enregistré n'a de `z`, et l'incrémenter rendrait injouables toutes les rediffusions gardées (`replay.ts` refuse une autre version : classements, « revoir le meilleur tour »). Preuve : golden, rediffusions de référence et 88 circuits du 13/10 au 03/11 identiques octet pour octet. Un ancien paramètre changé, lui, incrémente toujours `SIM_VERSION`.
- **L'esprit (décision de Nathan, 25/10/2026)** : la voiture lancée sur l'herbe de course **garde sa vitesse si elle tient sa trajectoire** ; **braquer y coûte de la vitesse** ; on entre avec sa trajectoire et on la tient pendant le bloc, la voiture glissant légèrement vers l'extérieur selon sa vitesse. **Le frein y freine, c'est tout** : il ne lance jamais le dérapage du lot 7 (`stepCar` lit le sol sous la voiture au moment où il se déclencherait), et un dérapage venu de la route s'y éteint (comme volant lâché). Écartés après essai : un dérapage qui se lançait tout seul, puis une glisse au frein « à la Trackmania » (la voiture rebondissait et pivotait d'un coup).
- **Paramètres** : `SURFACES.turf` = `{ grip 0,8, traction 0,85, rolling 0,6, slick 0, turf 1 }` (lus par le pilote, le générateur, `braking.ts`) ; `SurfaceParams.turf` (part du comportement, 0 partout ailleurs) ; **neuf clés de `CarParams`**, toutes dans `?debug&tune` : `turfGrip`, `turfTraction`, `turfRolling` (les trois valeurs de la table, que la voiture lit à leur place sous une roue d'herbe de course), `turfRear` 1 (l'arrière tient autant que l'avant), **`turfKeel`** 1 (un rappel amorti ramène le nez dans l'axe de la vitesse : le rappel du dérapage, visé à 0 — la voiture suit sa ligne, ne pivote pas, même au frein volant à fond), **`turfSteerDrag`** 8 m/s² (braquer freine, en proportion du volant), `turfSlideDrag` 1,5 (× `slideDrag`), `turfSlideFree` 0,08 et `turfScrub` 60 (au-delà de cette dérive, un coût en carré). Dans `car.ts`, tout passe par des branches « herbe de course » : les autres revêtements font exactement les mêmes calculs qu'avant.
- **Mesuré** (`test/herbe.test.ts`, seuils dans le README) : pointe 97–99 % de la route (≈ 47 m/s ; l'herbe d'avant 57 %), 0 → 100 km/h 10–30 % plus long, 128 m d'herbe à fond < 0,1 s ; lancée à 62 m/s, elle ralentit comme sur la route ; volant à fond 2 s : la vitesse tourne < 85 % de la route (73° contre 93°), dérive < 6° ; volant 0,2 / 0,5 / 1 : 1,5 / 3 / 7 m/s de plus perdus que sur la route ; frein et volant à fond : aucun dérapage, dérive < 15° ; virages du pilote plus coûteux que sur la route, moins que sur l'herbe d'avant ; passages route ↔ herbe pas plus brusques que route ↔ terre ; aucun blocage.
- **Générateur v17** (lot R11 : plus de date de bascule ; `GENERATOR_BEFORE_48` = 16 est la version d'avant) : `themeOfVersion(thème, version)` (themes.ts) — **Campagne** : zones `turf` 3 / `dirt` 1, l'une des trois figures d'herbe toujours là (`Theme.figures.requireAlso`, `TURF_FIGURES` : `ample-herbe`, `chicane-herbe`, `droite-herbe`, `only: ["campagne"]`, **`since: 17`** — `Figure.since` : un générateur plus ancien ne les tire pas) ; une zone d'herbe de course se pose **sur des lignes droites et des pentes** là où trois blocs de suite peuvent la porter (`turfZone` ; les approches protégées du lot 34 gardent la route). **Les autres thèmes sont identiques en v17** (testé, à l'identifiant près). Mesure (`HERBE=1 npm run measure:generator`, section 4) : 20 Campagne d'après la bascule, 11,7 % des blocs (2,5 % avant), 20 circuits sur 20 (8 avant), 0,72 s perdues par le pilote. **Prochaine version** : monter `GENERATOR_VERSION`, `themeOfVersion` ou `since` pour ce qui ne vaut qu'à partir d'elle ; aucune date.
- Scénario `?scenario=herbe` (`HERBE_TRACK_SPEC`, `createHerbeTrack`, circuits.ts ; palette de la Campagne).

## Générateur : identité des thèmes, nouvelles figures, variété (lot 49)
README : `docs/lots/lot-49-identite-gameplay.md` (l'état des lieux, les mesures avant / après, la bascule) ; **fiches d'identité validées par Nathan** : [`docs/lots/lot-49-identite/fiches.md`](../../docs/lots/lot-49-identite/fiches.md) (au volant, surfaces, figures signatures, rythme, ce que le thème ne fait jamais).
- **Générateur v18** (lot R11 : plus de date de bascule ; `GENERATOR_BEFORE_49` = 17 est la version d'avant ; la v17 n'a servi aucun jour). La rotation des vedettes compte les apparitions d'un thème depuis **`ANCRE_V18`** (generator.ts, le 04/11/2026 — **une ancre de la v18, pas une date de bascule : elle ne bouge jamais**, sinon les jours de la v18 changeraient) ; **avant l'ancre elles se comptent à rebours** (−1, −2…), pour que la variété garantie tienne quel que soit le premier jour servi par la v18. Les jours d'avant gardent leur circuit au bit près (golden, 88 circuits du 13/10 au 03/11 comparés à `main`). `SIM_VERSION` reste 14 : aucune physique nouvelle ; le pilote et `trackJumps` n'ont changé que pour un virage posé **juste derrière un vide**, qu'aucun circuit d'avant n'a.
- **Les fiches dans le générateur** : `themesVersion.ts` (hors du premier chargement : seuls le générateur et les tests l'importent ; il porte aussi la table du lot 48) — `themeOfVersion(thème, version)` ajoute en v18 les **favorites** de la fiche, ses **interdits** (`TURBO_FIGURES` au Rallye, à la Banquise et à la Campagne, et **aucune variante qui pose un `T`** dans un thème sans super turbo), ses **vedettes** (`Theme.figures.vedettes`, 3 ou 4 par thème) et un peu plus de terre (Rallye) et de glace (Banquise). **Changer un thème à partir d'une version = une entrée de `themesVersion.ts`, jamais une valeur de `THEMES`.**
- **Les douze nouvelles figures** (`FIGURES_LOT49`, `since: 18` : un générateur plus ancien ne les tire pas) : six sauts techniques — `saut-sortie-virage` (sans plaque, l'élan du virage), `tremplin-releve` (rampe en sortie de relevé : on décolle en tournant, figer au frein), `chicane-tremplin`, `reception-virage` (on retombe au début d'un virage **ample** : `trackJumps` compte `CURVE_LANDING` = 32 m de réception, fenêtre ≈ 33–43 m/s ; le pilote part de l'axe et s'en écarte sur la première moitié de l'arc ; un virage large derrière un vide n'est pas pris par le pilote, ne pas en écrire), `saut-glace`, `saut-falaise` — et `bosses-terre`, `demi-tour-mixte`, `demi-tour-glace`, `rues-en-escalier`, `fil-du-rasoir`, `devers-descente`. Toutes en **blocs existants** ; chacune finie par le pilote dans chaque variante, les deux sens et les trois largeurs (`figures.test.ts`), posée sans faute (règles du lot 37 : `apps/web/test/decorPose.test.ts`), et jouable seule : `?scenario=figure-<nom>` (`&v=1`, `&m=1`). **Un saut sans plaque n'a pas de virage imposé derrière sa réception** (`turned` vise les sorties à plus de 55 m/s).
- **Règles de composition en v18** (`selectFigures`, `composeFigures`) : la **vedette du jour** est toujours là (jamais au repos, jamais remplacée à la pose) et tient lieu d'une des deux techniques exigées ; le **freinage franc** se prend d'abord parmi les figures qui font aussi la portion rapide (une figure générique de moins), et peut être pris parmi les figures au repos si aucune autre ne convient ; le poids ×2 des figures à freinage ne vaut plus pour un thème à vedettes ; **un saut peut ouvrir le circuit** (deux droites d'élan de plus) **ou le finir** (sa réception mène à l'arrivée) quand aucun ordre ne l'évite ; une tentative de **Nuit** sans route sans rebords est refusée ; **tri des tentatives** (`QUICK_SLACK_MS`) : la course de la plus haute adhérence roule seule d'abord, une tentative qu'elle finit à plus de 40,5 s est refusée sans les autres courses (`bestPilotRun(…, { first })` la reprend sinon : sans ce tri, le test de durée de génération échouait en CI). Mesuré : sans ces règles, la vedette rendait les circuits trop longs (jusqu'à 15 jours de Stade sur 25 sans circuit valide).
- **Variété garantie** : `themeOccurrence(jour, thème)` = le numéro d'apparition du thème depuis l'ancre `ANCRE_V18` (négatif avant elle ; `themeForDay` jour après jour ; le Salon : sa session). Deux circuits consécutifs d'un même thème ont des numéros qui se suivent : (1) **la vedette** `vedettes[k mod n]` (`vedetteOf`), les autres attendent leur tour ; (2) **le tiers au repos** (`isRested`) suit `k + ⌊k / n⌋` (il change d'une apparition à l'autre, et entre k et k + n) ; (3) **l'ordre** : un **tournoi fixe** par thème (`follows` : un sens par paire de figures, empreinte du thème et de la paire) — une apparition paire n'enchaîne deux figures que dans ce sens, une impaire que dans l'autre, donc **deux circuits consécutifs d'un même thème ne partagent aucun enchaînement de deux figures** (une remplaçante à la pose suit la même règle, `keepsOrder`). L'ordre reste tiré au hasard parmi ceux qui conviennent (insertion : il en existe toujours un). Un tri fixe aurait donné le même ordre à deux circuits de même parité qui ont les mêmes figures (mesuré : la ressemblance dans un même thème montait).
- **La mesure de ressemblance** (`ressemblance.ts`, pure, testée) : moyenne de deux indices de Jaccard — les figures et leurs enchaînements (`empreinte`), et les suites de quatre **formes** de blocs (`shapesOf` : sans largeur, repère, bas-côté ni sens absolu). **La relancer** : `IDENTITE=1 npm run measure:generator` (section 5 : 25 circuits par thème à partir de `IDENTITE_FROM`, la bascule par défaut ; `IDENTITE_GEN=17` pour l'avant ; `IDENTITE_N`) — figures par thème, sauts et leur approche (« boost puis rampe en ligne droite »…), vitesse, virages, revêtements, ressemblance (même thème, thèmes différents, jours consécutifs d'un même thème, jours qui se suivent au calendrier) et paires les plus semblables. Avant → après (200 circuits) : entre thèmes 0,091 → 0,059, toutes paires 0,102 → 0,074, jours consécutifs d'un même thème 0,179 → 0,136 (pire 0,750 → 0,308), enchaînements partagés 26 paires → 0 ; même thème 0,187 → 0,179 (les fiches resserrent chaque thème : voir le README).
- **Tests** : `identite-a.test.ts` / `identite-b.test.ts` (`helpers/identite.ts` : 60 circuits par thème après la bascule, fenêtre 30–40 s et or sous 45 s, chaque nouvelle figure générée dans ses thèmes, vedettes, aucun enchaînement commun, aucun super turbo là où il n'y en a pas, Salon), `identite-avant-apres.test.ts` (ressemblance et temps de génération v17 → v18 sur les mêmes jours), `golden-daily.test.ts` (un jour d'après la bascule par thème), `ressemblance.test.ts`.

- **Garde-fous mesurés** : 365 graines validées par le pilote (`test/variete365.test.ts`, et 3 × 365 jours à la main : aucun secours) ; temps du pilote 30,9–40,0 s (v20 : 30,4–39,9 ; médiane 37,8 contre 37,9) ; génération : moyenne comparable (≈ 2,3 tentatives par jour contre 2,0), pire jour sur trois années 1 667 ms en local contre 1 074 en v20. **Un trait de fiche qui allonge les circuits coûte des tentatives** : à 100 % de courbes amples au Stade et avec des sauts ×1,8 à la Nuit, le pire jour valait 3,6 s en CI ; mesurer le pire jour (pas la moyenne) après tout changement de fiche. ## Sac de thèmes : jamais deux jours de suite le même thème (lot V1)
README : `docs/plateforme/lots/lot-V1-themes-sans-repetition.md`. **Générateur 20** (`GENERATOR_VERSION`, `GENERATOR_SAC_THEMES` de `dailyId.ts`) ; `SIM_VERSION` inchangée (14) ; les circuits ne changent que par leur thème (et `MAX_ATTEMPTS_SAC`, plus bas).
- **La règle, commune aux deux jeux, écrite une fois** : `packages/core/src/sacThemes.ts` (`themeDuSac`, `ordreDuCycle` ; aucune logique de jeu, des indices de thèmes et des numéros de jour). Les jours se découpent en **cycles de n jours** (n = 8 thèmes) **alignés sur le numéro de jour** (`⌊jour ÷ n⌋`, aucune date écrite) ; dans chaque cycle chaque thème sort **une fois**, dans un ordre tiré de la graine (`mixSeed(cycle, sel)`) ; **à la jonction de deux cycles** le dernier thème du cycle d'avant ne revient pas avant le 3ᵉ jour et l'avant-dernier pas le 1ᵉʳ (seules les deux premières places sont réordonnées : jamais deux jours de suite, jamais A B A) ; deux apparitions d'un thème sont séparées de **2n − 1 jours au plus**. Le calcul d'un jour est **direct** (trois cycles, mis en cache), jamais « rejouer les jours depuis l'ouverture ».
- **`themeForDay(jour, version = generatorVersionOf(jour))`** (themes.ts) : version < 20 → l'**ancienne règle** (`themeAncien`, un tirage indépendant par date, qui pouvait répéter la veille ; ne change jamais : c'est le thème de tout jour déjà servi) ; sinon le sac. **Un jour est « ancien » quand le registre (`jours-track.json`, `generatorVersionOf`) lui donne une version d'avant le sac** : le **premier jour du sac** (celui dont la veille est ancienne) lit donc le thème de la veille dans le registre et évite le thème de la veille et de l'avant-veille ; le suivant évite celui de l'avant-veille (`resolu`, `sacThemes.ts` : seuls ces deux jours-là, au plus, sont remplacés par un autre thème tiré de la date). Aucune date écrite : la bascule se lit dans le registre que « Mettre en production » écrit.
- **Un test ou une mesure d'une ancienne version impose sa version** (`dailyCircuit(jour, 0, null, 18)`, `themeForDay(jour, 18)`, `themeOccurrence(jour, thème, 18)`) : sans cela le thème du jour serait celui du sac. `themeOccurrence` (rotation des vedettes, lot 49) compte les apparitions avec l'ancienne règle pour une version d'avant le sac, avec le thème réellement servi (`themeForDay(d)`) pour la v20.
- **Budget de tentatives** : `MAX_ATTEMPTS_SAC` = **120** pour la v20 (40 pour les versions d'avant : un jour de secours ou une tentative retenue d'une ancienne version ne bouge pas). Mesuré sur 365 jours : un seul jour (Banquise, 02/12/2026) épuisait 40 tentatives ; il aboutit à la 51ᵉ.
- **Un nouveau thème s'ajoute au sac ; la règle ne change pas** : `THEME_NAMES` + `THEMES` (voir « Thèmes (lot 8) ») changent n, donc les cycles de tous les jours **qui suivent le sac** : monter `GENERATOR_VERSION` (comme tout changement de thème). Au moins cinq thèmes (`ordreDuCycle` lève sinon).
- **Mesure** : `npm run mesure:themes` (`scripts/mesure-themes.ts` ; `-- --niveaux` : la validité des 365 niveaux des deux jeux). Tests : `packages/core/test/sacThemes.test.ts` (la règle, n = 5 et 8), `registreJours.test.ts` (rotation des vedettes en v20), `golden-daily.test.ts` (un vecteur par thème de la dernière version).

## Largeurs de route et courbes amples (lot 12)
- **Largeur = attribut de bloc** (`Block.w0` entrée, `Block.w1` sortie, en m) : `e` étroite 14 m, `n` normale 20 m, `l` large 26 m (`ROAD_WIDTHS`, track.ts), dans une cellule de 32 m. Notation : `S/n` (constante), `S/e>l` (**bloc de transition**), combinable (`S/n>et`, `L3/lb`). **Chaînée comme les hauteurs** : un bloc sans largeur garde la sortie du précédent (14 m au départ, comme avant) ; une largeur écrite doit la prolonger exactement (`parseTrack` refuse « marche de largeur ») ; seul le premier bloc choisit la sienne. Un virage garde sa largeur (pas de transition dans un virage).
- **Transition** : une droite de 32 m dont la demi-largeur suit un lissage cubique (`blockHalfWidth`, `blockHalfWidthSlope` : pente nulle aux deux bouts, 0,28 au plus) ; `world.sample` l'utilise, `collide` incline la normale du rebord (`√(1 + pente²)`), le générateur ne fait qu'**un cran à la fois** (14 ↔ 20 ↔ 26). Les **plaques** (P, T) font la moitié de la largeur de la route (`blockPadHalfWidth`, 3,5 m de demi-largeur sur 14 m : inchangé) ; `Gate.halfWidth` donne la largeur de la porte (course : tolérance + 2 m) ; le rendu (`trackMesh.ts`) suit : rebords, sillons, damier, portes, tremplin, moteur coupé.
- **Virage ample `L3` / `R3`** (3 × 3 cellules, rayon d'axe 80 m, `curveSize`) : huit cellules réservées (le coin intérieur n'est jamais touché par la route), sortie à 3 colonnes et 2 rangées. Un **virage serré** (rayon 16 m) tient jusqu'à 26 m de large (rayon intérieur 3 m) mais **le générateur n'en met pas sur la route large**.
- **Générateur** (`generator.ts`, `themes.ts`) : 5 à 7 créneaux calme + virage ; virages **larges (L2/R2) ou amples** le plus souvent, S larges (`L2 R2`), demi-tours larges (`L2 L2`) ; **au plus 2 virages serrés par circuit** (passage signature compris), **jamais deux de suite**, jamais sur la route large ; **au moins deux largeurs** par circuit (sinon la tentative échoue), largeur de départ et changements tirés selon `Theme.widths` : *Stade* et *Banquise* plutôt larges (poids 6/5 pour 26 m), *Rallye* et *Campagne* plutôt étroits, *Nuit* mélangé (2 à 3 changements). **Signatures** : Banquise = chicane large sur glace (`iceChicane`), Campagne = **étranglement** (`dirtPinch` : la route se resserre à 14 m puis un virage serré sur la terre, puis s'élargit à nouveau). **Fenêtre du temps de l'auteur : 30–40 s** (`AUTHOR_MIN_MS` / `AUTHOR_MAX_MS`), pour qu'une course correcte (or ×1,08) tienne en 30–45 s.
- **Pilote** : la marge aux rebords reste de 3,6 m (`WALL_MARGIN`) ; l'écart latéral permis est `demi-largeur − marge` en chaque point, donc la corde s'ouvre avec la largeur (14 m : 3,4 m de jeu ; 26 m : 9,4 m) et un virage large se prend plus vite sur la route large (mesuré : L2 en 5,51 s à 14 m, 5,32 s à 26 m).
- Tests : `packages/sim/test/largeurs.test.ts` (notation, chaînage, transition, rebords inclinés, plaques, portes, L3/R3, pilote), `generator.test.ts` (largeurs, virages serrés, largeur dominante par thème). Outil : `?scenario=largeurs` (écrit à la main : `LARGEURS_TRACK_SPEC`).
- **Nouvelle largeur, nouveau bloc de forme ou nouvelle règle de génération = `SIM_VERSION` / `GENERATOR_VERSION` +1**, puis `UPDATE_GOLDEN=1` sur `golden.test.ts` et `golden-daily.test.ts`, `npm run history:seed` et `npm run measure:generator`.

## Freinage après un boost (lot 34)
README : `docs/lots/lot-34-virages-boosts.md` (mesures avant / après, liens d'aperçu ; sa date de bascule a disparu au lot R11).
- **Version du générateur d'un jour** (lot 34, **refait au lot R11** — voir « Registre des jours (lot R11) ») : `generatorVersionOf(jour)` lit le registre ; `dailyTrackId`, `dailyCircuit`, `generateCircuit`, `composeFigures`, `composeSpec` prennent la version du jour par défaut (un dernier argument `generator` l'impose : mesure, tests des anciennes versions ; l'identifiant suit). La v16 (freinage après un boost) a `GENERATOR_BEFORE_48` = 16 pour constante ; le golden garde ses vecteurs v15 et v16 (leur version est celle de leur `trackId`, imposée par le test).
- **Règle « freinage possible après un boost »** (`secureBraking`, `braking.ts`, appliquée par `composeFigures` à chaque figure posée, en v16 seulement) : pour chaque virage **abordé vite** (après une plaque, un super turbo, ou à plus de `FAST_APPROACH` = 52,8 m/s : une portion rapide, une descente) — (1) si le thème a un bas-côté (ni vide, ni Ville), le virage et le bloc qui le suit le reçoivent (moins de murs à l'extérieur ; jamais un virage relevé) ; (2) si le freinage manque (`brakingDeficit` > 0), **des droites de freinage sont ajoutées devant le virage, une à une**, jusqu'à ce qu'il se freine (au plus `MAX_BRAKING_ADD` = 4, sinon la variante est refusée). **La distance se calcule à partir de la vitesse, jamais un nombre fixe de blocs** : modèle statique (`advance`, `approachAfter`) — pointe du plat 48, plaque 66 et super turbo 88 m/s, **aucun freinage utile pendant la poussée** (74 m pour une plaque, 136 m pour un super turbo depuis l'entrée du bloc : frein 40 contre 30 et 42), traînée en cube, pente, pas de freinage en l'air ni à la réception ; vitesse de passage serré 21, large 38, ample 46 m/s (× √adhérence du revêtement, glace en roue libre) ; freinage nécessaire = (v² − v_passage²) / (2 × 0,8 × 40 × motricité) + 0,3 s × v (`BRAKE_REACTION`). Le bas-côté ne suffit pas comme échappatoire à 66–88 m/s (sa bande finit par un rebord à 15 m de l'axe : mesuré, les contacts ne baissaient pas) : un serré après une portion rapide a donc sa droite de freinage, plus le bas-côté quand le thème en a. Les enchaînements techniques sous la pointe (un large puis un serré) ne sont pas touchés : c'est l'intention de leur figure. L'approche d'un virage rapide est **protégée** (ni zone de revêtement, ni route bosselée, ni section sans rebords) ; derrière une plaque ou un super turbo, la plus longue droite peut atteindre `MAX_PLAIN_STRAIGHT` + 4 (`plainRunsOk`). Les droites ajoutées se prennent sur le budget des figures (`BRAKING_BUDGET` = 2 unités).
- **Virage-piège** (`turnReports`, `traps.ts`, mesure dynamique sur la course du pilote d'auteur) : une **approche rapide** (après une plaque, un super turbo ou au-delà de `FAST_APPROACH` : les enchaînements techniques sous la pointe du plat sont comptés à part, colonne « techniques »), un vrai freinage (au moins `MIN_BRAKE` = 8 m/s à perdre), une **marge sous 0,3 s** (`TRAP_SLACK` : temps qu'on peut rouler plein gaz après la fin de la poussée, ou la sortie du virage précédent, avant de devoir freiner pour la vitesse de passage du pilote) **et un mur à l'extérieur** (ni bas-côté, ni cuve ; un virage sans rebords n'est pas compté). **Plafond : au plus un par circuit, et seulement quand le thème s'y prête** : le passage signature (Stade : `turbo-courbe`), ou Ville (ses épingles) ; `Composition.braking.kept` le compte. Rallye et Canyon gardent leur format (signature, figures, revêtements). Mesuré (156 circuits, v15 → v16) : 0,82 → 0,22 piège par circuit, maximum 3 → 1, 31 circuits à plus d'un → 0.
- **Pilote « humain correct »** (`humanRun`, traps.ts, mesure seule) : le pilote d'auteur (même trajectoire et adhérence) qui **ne freine ni pendant une poussée, ni dans les 0,3 s qui suivent sa fin, la sortie d'un virage ou une réception** (il garde le plein gaz) ; contacts avec un rebord comptés (deux à moins d'1 s = un). Choisi parce qu'il ne se trompe que là où il faut freiner tout de suite ; « freiner 0,3 s trop tard partout » donnait le même excès de vitesse (≈ 10 m/s) à chaque virage freiné, quelle que soit la distance disponible, et ne jugeait donc pas la règle (mesuré). Mesuré (156 circuits) : 2,36 → 0,48 contact par circuit (1,47 → 0,24 après une poussée).
- **Mesure** : `npm run measure:generator`, section 3 (« Lot 34 ») : pour v15 et v16 (`COMPARE`), 60 dates du jour et 12 circuits par thème forcé (`TRAP_DAYS`, `TRAP_THEME_DAYS`) : pièges par circuit (moyenne, max, circuits à plus d'un), contacts du pilote « humain correct » (dont après une poussée) et du pilote d'auteur, durées, compteurs de la règle (virages rapides, corrigés, droites ajoutées, bas-côtés imposés, pièges gardés), et pour les virages abordés vite : vitesse d'arrivée possible, vitesse de passage, freinage nécessaire contre distance disponible ; la section 2 (validation par thème) compare aussi les deux versions ; `GENERATOR` impose la version des sections 1 et 2. Tests : `packages/sim/test/freinage.test.ts` (modèle, règle sur 24 dates d'après la bascule, au plus un piège, contacts au moins divisés par 2 sur 8 dates, durées), `golden-daily.test.ts`.

## Relief, sauts et chute (lot 17)
- **Niveaux** : `LEVEL` = 4 m. `U` / `D` = 1 niveau sur une cellule (pente 0,125) ; **`U2` `U3` `D2` `D3`** = 2 ou 3 niveaux (pente 0,25 / 0,375, `RISE_LETTERS`, `track.ts`). `Block.rise` = dénivelé résolu du bloc (les hauteurs s'enchaînent avec `exitDelta(kind, rise)`) ; `Block.open` = sans rebords. Un dos d'âne (`U2 D2`) fait décoller ; une montée raide ne se met jamais sur l'herbe, la terre ou la glace (la voiture cale : `surfaceable`, generator.ts).
- **Sauts** : **`K`** rampe (plate jusqu'à `KICK_START` = 16 m, puis +1 niveau, pente 0,25), **`G`** vide (aucun sol, aucun rebord ; `GU` / `GD` / `GD2` : l'autre bord est 1 niveau plus haut / plus bas / 2 niveaux plus bas), puis une réception (`D`, `S`…). `packages/sim/src/jump.ts` : `trackJumps(track)` → `{ kick, gapCells, gap, rise, landing, runout, minSpeed, maxSpeed }` = **fenêtre de vitesse au bord de la rampe** (balistique pure, marge ×1,05 mesurée ; plancher ≈ 33 m/s pour un vide d'une cellule vers un bord plus bas, 40 au même niveau, 52–58 pour deux cellules, 55 vers un bord plus haut ; plafond = la réception ne suffit plus). **Tester par la simulation** (`test/sauts.test.ts`), pas seulement par la formule. `J` (tremplin, lot 2) reste dans le circuit d'essai et `pilotage`, mais le générateur ne le pose plus.
- **Sans rebords** (`S/o`, modificateur `o`) : `collide` ne retient plus la voiture par le côté ; elle tombe. Le générateur n'en met que sur des blocs ordinaires à ≥ 6 m au-dessus du point le plus bas (`openSection`), selon le thème (`openChance`).
- **Chute** (`race.ts`) : sous `track.voidY` (route la plus basse − `FALL_DEPTH` = 4 m) `race.fallTicks` passe à 1 ; la voiture tombe **sans commande** pendant `FALL_TICKS` = 60 pas (0,5 s), puis reprend au dernier point de contrôle (`respawn`) ; le chrono ne s'arrête jamais (un pas par pas, +1 à la reprise) ; la touche de reprise pendant la chute reprend aussitôt. Rejouable à l'identique. Web : voile sombre `#fall`, bandeau « Chute ! », sons `fall` / `respawn`, caméra qui ne plonge pas ; **ombre d'atterrissage** (`landing.ts`, `predictLanding` : lecture seule) = ombre posée au point de réception prévu, absente si la voiture ne retombe sur rien.
- **Générateur** (`composeSpec`) : dénivelé ≥ `MIN_RELIEF` = 12 m (le premier relief du circuit en fait au moins 12), reliefs `HILLS_GENTLE` / `HILLS_STEEP` (hauteurs gardées entre ±24 m), **vrai saut** (`jumpCalm` : `short` K GD, `flat` P K G D, `long` T K G G D, `longDown` P K G GD D, `up` T K GU) selon `theme.jumpChance` (100 % Stade, Nuit ; le Rallye l'a aussi par sa signature, un saut court sur la terre) ; priorité des créneaux : signature, saut, virages marquants, portions rapides, reliefs. Pas d'intersection (une cellule = un bloc) ; **pas de pont à deux niveaux** (la grille ne le permet pas simplement). Descentes raides dans la portion rapide `drop`.
- **Pilote** : le freinage tient compte de la pente (`slopeGravity × pente`), **aucun freinage en l'air** (la vitesse visée ne baisse pas de la rampe à la fin de la réception : `airborne`), reste au milieu sur rampe / vide / réception, marge de 1 m de plus sans rebords. `PilotRun.jumpsOk` : au bord de chaque rampe, vitesse ≥ `JUMP_ENTRY_MARGIN` (1,08) × plancher et ≤ plafond, sinon le circuit est refusé.
- Rendu : piliers et dalle mince au-delà de `PILLAR_MIN` = 12 m au-dessus du sol lointain, faces pleines au bord d'un vide, rampe claire à bande d'alerte, damier vert de réception, bordure plate rouge et blanche sans rebords. Miniatures : le vide se voit (repli 2D compris).
- Web : `?scenario=relief` (préréglage « Relief et sauts » de `/admin/`). Tests : `test/relief.test.ts`, `test/sauts.test.ts`, `apps/web/test/landing.test.ts`, `e2e/relief.spec.ts`.

## Cuves (lot 18)
- **Notation** (`track.ts`) : `V` cuve droite (deux parois, demi-tube), `ML` / `MR` mur latéral (une paroi, à gauche / à droite), `/c` sur un virage (`L2/c`, `R3/c`, `L/c` : sa paroi est du côté **extérieur**). Une cuve est **une droite ou un virage avec un attribut** : `Block.cuve` (bits `CUVE_LEFT` | `CUVE_RIGHT`), `cuveIn` / `cuveOut` (côtés que le voisin prolonge : pas de rampe à ce bord). Refusés : pas de repère (`@cp`) ni de transition de largeur, ni `o`, ni `b`, ni sur le départ ou l'arrivée ; elle reste plate (aucun relief), la route peut porter un revêtement mais le générateur n'en met pas. `parseToken` renvoie `cuve` seulement s'il y en a une.
- **Géométrie** (`cuve.ts`, pas de trigonométrie) : en travers de la route, fond plat jusqu'à `f`, **quart de cercle** de rayon `R = CUVE_RATIO (0,65) × demi-largeur` (4,6 / 6,5 / 8,5 m pour 14 / 20 / 26 m), qui devient vertical en `demi-largeur`, puis **paroi verticale** jusqu'à `R + CUVE_LIP (8 m)` ; au-delà, c'est le vide (on passe par-dessus). Amplitude `a` ∈ [0, 1] (`cuveAmplitude`) : 0 = rebord ordinaire de 1,4 m, 1 = cuve ; **rampe de `CUVE_RAMP` = 16 m** depuis l'entrée / la sortie d'une droite, **30 % de l'arc** (`CUVE_RAMP_ARC`) dans un virage (7 / 22 / 37 m), sauf si le bloc voisin prolonge la paroi. Un virage est une **surface de révolution** (l'écart est la distance au centre du virage) : la normale reste dans le plan rayon-vertical. `shellAt` (distance signée, normale, avance de la route) ; `world.shell(x, z, y, out)` n'existe que pour `trackWorld` (le sol plat n'en a pas) ; `world.sample` rend une hauteur approchée (paroi tronquée à ≈ 80°) pour les lecteurs de hauteur ; `collide` ne répond pas dans une cuve (les parois sont dans la surface).
- **Physique** (`car.ts`, `substepShell`) : le contact se fait par la **normale** de la surface. La voiture est repérée dans le plan tangent (`tangentFrame` : avance `f`, gauche `l`, normale `n`) ; `car.yaw` reste l'angle d'un cap « à plat » (la voiture tourne autour de la normale : `yaw − cap de la route`) ; mêmes pneus, moteur et freins qu'à plat (formules recopiées de `substep`) ; la pesanteur se projette sur le plan (`ax −= slopeGravity × f_y`, `ay −= gravity × l_y`) ; la paroi repousse la position le long de la normale et supprime la vitesse qui y entre (sans rebond) ; **en l'air** (distance > `SHELL_TOUCH` 0,08 m) : balistique ; elle suit une paroi qui s'éloigne de moins de `SHELL_SNAP` 0,1 m (fin de rampe). Tangage et roulis restent 0 dans une cuve ; `CarState` gagne `nx, ny, nz` (la normale sous la voiture : (0, 1, 0) hors cuve, lue par le rendu). **Les blocs sans cuve rejouent au bit près** (test : même état qu'un monde sans `shell` ; rediffusion de l'essai inchangée à la version près).
- **« Décrochage »** (cuve **droite** seulement) : au-dessus de `shellStickHi` (34 m/s) la pesanteur le long de la paroi est annulée (la voiture tient sur la verticale), sous `shellStickLo` (24 m/s) elle s'applique en entier (la voiture redescend), entre les deux c'est progressif (`smoothstep`) ; l'adhérence suit la charge presque en proportion sur une paroi, et `shellDown` (1,2 g) est l'appui qui charge les pneus à vitesse. **Dans un virage en cuve la pesanteur reste entière** : c'est la géométrie (cône) qui tient la voiture à sa hauteur d'équilibre (`tan θ = v² / (g × rayon)`). Trois clés de `CarParams` (`?debug&tune`).
- **Pilote** : `AutopilotOptions.wall` (faux par défaut : le fond, comme un virage ordinaire) ; `true` = trajectoire **clouée** à la paroi extérieure du virage en cuve (écart latéral imposé : `pin`, entonnoir de 40 m en lissage cubique, `CUVE_INSET` = 1 / 2 / 2,5 m du pied de la paroi verticale selon la taille, `racingLine` compte `g × pente de la paroi` comme un relevé, aucun freinage sur la rampe de sortie). **`bestPilotRun` essaie les deux** (fond et paroi, 4 niveaux d'adhérence chacun) et garde le plus rapide ; `PilotRun.wall` dit lequel. La relaxation de la trajectoire va plus loin (4000 itérations) seulement pour un circuit qui a un virage en cuve : **les autres circuits gardent leur tracé**.
- **Générateur** : `Theme.cuveChance` — Stade 100 %, Nuit 100 %, Banquise 25 %, Rallye et Campagne 0 %. Rien n'est tiré pour un thème sans cuve (même suite de tirages). Motifs (`CuveKind`, poids 3 / 2 / 3) : `bowl` six blocs `S V V V V S`, `wall` `S ML/MR ×4 S`, `turn` un virage en cuve (`L2/c`, `L3/c`, parfois le serré `L/c` qui compte dans le budget de virages serrés). Priorité des créneaux : signature, saut, **cuve**, virages marquants, portions rapides. `bowl` et `wall` ajoutent six cellules : un créneau de moins ; s'il n'y a pas de créneau calme libre, c'est un virage en cuve. Un thème à 100 % refuse la tentative sans cuve (graine voisine).
- **Rendu** (`trackMesh.ts`, `addCuve`) : fond à la couleur du revêtement, quarts de cercle et parois en **damier rouge et blanc** (bandes de 4 m dans le sens de la marche), chapeau de crête, remblai en retrait de 0,15 m derrière chaque paroi (sinon les deux plans scintillent). Voiture et fantôme : `carPose.ts` (`CarPose` : la normale de la voiture, lissée à 12 /s, tourne le « haut » du monde ; **l'axe de rotation est l'avance de la route**, le cap reste donc le long de la paroi) ; **caméra** : son « haut » est entre la verticale et la normale (60 % du roulis, `CAMERA_ROLL_FOLLOW`) ; ombre masquée sur une paroi. `telemetry.ts` : roues posées dans le plan tangent (`tangentFrame`), `tilt`, `onWall` ; `fx.ts` : traces de pneus au ruban orienté par la normale (`Skids.wheel(…, nx, ny, nz)`) et étincelles des roues arrière sur la paroi (> 18 m/s).
- Outils : `?scenario=cuves` (`CUVES_TRACK_SPEC`, circuits.ts : élan, cuve droite, mur latéral, virage en cuve large à pleine vitesse, demi-tour serré, le même virage abordé trop lentement), raccourci « Cuves et murs » de `/admin/`, ligne « Cuves » du planning (`cuvesText`), miniature cadrée sur la cuve s'il n'y a ni signature ni saut. Tests : `packages/sim/test/cuves.test.ts` (seuils recopiés dans `docs/lots/lot-18-cuves.md`), `apps/web/test/carPose.test.ts`, `e2e/cuves.spec.ts` (navigateur et Node calculent la même voiture sur la paroi, à 1e-9 près).
- `SIM_VERSION` et `GENERATOR_VERSION` valent **9**. **Une nouvelle forme de paroi ou un changement de `shell*` = `SIM_VERSION` +1** (et `GENERATOR_VERSION` : le pilote d'auteur roule sur ces blocs), puis les références habituelles (`UPDATE_GOLDEN=1`, `history:seed`, `measure:generator`).

## Figures (lot 20)
- **Un circuit du jour = 5 à 7 figures** (`packages/sim/src/figures.ts`, `FIGURES`, 40 figures) posées à la suite par `composeFigures` (`generator.ts`) ; `composeSpec` n'en rend que le texte, `DailyCircuit.figures` donne `{ name, variant, left, from, to }` (blocs `[from, to)`). Le texte, les temps et les golden d'une date changent avec le lot ; **`SIM_VERSION` ne bouge pas** (aucun bloc, aucune physique).
- **Une figure** = `{ name, label, category, variants, off, build(ctx) }` (sa phrase, `intent`, est dans `figureIntents.ts` depuis le lot V2) + drapeaux `jump` / `cuve` / `cut` / `turbo` / `banked` / `relief` / `braking`, `weight`. `build({ L, R, wall, width, variant })` rend des blocs (`L` = sens du premier virage, échangé par le miroir ; `width` = route à l'entrée, la figure se rétrécit d'elle-même si besoin : `toTight`, `reach`) ou `null` si la variante est impossible. Catégories : `technique`, `saut`, `rapide`, `combo`, `cuve`, `relief`. Une figure commence par une droite d'amorce (retirée si le bloc précédent en est une) et garde derrière elle les droites exigées (2 après une plaque, 5 après un super turbo, 3 après un saut court, 5 après une cuve ou un saut long). `turned` ajoute un virage large derrière un saut ou une cuve : sans lui, on les quitte à plus de 55 m/s et on garde le plein gaz jusqu'au bout.
- **Composition** (`selectFigures`) : la signature du thème (`SIGNATURE_FIGURE`) toujours ; un saut et une cuve selon `jumpChance` / `cuveChance` (une figure qui fait les deux, 55 %) ; du dénivelé (de préférence un virage en pente) ; au moins un **freinage franc** (`braking` : plaque ou turbo, puis virage) ; une portion rapide ; une figure favorite du thème ; au moins deux techniques ; le reste au poids (favorites ×4, `braking` ×2, `weight`) dans un budget de durée (`FIGURE_BUDGET`, `figureSeconds`). Plafonds : 2 sauts, 1 cuve, 1 moteur coupé, virages serrés (`minTightTurns`) ≤ `MAX_TIGHT`. **Huit tirages** : le premier budget tenu (`FIGURE_TOTAL_MAX`) qui lâche le plus le gaz (somme des `off`) l'emporte. Ordre aléatoire, jamais de saut en tête ni en queue ; chaque figure prend la première (variante, miroir) qui tient sur la grille, dans les hauteurs permises et le budget de virages serrés, sinon une remplaçante de la même catégorie ; la signature ne se remplace pas. Liaisons `CONNECTORS` ; `MAX_PLAIN_STRAIGHT` (6 blocs) plafonne la plus longue droite ordinaire. Un circuit estimé hors de `ESTIMATE_MIN`–`ESTIMATE_MAX` (`estimateSeconds` : durée du pilote ≈ 0,95 × estimation) est refusé **sans faire rouler le pilote**.
- **Peu de répétition sans historique** : `isRested(nom, jour)` — trois groupes de figures (empreinte du nom), le jour `d` laisse au repos le groupe `d mod 3` (hors signature) ; deux jours de suite n'ont que le tiers des figures en commun, et rien n'est généré pour les jours passés. **Thèmes** : `theme.figures.favor` / `.ban` (glace là où il y a de la glace, terre là où il y a de la terre, cuves là où il y en a).
- **Ajouter une figure** : une entrée de `FIGURES` (nom en minuscules à tirets, `off` provisoire) et sa phrase dans `FIGURE_INTENTS` (`figureIntents.ts`) → `npx vitest run packages/sim/test/figures.test.ts` (le pilote doit finir **chaque** variante, dans les deux sens, sur les trois largeurs) → `RHYTHM=1 npm run measure:generator` pour régler `off` (secondes hors plein gaz par passage) → favorites ou interdites des thèmes → **`GENERATOR_VERSION` +1**, `UPDATE_GOLDEN=1 npx vitest run packages/sim/test/golden-daily.test.ts`, `npm run history:seed`. **Un thème qui interdit trop de figures ou une règle de plus se mesure** (`construit` / `dans la fenêtre` par thème) : au lot 20, trois virages serrés tirés sans compter faisaient échouer 50 % des tentatives de *Campagne*.
- **Pilote** : mesure seule ajoutée à `PilotRun` (`fullThrottleTicks`, `liftEvents`, `grip`) ; un moteur coupé ne compte pas comme plein gaz.
- Web : `?scenario=figures` (tour de onze figures écrit à la main, `FIGURES_TRACK_SPEC`) et `?scenario=figure&f=<nom>&v=<variante>&m=1` (`createFigureTrack` : cinq droites de lancement, point de contrôle juste avant, miroir avec `m=1` ; nom inconnu = circuit d'essai) ; admin : « Les figures », « Une figure en boucle » (sélecteur, variante, miroir) et la carte d'un jour du planning liste ses figures (`figuresText`). Tests : `packages/sim/test/figures.test.ts`, `apps/web/e2e/figures.spec.ts`. README : `docs/lots/lot-20-figures.md`.

## Fichiers légers et fichiers lourds (lot 36)
Le jeu (`apps/web`) ne charge pas le générateur au premier écran : le circuit du jour se calcule dans un fil de travail (`apps/web/CLAUDE.md`, « Premier chargement et chargement à la demande »). Pour que l'empaqueteur puisse l'écarter, **`sim` se lit en deux familles** — **légers** (physique, monde, rediffusion, thèmes, `medals.ts`, `dailyId.ts`, `fictionalNames.ts`, `salon.ts`) et **lourds** (`generator`, `figures`, `braking`, `autopilot`, `fictional`, `circuits`, `salonCircuit`, `traps`, `choices`, `medalStats`) ; **un fichier léger n'importe jamais, même de loin, un fichier lourd** (`test/legerete.test.ts`). Le lot 36 a déplacé, sans changer un résultat, `medalsFor` / `medalFor` / les facteurs et la bascule des médailles (`medals.ts`), `generatorVersionOf` / `dailyTrackId` / `isVariant` (`dailyId.ts`, qui lit le registre `jours-track.json` depuis le lot R11), `FICTIONAL_NAMES` (`fictionalNames.ts`) et `salonCircuit` (`salonCircuit.ts`) ; `generator.ts`, `fictional.ts` et `index.ts` les réexportent, rien ne change pour les importeurs. `package.json` déclare `"sideEffects": false` (sans cela l'empaqueteur garde tout module qui lit une propriété d'un objet importé au niveau du module). **Une fonction dont le premier écran a besoin va dans un fichier léger.**

## Règles de la simulation (déterminisme)
- Pas fixe (`TICK_RATE` = 120 Hz), jamais de `dt` variable ; interpolation à l'affichage seulement.
- Pas de moteur physique externe. Pas de `Math.sin/cos/exp/pow/tanh/atan2/…` dans `sim` : implémentations maison ou tables (`sin`/`cos` de `math.ts` ; saturation rationnelle `tireCurve` = t / ⁴√(1 + t⁴) ; angles de glissement, tangage et roulis gardés en **pentes** (rapports), jamais convertis en angles ; amortissements en `x * (1 − k·dt)`).
- Modifier une valeur par défaut de `CarParams` (ou la géométrie de `car.ts`) = incrémenter `SIM_VERSION` + régénérer les références (et `GENERATOR_VERSION` si le temps du pilote change, ce qui est presque toujours le cas).
- Commandes de la voiture = entiers (`makeInput`) ; l'état de référence de `car.test.ts` ne change que si la physique change volontairement.
- Pas de `Math.random` ni `Date` dans `sim` : PRNG à graine explicite.
- Une course = la suite des commandes du joueur ; le même code la rejoue côté serveur.
